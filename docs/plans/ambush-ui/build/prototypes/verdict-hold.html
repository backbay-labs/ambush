Guard-scope findings, for whoever writes the copy gate

These are not observations about this page; they are three ways a naive tools/check-copy-banned-terms.sh fails the plan's own strings, found by writing the guard and running it.

  • The bare-source-count rule needs a word boundary on both sides. distinct_sources, source_ids and sources.insert(…) are identifiers. A rule of the shape sources-not-followed-by-/ N agents fires on all three.
  • And it must not strip numeric mono spans. Render law 2's own string is <span class="mono num">2</span> sources / <span class="mono num">1</span> agent. A guard that strips every mono span to skip wire values turns that into " sources / agent" and then reports the law's own rendering as a violation of the law. A mono span holding nothing but a number is part of the sentence.
  • The bare-lease ban is scoped to LABELS, and a prose scan overshoots. APPENDIX-NORMATIVE.md §7 bans the bare word "in a label, heading, nav item or badge" — not in a sentence explaining that three unrelated objects share it. A flat scan fires on the explanation. The gate should scan label-shaped DOM (headings, the data-perch-role vocabulary, badge and nav components) rather than free text, which is the same shape as 16-INVARIANT-TESTS' decision D7 for the signed/verified rule.
  • The rule must require a numeral, or it fires on the phrase "the source was measured". APPENDIX-NORMATIVE.md §7 bans "a bare source count", so the pattern is a numeral immediately before sources? and not followed by / N agents?. Without the numeral the rule fires on every ordinary use of the English word, including a sentence about reading source code — and a rule that fires on prose about itself is a rule that gets switched off.
  • The hunt-as-a-noun rule fires on the verb. 16-INVARIANT-TESTS' row exempts hunt_id and does not match hunting; it does match hunts, so ordinary copy like "so nobody hunts for it" fails. The verb forms need exempting too. This page reworded rather than adding an allowlist entry, because product copy is never allowlisted.

How to re-measure this page

Nothing below is a claim you have to take on trust. The two checks that matter are cheap:

  • Type census. Open the page, then in the console: Object.entries([...document.querySelectorAll("*")].filter(e => !e.closest("[data-proto-chrome]") && [...e.childNodes].some(n => n.nodeType === 3 && n.textContent.trim())).reduce((a, e) => { const s = getComputedStyle(e).fontSize; a[s] = (a[s] || 0) + 1; return a; }, {})).sort(). Every bucket should be ≥11px, and the ≥14px buckets should hold well over a quarter of the nodes.
  • Both themes. The theme control's system position is the default and no data-theme is stamped at boot, so --blink-settings=preferredColorScheme=1 (or an OS light setting) genuinely reaches the light palette. Compare getComputedStyle(document.body).backgroundColor in both.
