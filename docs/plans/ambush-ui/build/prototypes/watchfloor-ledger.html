How to read this file

Every state is addressable, and the convention is now one convention. #state=shedding&screen=ledger&sel=3&ov=export. The reader also accepts the query-string form, so a link written under either of the two conventions two producers separately committed to will resolve. The fragment is what this page emits, because it survives a file:// double-click without a query string. Eleven states are wired: quiet, below the bar, crossing, hold open, after the shift, two consoles, degraded governance, telemetry source down, shedding, telemetry stale, loading, daemon unreachable. The strip is pinned along the bottom edge rather than floating in a corner, because a corner card at this size permanently covers the tail of the third wall column, and a prototype that hides a region in order to show its own controls is not showing the region; body reserves the strip's height.

Paste this into the three prototypes that have no reader. Fifteen lines, no dependencies:

function readLink() {
  const q = new URLSearchParams(location.hash.replace(/^#/, ""));
  const s = new URLSearchParams(location.search.replace(/^\?/, ""));
  const get = (k) => (q.get(k) !== null ? q.get(k) : s.get(k));
  const st = get("state"), sc = get("screen"), sel = get("sel"), ov = get("ov");
  if (st && STATES[st]) state = st;
  if (sc) showScreen(sc);
  if (sel && /^\d+$/.test(sel)) selectedRow = Number(sel);
  overlay = ov || "";
}
function writeHash() {
  const parts = ["state=" + state];
  if (selectedRow) parts.push("sel=" + selectedRow);
  if (overlay) parts.push("ov=" + overlay);
  try { history.replaceState(null, "", "#" + parts.join("&")); } catch (e) { /* file:// */ }
}

Two screens, one page, because they share a chart vocabulary and a governance strip. Neither screen accepts a decision: /watch-floor registers no click handler at all, and /ledger is a record with one write-shaped affordance (Export) that produces a file. The grant control does not appear on either screen — it lives in prototypes/verdict-hold.html. Every value on screen is computed by this page from the fixture, so the arithmetic is internally consistent rather than typed in, and the Fixture check row under the lanes recomputes the canonical scenario against the four checkpoints build/fixtures/perch-demo-fixture.json records. If a later edit breaks the maths, that row says so on screen instead of the screenshot being quietly wrong.
