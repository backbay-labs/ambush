## Phase Details

### Phase 96: Shared Telemetry Schema And Bridge Contract
**Goal**: Shared telemetry types move into `swarm-core`, and the repo gains a first-class `TelemetryBridge` contract plus Tetragon trait-based polling
**Depends on**: Phase 95 (v1.32 complete)
**Requirements**: BRIDGE-01, BRIDGE-02
**Success Criteria** (what must be TRUE):
  1. `TelemetryEvent` and its payload variants live in `swarm-core` so multiple bridge crates can share one normalized schema without a crate cycle
  2. `swarm-core` defines a `TelemetryBridge` trait plus shared `BridgeHealth` status for polling normalized telemetry
  3. `TetragonBridge` implements `TelemetryBridge` and no longer requires a direct `Sender<TelemetryEvent>` in its primary contract
  4. Existing Tetragon reconnect-backoff and `ProcessExec` mapping logic remain covered by tests after the trait port
  5. Existing runtime and detector code continue to compile through re-export compatibility
**Plans**: 2/2 plans complete

Plans:
- [x] 96-01-PLAN.md -- Move shared telemetry schema into `swarm-core` and add the `TelemetryBridge` contract with shared bridge health types
- [x] 96-02-PLAN.md -- Refactor `TetragonBridge` onto trait-based polling while preserving reconnect and mapping behavior

### Phase 97: CloudTrail And Generic Json Bridges
**Goal**: The repo ships CloudTrail and generic JSON bridge implementations that normalize external events into shared telemetry
**Depends on**: Phase 96
**Requirements**: BRIDGE-03, BRIDGE-04
**Success Criteria** (what must be TRUE):
  1. `CloudTrailBridge` implements `TelemetryBridge` and maps CloudTrail records into normalized `TelemetryEvent` values
  2. `GenericJsonBridge` implements `TelemetryBridge` and maps configurable JSON paths into shared telemetry without recompilation
  3. Bridge-specific schema validation rejects malformed bridge output fail-closed
  4. Bridge unit tests cover core record mappings and invalid input handling
  5. Bridge constructors and config shapes are reusable by the runtime registry phase
**Plans**: 2/2 plans complete

Plans:
- [x] 97-01-PLAN.md -- Implement `CloudTrailBridge` with normalized authentication and network event mappings
- [x] 97-02-PLAN.md -- Implement `GenericJsonBridge` with configurable field mapping and payload selection

### Phase 98: Runtime Bridge Registry And Health Surface
**Goal**: Runtime config activates bridges by name, spawns only configured bridge instances, and surfaces bridge health on operator status and `/metrics`
**Depends on**: Phase 97
**Requirements**: BRIDGE-05
**Success Criteria** (what must be TRUE):
  1. Runtime config selects active bridges by name instead of assuming only static ingest sources
  2. The runtime can construct and poll only configured bridge instances
  3. Bridge event counts, error counts, and lag are exposed through operator status and Prometheus metrics
  4. Bridge failures degrade bridge health without corrupting the hot detection path
  5. Serve mode remains compatible with existing ingest and agent runtime paths
**Plans**: 2/2 plans complete

Plans:
- [x] 98-01-PLAN.md -- Extend config and runtime wiring to build a bridge registry from named telemetry bridge instances
- [x] 98-02-PLAN.md -- Surface bridge health and metrics through operator status, `/healthz`, and `/metrics`

### Phase 99: Concurrent Bridge Integration Proof
**Goal**: Integration coverage proves multiple bridge instances can feed the shared detection pipeline concurrently and deposit pheromones end to end
**Depends on**: Phase 98
**Requirements**: BRIDGE-06
**Success Criteria** (what must be TRUE):
  1. Integration tests start at least two bridge instances concurrently against a shared runtime input channel
  2. Both bridges produce normalized events that flow through the detection pipeline and deposit pheromones
  3. The concurrency proof remains deterministic and bounded for routine CI execution
  4. The full workspace remains green after the bridge stack lands
  5. Milestone verification demonstrates the new bridge architecture works beyond unit scope
**Plans**: 2/2 plans complete

Plans:
- [x] 99-01-PLAN.md -- Add multi-bridge integration harness and deterministic fixture sources
- [x] 99-02-PLAN.md -- Verify concurrent bridge ingestion produces shared detection and pheromone outcomes under workspace validation
