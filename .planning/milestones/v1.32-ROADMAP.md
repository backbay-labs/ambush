## Phase Details

### Phase 94: Agent Registry And Role Shift Runtime
**Goal**: The dispatcher manages a keyed multi-agent roster with role-shift propagation, shared environment snapshots, and lifecycle telemetry
**Depends on**: Phase 93 (v1.31 complete)
**Requirements**: MULTI-01, MULTI-02, MULTI-03, MULTI-06
**Success Criteria** (what must be TRUE):
  1. An `AgentRegistry` holds a keyed roster of live agents indexed by `AgentId`
  2. Agents can emit `SwarmAction::RoleShift`, and the dispatcher propagates role changes across the roster through a runtime event bus
  3. Each dispatcher tick builds a `SwarmEnvironment` snapshot with recent pheromones, current swarm mode, and recent peer findings
  4. Agent spawn, tick completion, health transitions, and role shifts emit structured logs plus Prometheus counters partitioned by role
  5. Serve mode can reload or re-register agents through the registry without breaking the existing dispatcher loop
**Plans**: 2/2 plans complete

Plans:
- [x] 94-01-PLAN.md -- Introduce `AgentRegistry`, keyed dispatcher ownership, and role-shift propagation over a runtime event bus
- [x] 94-02-PLAN.md -- Add per-tick environment snapshots, peer finding visibility, and lifecycle metrics/logging for multi-agent execution

### Phase 95: StalkerAgent And WeaverAgent Pipeline
**Goal**: Investigation and correlation agents run inside the live registry and prove the full multi-agent pipeline end to end
**Depends on**: Phase 94
**Requirements**: MULTI-04, MULTI-05, MULTI-07
**Success Criteria** (what must be TRUE):
  1. `StalkerAgent` consumes `WhiskerAgent` detection pheromones and deposits investigation-result pheromones back into the substrate
  2. `WeaverAgent` consumes investigation pheromones and assembles `CorrelatedIncident` records when correlation thresholds are met
  3. Runtime config and serve mode register `WhiskerAgent`, `StalkerAgent`, and `WeaverAgent` into one live agent registry
  4. Integration coverage proves the bounded pipeline: detect -> pheromone deposit -> investigation -> correlation -> incident assembly
  5. The multi-agent pipeline remains green under workspace build, clippy, and test verification
**Plans**: 2/2 plans complete

Plans:
- [x] 95-01-PLAN.md -- Implement `StalkerAgent`, investigation pheromone flow, and live runtime registration
- [x] 95-02-PLAN.md -- Implement `WeaverAgent`, correlation output flow, and end-to-end multi-agent integration tests
