# Milestone v1.12: Draft Materialization And Validation Bundles

**Status:** COMPLETE
**Date:** 2026-04-03
**Milestone Goal:** Turn reviewed draft proposals into materialized candidate artifacts plus refreshed validation bundles, then reconnect them to the existing verified rollout ladder without hand-editing or duplicate queue state.

## Overview

This milestone closed the gap exposed by `v1.11`. The runtime could already derive pressure, package drafts, promote drafts into the reviewed queue, and run proof-backed rollout flows for verified candidates, but the draft-backed queue entries still stopped short of materialized experiment and evidence artifacts. `v1.12` made that bridge repo-owned, durable, and CLI-first.

The shipped slice stays deliberately narrow. It does not add automatic mutation, automatic promotion, automatic canary launch, governance, or richer operator surfaces. It removes manual artifact translation between draft review and the verified rollout ladder while keeping every stage explicit and operator-controlled.

## Completed Phase Plan

### Phase 38: Draft Candidate Materialization

**Status:** COMPLETE
**Requirements:** MTRL-01, MTRL-02
**Plans:** 1/1 plans complete

**Delivered:**
- `swarmctl evolution-materialize` now materializes one repo-owned experiment manifest from a stable draft.
- materialization artifacts preserve draft lineage, pressure references, digests, and applied profile changes.
- `swarmctl evolution-materialization-result` reloads persisted materialization artifacts by stable ID.

### Phase 39: Validation Bundle Refresh

**Status:** COMPLETE
**Requirements:** VALD-01, VALD-02
**Plans:** 1/1 plans complete

**Delivered:**
- `swarmctl evolution-validation-refresh` now refreshes experiment, verification, proof, shadow, and advisory evidence from one materialized candidate.
- validation bundles preserve stable references to the refreshed evidence chain.
- validation fails closed on manifest drift, lineage drift, or inconsistent refreshed evidence and still persists blocked bundles for review.

### Phase 40: Queue Reconciliation And Handoff Readiness

**Status:** COMPLETE
**Requirements:** RECN-01, RECN-02
**Plans:** 1/1 plans complete

**Delivered:**
- `swarmctl evolution-queue-reconcile` now updates the original draft-backed queue proposal in place instead of creating duplicate rollout state.
- reconciliation preserves draft-promotion lineage plus refreshed evidence references.
- reconciled proposals become handoff-ready for the existing queue-to-canary path after explicit operator acceptance when refreshed evidence passes.
