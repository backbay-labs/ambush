# Phase 11 Plan 01: Operator Control Surface

<objective>
Expose the shipped runtime review surface and durable artifacts through a repo-owned CLI without requiring raw file inspection or a networked control plane.
</objective>

<read_first>
- .planning/phases/11-operator-control-surface/11-CONTEXT.md

- crates/swarm-spine/src/store.rs
- crates/swarm-spine/src/investigation.rs
- crates/swarm-spine/src/incident.rs
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add a reusable control module and CLI entrypoint for runtime status plus stable-ID artifact lookup.</description>
<acceptance_criteria>
- `swarmctl status` returns the operator review report from repo-owned config.
- `swarmctl replay`, `swarmctl investigation`, and `swarmctl incident` can resolve stable IDs without reading raw files directly.
- JSON output is lossless and human-readable output is concise.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Extend runtime services with the stable-ID helpers needed by the control surface.</description>
<acceptance_criteria>
- Replay bundles can be loaded by bundle ID, hunt ID, or receipt ID through runtime-facing helpers.
- Investigation bundles can be loaded by investigation ID, hunt ID, or receipt ID through runtime-facing helpers.
- Incidents can be loaded by incident ID or hunt ID through runtime-facing helpers.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Document the operator CLI and verify the control surface with focused tests.</description>
<acceptance_criteria>
- Configuration docs include CLI examples and origin semantics.
- Tests cover runtime status output, stable-ID artifact lookup, and origin labeling.
- The runtime crate still passes formatting, tests, and clippy after the CLI lands.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-runtime control --quiet
- cargo test -p swarm-runtime --bin swarmctl --quiet
- cargo fmt --all --check
- cargo clippy --workspace -- -D warnings
</verification>

<success_criteria>
- Operators can inspect current runtime review state from a repo-owned CLI.
- Operators can retrieve replay bundles, investigation bundles, and incidents by stable IDs.
- The control surface differentiates live runtime status from persisted artifacts in its output.
</success_criteria>
