# Phase 13 Plan 01: Evaluation And Regression Gates

<objective>
Package the replay harness into a practical regression gate that operators or CI can run against one replay result or the full tracked scenario corpus.
</objective>

<read_first>
- .planning/phases/13-evaluation-and-regression-gates/13-CONTEXT.md
- .planning/phases/12-deterministic-replay-harness/12-01-SUMMARY.md
- crates/swarm-runtime/src/replay.rs
- crates/swarm-runtime/src/bin/swarmctl.rs
- docs/CONFIGURATION.md
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add suite-level replay evaluation over the tracked scenario directory.</description>
<acceptance_criteria>
- One helper can evaluate every tracked scenario in a directory and summarize pass/fail counts.
- The suite report surfaces failing scenario names and underlying checks clearly enough for debugging.
- The suite order is deterministic.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Extend the CLI and tests so replay regression becomes a real local or CI gate.</description>
<acceptance_criteria>
- `swarmctl replay-evaluate` can target a single run, a single scenario, or the tracked scenario directory.
- The CLI exits nonzero when any evaluation fails.
- One automated test evaluates the real tracked `scenarios/` directory against the repo config and fails on regression.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Document the end-to-end replay and evaluation workflow for operators.</description>
<acceptance_criteria>
- Docs show how to run replay, inspect a result bundle, evaluate a scenario, and gate the whole tracked corpus.
- Docs mention the default replay result directory and expected failure semantics for CI.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-runtime replay --quiet
- cargo run -p swarm-runtime --bin swarmctl -- replay-evaluate --scenarios-dir scenarios
- cargo fmt --all --check
- cargo clippy --workspace -- -D warnings
</verification>

<success_criteria>
- Replay evaluation reports are legible for operators.
- Tracked scenarios act as a practical regression gate locally and in CI.
- Replay and evaluation workflow is documented end to end.
</success_criteria>
