# Phase 12 Plan 01: Deterministic Replay Harness

<objective>
Ship a repo-owned offline replay harness that reuses production Rust types, persists replay-run bundles, and can be rerun repeatably from tracked scenarios or stored replay bundles.
</objective>

<read_first>
- .planning/phases/12-deterministic-replay-harness/12-CONTEXT.md
- .planning/phases/11-operator-control-surface/11-01-SUMMARY.md
- crates/swarm-runtime/src/service.rs
- crates/swarm-runtime/src/correlation.rs
- crates/swarm-runtime/src/investigation.rs
- crates/swarm-spine/src/lib.rs
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add a replay module that can load repo-owned scenarios, materialize replay steps, run them offline, and persist replay-run bundles.</description>
<acceptance_criteria>
- Event-backed and replay-bundle-backed scenarios are both supported.
- Replay forces `detect_only` behavior and never executes live response actions.
- Replay-run bundles include replay bundles, investigations, incidents, a deterministic summary, and performance snapshots.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Extend correlation and the CLI for deterministic replay execution and durable result lookup.</description>
<acceptance_criteria>
- Correlation can accept a deterministic timestamp for offline incident IDs.
- `swarmctl replay-run` executes one scenario and persists the result bundle.
- `swarmctl replay-result` loads a persisted offline replay result by run ID or scenario path.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add tracked replay scenarios, focused tests, and operator docs for the offline replay loop.</description>
<acceptance_criteria>
- `scenarios/` contains at least one suspicious correlation case and one benign baseline case.
- Tests prove identical replay inputs produce the same deterministic artifacts across runs.
- Configuration docs explain the replay-run/result workflow and default result directory.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-runtime replay --quiet
- cargo run -p swarm-runtime --bin swarmctl -- replay-run --scenario scenarios/office-dropper-correlation.yaml
- cargo fmt --all --check
- cargo clippy --workspace -- -D warnings
</verification>

<success_criteria>
- Offline replay can be driven from tracked scenarios or replay bundle fixtures.
- Durable replay-run bundles can be reloaded without inspecting raw files manually.
- Replay artifacts are repeatable enough to support later evaluation and regression gates.
</success_criteria>
