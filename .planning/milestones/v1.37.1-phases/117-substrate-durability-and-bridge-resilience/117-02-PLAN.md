**B. Bridge: Add event_timeout_secs to BridgeConfig and wrap poll() in timeout** (crates/swarm-ingest-tetragon/src/bridge.rs)

1. Add `event_timeout_secs` to `BridgeConfig`:
   ```rust

       pub endpoint: String,
       pub reconnect_backoff_ms: u64,
       pub max_reconnect_backoff_ms: u64,
       pub event_timeout_secs: u64,
   }
   ```
2. Update `Default for BridgeConfig` to include `event_timeout_secs: 30`.
3. In `poll()` (the `TelemetryBridge` impl), wrap the `stream.next().await` call in `tokio::time::timeout()`:
   ```rust
   let timeout_duration = Duration::from_secs(self.config.event_timeout_secs);
   match tokio::time::timeout(timeout_duration, stream.next()).await {
       Ok(Some(Ok(response))) => {
           // existing success handling
       }
       Ok(Some(Err(error))) => {
           // existing stream error handling
       }
       Ok(None) => {
           // existing stream closed handling
       }
       Err(_elapsed) => {
           // NEW: timeout branch
           self.stream = None;
           let message = format!(
               "event stream silent for {}s; triggering reconnect",
               self.config.event_timeout_secs
           );
           self.sleep_on_disconnect(message.clone()).await;
           return Err(TelemetryBridgeError::Connection(message));
       }
   }
   ```
   Note: `sleep_on_disconnect` already calls `record_error` which increments error_count in BridgeHealth, so the metric `swarm_bridge_error_count` is automatically updated.

4. Add `use tokio::time::timeout;` if not already imported (check — `tokio::time::Duration` and `tokio::time::sleep` are already imported).

**C. Mapper: Use sentinel for empty parent** (crates/swarm-ingest-tetragon/src/mapper.rs)

1. Change the `parent_process` assignment in `map_process_exec` from:
   ```rust
   let parent_process = exec
       .parent
       .as_ref()
       .map(|parent| parent.binary.clone())
       .unwrap_or_default();
   ```
   to:
   ```rust
   let parent_process = exec
       .parent
       .as_ref()
       .map(|parent| parent.binary.clone())
       .filter(|binary| !binary.trim().is_empty())
       .unwrap_or_else(|| "<none>".to_string());
   ```
   This handles both `parent: None` (no parent proto) and `parent: Some(Process { binary: "" })` (empty binary).

**D. Bridge schema: Relax parent_process validation** (crates/swarm-ingest-tetragon/src/bridge.rs)

1. In `process_start_schema_valid`, remove the `!process.parent_process.trim().is_empty()` check. The sentinel `"<none>"` will always pass, but the validation should also not reject it. Change to:
   ```rust
   fn process_start_schema_valid(process: &ProcessStartEvent) -> bool {
       !process.process_name.trim().is_empty()
           && !process.command_line.trim().is_empty()
   }
   ```
   The parent_process is no longer required for schema validity since init-spawned processes legitimately have no parent.
