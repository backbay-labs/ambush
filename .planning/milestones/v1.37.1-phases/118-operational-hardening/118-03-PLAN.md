Create `crates/swarm-runtime/tests/operational_hardening_integration.rs` with a single focused integration test:

```rust
// Test: secret_rotation_and_dead_letter_rotation_cycle_without_data_loss
//
// This test proves that:
// 1. Secret hot-rotation via reload_secrets_only() works in an IngestState context
// 2. Dead-letter journal rotation works when max_dead_letter_bytes is configured
// 3. Both can cycle in the same runtime context without losing records
```

**Test structure:**

1. **Setup:**
   - Create a temp directory for secrets and dead-letter journals
   - Write an initial secret file `edr-token` with value `"initial-token\n"`
   - Build a `SwarmConfig` with:
     - `response_adapter: ResponseAdapterConfig::HttpEdr` pointing to a dead-letter path in temp dir
     - `runtime.secret_dir: Some(temp_dir)` with `@secret:edr-token` as the auth_token
     - `runtime.max_dead_letter_bytes: Some(500)` (low threshold to trigger rotation quickly)
   - Build an `IngestState` from this config using `IngestState::from_path` or `IngestState::from_config`

2. **Secret rotation cycle:**
   - Write `"rotated-token\n"` to the secret file
   - Call `state.reload_secrets_only()`
   - Load the active stack and verify the response adapter config's auth_token is `"rotated-token"` (not `"initial-token"`)
   - This proves secret rotation works in IngestState context

3. **Dead-letter rotation cycle:**
   - Create a `DeadLetterJournal` at the same dead-letter path with `max_bytes: Some(500)`
   - Write enough `DeadLetterEntry` records to exceed 500 bytes (4-5 entries at ~189 bytes each)
   - Write one more entry to trigger rotation
   - Assert: the active journal has exactly 1 entry (the post-rotation entry)
   - Assert: a rotated file exists with the `{path}.{timestamp}` suffix
   - Read the rotated file and assert it contains the original entries (no data lost)

4. **Combined proof:**
   - After both rotations, verify: secret is still the rotated value (secret rotation did not regress), dead-letter rotated file is readable (dead-letter rotation preserved data)

**Important implementation notes:**
- Use `IngestState::from_config` with a synthetic config — do NOT depend on `rulesets/default.yaml` for this test since we need custom secret_dir and max_dead_letter_bytes
- If `IngestState::from_config` is not available, use the pattern from the existing `reload_secrets_only_updates_auth_token` unit test in `ingest.rs` to build the state
- The dead-letter rotation portion can use `DeadLetterJournal` directly since the important thing is proving rotation works with the configured max_bytes value
- Clean up temp files after the test
