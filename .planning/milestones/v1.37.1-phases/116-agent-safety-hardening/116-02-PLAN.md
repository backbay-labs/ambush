    1. In `tick_agents()`, replace the direct `agent.tick(&env).await` call (around line 242) with:
       ```rust
       let tick_timeout = Duration::from_millis(self.config.agent_tick_timeout_ms);
       match tokio::time::timeout(tick_timeout, agent.tick(&env)).await {
           Ok(Ok(actions)) => {
               self.health_overrides.remove(agent_id);
               tracing::info!(
                   agent_id = %agent_id,
                   role = agent_role_label(tick_role),
                   action_count = actions.len(),
                   module = module_path!(),
                   "agent tick completed"
               );
               completed_ticks.push(CompletedAgentTick {
                   agent_id: agent_id.clone(),
                   role: tick_role,
                   actions,
               });
           }
           Ok(Err(error)) => {
               tracing::warn!(
                   agent_id = %agent_id,
                   role = agent_role_label(tick_role),
                   reason = %error,
                   module = module_path!(),
                   "agent tick failed"
               );
               self.health_overrides
                   .insert(agent_id.clone(), AgentHealth::Degraded);
           }
           Err(_elapsed) => {
               tracing::warn!(
                   agent_id = %agent_id,
                   role = agent_role_label(tick_role),
                   timeout_ms = self.config.agent_tick_timeout_ms,
                   module = module_path!(),
                   "agent tick timed out, marking degraded"
               );
               self.health_overrides
                   .insert(agent_id.clone(), AgentHealth::Degraded);
           }
       }
       ```
       This replaces the existing `match agent.tick(&env).await { Ok(...) => ..., Err(...) => ... }` block.

    **A. Replace the wildcard match arm in `apply_actions()` with explicit handling:**

    In `apply_actions()` (around line 293-306), the current match on `action` has:
    ```rust
    match action {
        SwarmAction::RoleShift { new_role } => { ... }
        SwarmAction::HealthReport { status } => { ... }
        _ => {}
    }
    ```

    Replace the `_ => {}` wildcard with explicit arms for every SwarmAction variant:

    ```rust
    match action {
        SwarmAction::RoleShift { new_role } => {
            pending_role_shifts.push(PendingRoleShift {
                agent_id: completed.agent_id.clone(),
                from_role: completed.role,
                to_role: new_role,
            })
        }
        SwarmAction::HealthReport { status } => {
            self.health_overrides
                .insert(completed.agent_id.clone(), status);
        }
        // DepositPheromone is recorded as a finding above but not
        // dispatched here — deposits flow through the substrate directly
        // from agent tick internals, not through the dispatcher action loop.
        SwarmAction::DepositPheromone { .. } => {
            // Agent-direct: deposits are submitted to the substrate by the
            // agent itself during tick(). The action is recorded as an
            // AgentFinding for peer visibility but requires no dispatcher routing.
        }
        // RequestResponse is recorded as a finding above. Response routing
        // is handled by the response executor pipeline, not the dispatcher.
        SwarmAction::RequestResponse { .. } => {
            // Agent-direct: the response executor pipeline handles these.
            // Recorded as an AgentFinding for peer visibility.
        }
        // ClaimInvestigation and PublishFindings are agent-direct actions.
        // The stalker agent manages investigation state internally.
        // These are NOT dispatcher-routed — they exist in SwarmAction
        // so they can be recorded as AgentFindings for peer visibility.
        SwarmAction::ClaimInvestigation { hunt_id, lead } => {
            tracing::debug!(
                agent_id = %completed.agent_id,
                hunt_id = %hunt_id.0,
                lead = %lead,
                module = module_path!(),
                "agent-direct action: claim_investigation (not dispatcher-routed)"
            );
        }
        SwarmAction::PublishFindings { hunt_id, confidence, .. } => {
            tracing::debug!(
                agent_id = %completed.agent_id,
                hunt_id = %hunt_id.0,
                confidence = %confidence,
                module = module_path!(),
                "agent-direct action: publish_findings (not dispatcher-routed)"
            );
        }
        SwarmAction::ProposeStrategy { strategy_id, fitness, .. } => {
            tracing::warn!(
                agent_id = %completed.agent_id,
                action = "propose_strategy",
                strategy_id = %strategy_id,
                fitness = %fitness,
                module = module_path!(),
                "unhandled swarm action variant in dispatcher"
            );
        }
    }
    ```

    **Key design notes in code comments:**
    - `DepositPheromone` and `RequestResponse`: agent-direct, recorded as findings above
    - `ClaimInvestigation` and `PublishFindings`: agent-direct, now logged at debug level instead of silently dropped. These are intentionally agent-direct (stalker manages investigation state) and the comments explain why.
    - `ProposeStrategy`: genuinely unhandled — no handler exists yet. Gets a `tracing::warn!` with `"unhandled swarm action variant in dispatcher"`.
    - `RoleShift` and `HealthReport`: dispatcher-routed as before.
