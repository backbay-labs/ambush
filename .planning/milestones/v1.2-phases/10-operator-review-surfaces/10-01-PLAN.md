# Phase 10 Plan 01: Operator Review Surfaces

<objective>
Turn the durable hot-path, investigation, and incident artifacts into one operator-facing review report with explicit freshness boundaries and degraded-mode visibility.
</objective>

<tasks>
<task number="1" type="auto">
<description>Extend the operator status report to include async investigation queue state, recent investigation summaries, and recent incidents.</description>
<acceptance_criteria>
- One report contains hot-path readiness plus async investigation and incident review sections.
- Investigation queue failures and store-readiness warnings are visible from the report.
- Recent investigations and incidents come from durable stores rather than raw file reads.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Add explicit freshness markers distinguishing hot-path decisions from later async enrichment.</description>
<acceptance_criteria>
- Report includes latest hot-path decision timestamp.
- Report includes latest investigation and incident timestamps.
- Tests verify that the report preserves the distinction between original decisions and later enrichment.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Document how operators review enriched findings, incidents, and degraded async modes.</description>
<acceptance_criteria>
- Config documentation references the investigation and correlation review surfaces.
- Runtime tests cover the full enriched operator report.
- Operator guidance explains queue failures and stale or missing async context.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-core -p swarm-spine -p swarm-runtime
</verification>

<success_criteria>
- Operators can inspect hot-path and async review state from one serializable report.
- The report shows recent investigations and incidents without raw storage inspection.
- Freshness markers distinguish authoritative hot-path output from later enrichment.
</success_criteria>
