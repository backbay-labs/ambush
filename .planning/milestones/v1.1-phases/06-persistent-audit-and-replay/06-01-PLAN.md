# Phase 6 Plan 01: Persistent Audit And Replay

<objective>
Persist replay bundles in a queryable store and expose lookup/replay helpers without re-running the original action.
</objective>

<read_first>
- .planning/phases/06-persistent-audit-and-replay/06-CONTEXT.md
- crates/swarm-spine/src/lib.rs
- crates/swarm-runtime/src/lib.rs
- crates/swarm-runtime/src/service.rs
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add a replay store abstraction with memory and local-file backends plus identifier indexes.</description>
<acceptance_criteria>
- Replay bundles persist as structured files plus an index.
- Store supports lookup by bundle ID, hunt ID, and receipt ID.
- Health and recent-decision summaries are available from the store.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Carry receipt-chain identifiers into audit trails and runtime persistence helpers.</description>
<acceptance_criteria>
- Audit records retain upstream receipt-chain identifiers.
- Persisted records expose bundle, hunt, trail, and receipt IDs.
- Runtime service can persist and reload bundles through the store abstraction.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add replay-preview helpers and tests proving that persisted inspection is side-effect free.</description>
<acceptance_criteria>
- Replay preview can be built from persisted bundles.
- Replay preview explicitly states it does not re-execute actions.
- Targeted spine/runtime tests pass.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-spine -p swarm-runtime
</verification>

<success_criteria>
- Persisted bundles survive restart and are queryable by stable identifiers.
- Audit artifacts preserve receipt correlation.
- Replay inspection remains read-only.
</success_criteria>
