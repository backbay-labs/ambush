## Active Milestone

### v1.53 Production Packaging, Recovery, And Operator Access

**Goal:** Make the system credibly deployable with secure packaging, HA and durability drills, SLO and capacity bounds, and a real operator access model instead of loopback-only shared-secret usage.
**Executable phases:** 180-183

- [ ] **Phase 180: Secure Production Packaging Profile** - Ship secure-by-default packaging for runtime, state, and dependency surfaces with an explicit supported deployment profile. (PROD-01) (queued)
- [ ] **Phase 181: Recovery Drills And Durability Validation** - Prove backup, restore, upgrade, rollback, and durability behavior across the supported state roots. (PROD-02, PROD-03) (queued)
- [ ] **Phase 182: SLO, Capacity Envelope, And Alert Baselines** - Publish end-to-end load, capacity, SLO, and alert guidance based on measured runtime behavior. (PROD-04) (queued)
- [ ] **Phase 183: Operator Access Model And Multi-Operator Audit** - Add scoped multi-operator access, attributable approvals, and a supported reference architecture for adoption. (ACCESS-01, ACCESS-02, ACCESS-03) (queued)

### Phase 180: Secure Production Packaging Profile

**Goal:** Ship secure-by-default packaging for runtime, state, and dependency surfaces with one supported deployment profile.
**Requirements:** PROD-01
**Depends on:** Phase 179
**Status:** Not Started
**Plans:** 0
**Success Criteria**:
1. Repo-owned deployment artifacts define one secure production profile instead of an ad hoc local-only layout.
2. Runtime and state-root boundaries are explicit across config, storage, and dependency services.
3. The supported packaging profile is documented clearly enough for later recovery and access milestones to build on it.

### Phase 181: Recovery Drills And Durability Validation

**Goal:** Prove backup, restore, upgrade, rollback, and durability behavior across the supported state roots.
**Requirements:** PROD-02, PROD-03
**Depends on:** Phase 180
**Status:** Not Started
**Plans:** 0
**Success Criteria**:
1. Backup, restore, upgrade, and rollback drills cover the durable runtime state roots that matter operationally.
2. Supported topology and durability expectations are explicit for both local-journal and JetStream-backed deployments.
3. Recovery evidence is durable and repeatable instead of relying on informal operator knowledge.

### Phase 182: SLO, Capacity Envelope, And Alert Baselines

**Goal:** Publish end-to-end load, capacity, SLO, and alert guidance from measured runtime behavior.
**Requirements:** PROD-04
**Depends on:** Phase 181
**Status:** Not Started
**Plans:** 0
**Success Criteria**:
1. SLOs and capacity envelopes come from measured end-to-end runtime behavior instead of microbenchmark inference.
2. Alert thresholds and operational guardrails are tied directly to those measured envelopes.
3. Operators can tell what hardware and workload profile the published numbers represent.

### Phase 183: Operator Access Model And Multi-Operator Audit

**Goal:** Add scoped multi-operator access, attributable approvals, and a supported reference architecture for operator adoption.
**Requirements:** ACCESS-01, ACCESS-02, ACCESS-03
**Depends on:** Phase 182
**Status:** Not Started
**Plans:** 0
**Success Criteria**:
1. Multiple operators can authenticate with scoped permissions over read, rehearse, approve, and maintenance actions.
2. Operator actions and approvals are individually attributable end to end in the normal audit lane.
3. A reference architecture documents supported identity, secret, deployment, and integration patterns for operators.
