# Phase 2 Plan 02: In-Memory Substrate And Metrics

<objective>
Implement the in-memory pheromone substrate, wire detector findings into it, and publish benchmark numbers for the fast-detection lane.
</objective>

<tasks>
<task number="1" type="auto">
<description>Implement an in-memory pheromone substrate with deposit, concentration query, and recent replay behavior.</description>
<acceptance_criteria>
- Deposits can be stored and queried in memory.
- Query semantics account for decay and source diversity.
- Recent deposits can be replayed or inspected for debugging.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Wire concrete detector findings into substrate-facing deposit helpers.</description>
<acceptance_criteria>
- A finding can be converted into a pheromone deposit without stringly-typed threat metadata.
- Tests prove the detector-to-substrate path works end to end.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add a lightweight benchmark harness and publish benchmark results.</description>
<acceptance_criteria>
- The team can generate p50, p95, p99, and throughput numbers.
- A repository artifact records the latest measurements.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-pheromone -p swarm-whisker -p swarm-runtime
</verification>

<success_criteria>
- The in-memory substrate is real and queryable.
- Detector-path latency numbers are published.
</success_criteria>
