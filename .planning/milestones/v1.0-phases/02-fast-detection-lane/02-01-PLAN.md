# Phase 2 Plan 01: Detector Path

<objective>
Implement one concrete detector path that accepts normalized telemetry in Rust and emits structured findings.
</objective>

<tasks>
<task number="1" type="auto">
<description>Add a concrete detector that evaluates a normalized telemetry event and produces structured findings.</description>
<acceptance_criteria>
- At least one detector is real, not a stub.
- Detector output includes threat class, severity, confidence, and evidence.
- The detector works on Rust-native normalized events only.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Align runtime pipeline types so the normalized event and finding contracts are explicit and reusable.</description>
<acceptance_criteria>
- Runtime pipeline event type maps cleanly into the detector.
- Finding output can later be translated into a pheromone deposit without lossy string conversions.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add detector-focused tests with small synthetic payloads.</description>
<acceptance_criteria>
- A positive-path test proves the detector fires on the intended pattern.
- A negative-path test proves benign events do not trigger a finding.
</acceptance_criteria>
</task>
</tasks>

<verification>

<success_criteria>
- One concrete detector exists and is tested.
- Runtime event and finding contracts are explicit and typed.
