# Phase 3 Plan 02: Response Execution Path

<objective>
Normalize the response execution path so dry-run and sandbox enforced actions return auditable receipts or failure records.
</objective>

<read_first>
- .planning/phases/03-safe-live-response/03-CONTEXT.md

- crates/swarm-response/src/lib.rs
- crates/swarm-response/src/adapters.rs
- crates/swarm-runtime/src/lib.rs
</read_first>

<tasks>
<task number="1" type="auto">
<description>Normalize the response result model so success and failure records are structurally consistent.</description>
<acceptance_criteria>
- Response execution produces a consistent receipt shape for successes.
- Failures are captured in a normalized record rather than ad hoc strings alone.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Harden the sandbox adapter and runtime wiring for both dry-run and enforced execution.</description>
<acceptance_criteria>
- Detect-only mode executes through dry-run behavior.
- Live-response mode can execute the sandbox adapter when policy authorizes it.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add runtime tests for deny, human-gated, dry-run, and allowed enforced paths.</description>
<acceptance_criteria>
- Runtime tests cover at least one deny path, one human-gated path, and one enforced success path.
- Receipt content is asserted rather than only non-empty presence.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-response -p swarm-runtime
</verification>

<success_criteria>
- The runtime can safely execute or simulate one response path.
- Response results are normalized and test-covered.
</success_criteria>
