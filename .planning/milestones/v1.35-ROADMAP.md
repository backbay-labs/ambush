## Phase Details

### Phase 104: Drain Control And Startup Probe Surface
**Goal**: Serve mode drains cleanly for Kubernetes rollouts and exposes a startup probe contract separate from steady-state readiness
**Depends on**: Phase 103 (v1.34 complete)
**Requirements**: K8S-01, K8S-02
**Success Criteria** (what must be TRUE):
  1. A PreStop handler flips the ingest server into drain mode so new `/v1/ingest/events` requests are rejected while accepted work is allowed to finish
  2. Drain completion waits for in-flight `ConfiguredRuntimeStack::process_event` work before triggering clean shutdown, bounded by `RuntimeSettings.drain_timeout_ms`
  3. `/startupz` returns HTTP 503 until startup-only checks pass, independent from `/readyz`
  4. Startup checks include loaded config schema compatibility, substrate readiness, and the presence of at least one configured telemetry source
  5. Serve-mode lifecycle tests prove drain, startup-probe, and clean-shutdown behavior
**Plans**: 2/2 plans complete

Plans:
- [x] 104-01-PLAN.md -- Add drain-state tracking, bounded shutdown coordination, and PreStop handling for serve mode
- [x] 104-02-PLAN.md -- Add `/startupz` semantics and lifecycle-focused verification for startup versus readiness behavior

### Phase 105: Schema Versioning And Secret Resolution
**Goal**: Runtime config becomes schema-aware and live response adapters can resolve rotating secrets without process restart
**Depends on**: Phase 104
**Requirements**: K8S-03, K8S-04
**Success Criteria** (what must be TRUE):
  1. `SwarmConfig` carries a required `schema_version` field and the loader rejects future or unknown schema versions fail closed
  2. Backward-compatible config transforms apply deterministically for supported older schema versions and emit structured migration-step logs
  3. `HttpEdrConfig` and `WebhookConfig` resolve `@secret:` references through one shared `SwarmSecretProvider` contract
  4. Mounted-file secrets under `RuntimeSettings.secret_dir` and environment-backed secrets can both be used for adapter authentication
  5. Secret-file watch events reload active adapter secrets without restarting the runtime
**Plans**: 2/2 plans complete

Plans:
- [x] 105-01-PLAN.md -- Add schema-versioned config parsing, supported migrations, and validation coverage
- [x] 105-02-PLAN.md -- Add shared secret resolution for response adapters and watch-driven secret reload behavior

### Phase 106: Heap Pressure Metrics And Readiness Gates
**Goal**: The runtime exports heap-pressure gauges and uses them to fail readiness before the process reaches an OOM boundary
**Depends on**: Phase 105
**Requirements**: K8S-05
**Success Criteria** (what must be TRUE):
  1. `/metrics` exposes `swarm_heap_bytes` and `swarm_heap_pressure_ratio` gauges through `CriticalPathMetrics`
  2. Heap pressure is sampled from the live process instead of a static config-only placeholder
  3. `/readyz` returns HTTP 503 when the measured pressure ratio exceeds `RuntimeSettings.max_heap_pressure`
  4. Health payloads surface heap state clearly enough for operators to distinguish memory pressure from substrate or detector degradation
  5. Metrics and readiness tests remain green across the runtime crate
**Plans**: 2/2 plans complete

Plans:
- [x] 106-01-PLAN.md -- Add live heap usage and pressure gauges to the shared Prometheus metrics surface
- [x] 106-02-PLAN.md -- Gate `/readyz` on configurable heap pressure and prove degraded readiness behavior in tests

### Phase 107: Disaster Recovery Runbook And Lifecycle Verification
**Goal**: The milestone ships with an operator-ready DR runbook and verification coverage for the new Kubernetes lifecycle hardening path
**Depends on**: Phase 106
**Requirements**: K8S-06
**Success Criteria** (what must be TRUE):
  1. A repo-owned runbook documents failure detection, operator remediation, and verification commands for JetStream loss, dead-letter disk-full, stuck-open circuit breaker, and blanket policy deny
  2. Configuration docs describe schema versioning, startup probes, drain/prestop behavior, heap-pressure readiness, and secret references
  3. Milestone verification covers cargo build, clippy, focused runtime tests, and the new lifecycle/secret/memory paths
  4. Planning state closes the milestone only after docs and runtime verification agree on shipped behavior
  5. The next queued milestone is ready to activate without reopening v1.35 gaps
**Plans**: 2/2 plans complete
