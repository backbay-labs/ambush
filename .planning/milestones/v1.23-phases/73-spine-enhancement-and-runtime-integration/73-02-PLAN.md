<objective>
Wire the guard pipeline into swarm-runtime's response authorization path so every response action is evaluated by guards before the response adapter fires, with guard rejections producing auditable records.

Purpose: GUARD-06 requires that the guard pipeline from Phase 72 actually gates response execution. Currently, `authorize_and_execute` goes straight from policy approval to response execution with no guard check. This plan inserts the guard evaluation step and adds a GuardRejected audit variant.

Output: Updated swarm-runtime with guard pipeline integration, updated swarm-spine with GuardRejected audit variant, new integration tests proving guard rejection prevents execution.
</objective>

   - The preferred approach: add a `guard_pipeline` field to `SwarmRuntime`. To avoid breaking the existing `SwarmRuntime::new(mode, policy, response)` constructor and all existing tests, add a builder method:
     ```rust
     impl<P, E> SwarmRuntime<P, E> {
         pub fn with_guard_pipeline(mut self, pipeline: GuardPipeline) -> Self {
             self.guard_pipeline = Some(pipeline);
             self
         }
     }
     ```

     Where `GuardPipeline` is the concrete type from swarm-guard (or a Box<dyn GuardEvaluator> trait object if needed).

4. Modify `authorize_and_execute`:
   - After policy evaluation passes (Allow or RequireHuman-in-detect-only), but BEFORE `self.response.execute()`, check if `self.guard_pipeline` is `Some`.

   - If any guard rejects: return a `RuntimeError` variant (add `GuardRejected { guard_name: String, reason: String }` to `RuntimeError`) instead of proceeding to execution.

5. Modify `audit_authorize_and_execute_instrumented`:

   - If guard pipeline is present, evaluate it. If rejected, produce:
     ```rust
     (None, AuditResponseRecord::GuardRejected { guard_name, reason }, None, false, false)
     ```
     instead of proceeding to response execution.
   - This means the response adapter never fires, the audit trail records the guard rejection, and the function returns successfully (not an error) with the rejection in the audit record.

6. Add `GuardRejected` to the `RuntimeError` enum:
   ```rust
   #[error("guard rejected: {guard_name}: {reason}")]
   GuardRejected { guard_name: String, reason: String },
   ```
