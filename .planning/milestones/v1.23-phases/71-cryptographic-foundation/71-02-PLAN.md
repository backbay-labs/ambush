3. Provides backward-compatibility shims so existing downstream code compiles without changes. These MUST be in a clearly marked `mod compat` section or directly in lib.rs:

   a. `pub type CryptoError = Error;` -- type alias for the old name

   b. `pub struct DetachedSignature` -- keep the existing struct definition (algorithm, key_id, public_key_hex, signature_hex fields with Serialize/Deserialize). This struct is NOT in hush-core; it is swarm-crypto's own compatibility type used by evidence.rs and review_workbench.rs.

   c. `pub struct Ed25519Signer` -- keep a compatibility wrapper that internally uses `signing::Keypair::from_seed` with a SHA-256 hash of the secret material string (matching the old `from_secret_material` behavior). Methods: `from_secret_material(&str) -> Self`, `key_id() -> &str`, `public_key_hex() -> &str`, `sign(&[u8]) -> DetachedSignature`.

   d. `pub fn canonical_json_bytes<T: Serialize>(value: &T) -> std::result::Result<Vec<u8>, CryptoError>` -- parse value through serde_json::to_value, then call `canonical::canonicalize` on it, return bytes. This preserves the old function signature.

   e. `pub fn canonical_json_string<T: Serialize>(value: &T) -> std::result::Result<String, CryptoError>` -- same but returns String.

   f. `pub fn normalize_canonical_json(raw: &str) -> std::result::Result<String, CryptoError>` -- parse raw JSON, canonicalize.

   g. `pub fn sha256_hex(bytes: &[u8]) -> String` -- NOTE: the old API returned UNPREFIXED hex. The new `hashing::sha256_hex` returns 0x-prefixed. This compat function must call `hashing::sha256(bytes).to_hex()` (unprefixed) to match the old behavior. This is critical for downstream digest comparisons.

   h. `pub fn verify_detached_signature(payload: &[u8], signature: &DetachedSignature) -> std::result::Result<(), CryptoError>` -- decode the hex fields from DetachedSignature, construct PublicKey and Signature, verify. Keep the key_id check (SHA-256 of public key bytes must match signature.key_id).
