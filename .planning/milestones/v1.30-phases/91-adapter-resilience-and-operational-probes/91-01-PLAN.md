<objective>
Add retry with exponential backoff, circuit breaker, and dead-letter persistence to HTTP EDR and webhook response adapters.

Purpose: Transient network failures currently cause silent response loss. Retry gives adapters resilience, circuit breaker prevents hammering a down endpoint, and dead-letter ensures no failed action is silently dropped.

Output: `resilience.rs` (ResilientExecutor wrapper), `dead_letter.rs` (JSONL journal), updated config structs with retry/circuit-breaker fields.
</objective>

    **Step 1 -- Config fields in swarm-core:** Add `RetryConfig` and `CircuitBreakerConfig` structs to `crates/swarm-core/src/config.rs`. Add `retry` and `circuit_breaker` fields (with `#[serde(default)]`) to both `HttpEdrConfig` and `WebhookConfig`. Defaults: `max_retries: 3`, `initial_backoff_ms: 200`, `backoff_multiplier: 2.0`, `circuit_breaker_threshold: 5`, `cooldown_ms: 30_000`. Add a `dead_letter_path` field (Option<String>, default None) to `SwarmConfig` or to a new `ResilienceConfig` section -- use your judgment on what fits the existing config shape. Validate retry config in the existing `validate()` chain (max_retries must be >= 0, initial_backoff_ms > 0, backoff_multiplier >= 1.0, threshold > 0, cooldown_ms > 0).

    **Step 2 -- DeadLetterJournal:** Create `crates/swarm-response/src/dead_letter.rs`. Define `DeadLetterEntry` (serde Serialize/Deserialize): `{ timestamp_ms: i64, receipt_id: String, action: String, mode: ExecutionMode, adapter: String, attempts: u32, last_error: String, details: Value }`. Define `DeadLetterJournal` with `path: PathBuf`. Implement `DeadLetterJournal::new(path)` that ensures the parent directory exists (create_dir_all). Implement `DeadLetterJournal::write(&self, entry: &DeadLetterEntry) -> io::Result<()>` that opens the file in append mode, serializes to JSON, appends a newline, and flushes. This is the same pattern as the LocalJournal append in swarm-pheromone. Add `mod dead_letter; pub use dead_letter::{DeadLetterJournal, DeadLetterEntry};` to lib.rs.

    **Step 3 -- ResilientExecutor:** Create `crates/swarm-response/src/resilience.rs`. Define `CircuitBreakerState` with `consecutive_failures: AtomicU32`, `last_failure_time: Mutex<Option<Instant>>`. Define `ResilientExecutor<E: ResponseExecutor>` wrapping an inner executor, a `RetryConfig`, a `CircuitBreakerConfig`, a `CircuitBreakerState`, and an `Option<Arc<DeadLetterJournal>>`. Implement `ResponseExecutor for ResilientExecutor<E>`:
    - If mode is DryRun, delegate directly to inner (no retry, no circuit breaker).
    - Check circuit breaker: if consecutive_failures >= threshold AND elapsed since last_failure < cooldown, return a synthetic `ResponseReceipt` with `ResponseStatus::Failed` and summary "circuit breaker open".
    - If circuit breaker cooldown has elapsed, allow the call (half-open state).
    - Execute inner. On success (Executed or Simulated), reset consecutive_failures to 0, return receipt.
    - On transient failure (Timeout, or connection error from ResponseError), increment consecutive_failures, update last_failure_time, sleep for backoff duration, and retry.
    - On non-transient failure (Failed with HTTP 4xx status in details), do not retry -- return immediately.
    - After exhausting max_retries, if dead_letter is Some, write a DeadLetterEntry. Return the last receipt/error.
    - Use `tokio::time::sleep` for backoff delays. Compute backoff as `initial_backoff_ms * backoff_multiplier^attempt` capped at 30 seconds.

    **Step 4 -- Wire into dispatch:** Update `DispatchingExecutor::from_config` to wrap `HttpEdrAdapter` and `WebhookAdapter` in `ResilientExecutor` when retry config is present (i.e., max_retries > 0). Sandbox adapter does not get resilience wrapping. This requires `DispatchingExecutor::from_config` to also accept a dead_letter_path parameter or a pre-built `Option<Arc<DeadLetterJournal>>`. Update the `AdapterInner` enum to hold `ResilientExecutor<HttpEdrAdapter>` and `ResilientExecutor<WebhookAdapter>` instead of bare adapters. Update `Cargo.toml` to add `tokio` features if not already present (needs `time` feature for sleep).

    **Step 5 -- Re-export and register module:** Add `pub mod resilience; pub mod dead_letter;` to `lib.rs`. Re-export key types.
