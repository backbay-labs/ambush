<objective>
Implement the HTTP EDR adapter and webhook adapter as concrete ResponseExecutor implementations with reqwest-backed HTTP clients, structured error handling, and configurable endpoints.

Purpose: The runtime currently has only a SandboxExecutor that logs intent without side effects. Real response requires HTTP calls to EDR platforms (block/isolate) and webhook notifications (Slack/PagerDuty). This plan adds both adapters and the config types that select between them.

Output: Two new ResponseExecutor implementations in swarm-response, plus adapter config types and reqwest as a workspace dependency.
</objective>

  <behavior>
    - HttpEdrAdapter::execute in DryRun mode returns Simulated receipt without making HTTP call
    - HttpEdrAdapter::execute in Enforced mode POSTs JSON body `{"action": "block_egress", "target": "...", "hunt_id": "...", "lease_id": "...", "scope": "..."}` to configured endpoint with `Authorization: Bearer <token>` header
    - HttpEdrAdapter returns Executed receipt on 2xx response, Failed receipt on 4xx/5xx, Timeout receipt on timeout
    - WebhookAdapter::execute in DryRun mode returns Simulated receipt without making HTTP call
    - WebhookAdapter::execute in Enforced mode POSTs Slack-compatible JSON `{"text": "...", "channel": "...", "attachments": [...]}` to configured URL
    - WebhookAdapter returns Executed receipt on 2xx, Failed on 4xx/5xx, Timeout on timeout
    - Neither adapter panics on network error
  </behavior>
  <action>
1. Create `crates/swarm-response/src/http_edr.rs`:
   - `HttpEdrAdapter` struct holding `config: HttpEdrConfig` and `client: reqwest::Client`
   - Constructor `HttpEdrAdapter::new(config: HttpEdrConfig) -> Result<Self, ResponseError>` that builds a reqwest Client with the configured timeout (`Duration::from_millis(config.timeout_ms)`) and no-redirect policy
   - `impl ResponseExecutor for HttpEdrAdapter`:
     - Extract action name via `request.action.kind()`
     - If `mode == DryRun`: return receipt with `Simulated` status, no HTTP call, details include the would-be payload
     - If `mode == Enforced`: build JSON body from `ActionRequest` fields (action kind, action-specific target/host_id/etc, hunt_id, lease capability_id, scope). POST to `config.endpoint` with `Authorization: Bearer {config.auth_token}` and `Content-Type: application/json`. Match on result:
       - `Ok(resp)` if `resp.status().is_success()`: return `Executed` receipt with response body in details
       - `Ok(resp)` otherwise: return `ResponseError::execution_failed` with status code and body in details, status `Failed`
       - `Err(e)` if `e.is_timeout()`: return `ResponseError::execution_failed` with timeout message
       - `Err(e)` otherwise: return `ResponseError::execution_failed` with error message
   - Receipt IDs follow pattern: `resp-edr:{hunt_id}:{capability_id}`

2. Create `crates/swarm-response/src/webhook.rs`:
   - `WebhookAdapter` struct holding `config: WebhookConfig` and `client: reqwest::Client`
   - Constructor `WebhookAdapter::new(config: WebhookConfig) -> Result<Self, ResponseError>` similar to HttpEdrAdapter
   - `impl ResponseExecutor for WebhookAdapter`:
     - If `mode == DryRun`: return receipt with `Simulated` status, no HTTP call
     - If `mode == Enforced`: build Slack-compatible JSON:
       ```json
       {
         "text": "[{severity}] {action_kind}: {summary}",
         "channel": config.channel (if set),
         "attachments": [{
           "color": severity_color(severity),
           "fields": [
             {"title": "Hunt ID", "value": hunt_id, "short": true},
             {"title": "Action", "value": action_kind, "short": true},
             {"title": "Severity", "value": severity, "short": true},
             {"title": "Scope", "value": lease.scope or "global", "short": true}
           ]
         }]
       }
       ```
     - POST to `config.url` with `Content-Type: application/json`. Handle success/failure/timeout same as HttpEdrAdapter.
   - Receipt IDs follow pattern: `resp-webhook:{hunt_id}:{capability_id}`
   - Helper `severity_color` maps Critical->danger/red, High->warning/orange, Medium->warning/yellow, Low->#439FE0/blue

3. Add `pub mod http_edr;` and `pub mod webhook;` to `lib.rs`. Re-export `HttpEdrAdapter` and `WebhookAdapter`.

4. Write tests in each module using `tokio::test`:
   - DryRun mode returns Simulated without panic (no server needed)
   - Enforced mode against a non-listening port returns a connection error (not panic)
   - Test the JSON payload structure is correct by capturing it in DryRun details

Note: Do NOT use `#[allow(clippy::unwrap_used)]` outside `#[cfg(test)]` modules. Production code must use proper error handling.
