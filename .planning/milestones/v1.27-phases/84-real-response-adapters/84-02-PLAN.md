   - `DispatchingExecutor` struct wrapping a `Box<dyn ResponseExecutor>` (or an enum dispatch for zero-allocation -- prefer enum since there are only 3 variants)
   - Internal enum `AdapterInner { Sandbox(SandboxExecutor), HttpEdr(HttpEdrAdapter), Webhook(WebhookAdapter) }`
   - `DispatchingExecutor::from_config(config: ResponseAdapterConfig) -> Result<Self, ResponseError>` factory that constructs the appropriate inner adapter
   - `impl ResponseExecutor for DispatchingExecutor` that delegates to the inner adapter's `execute` method

   - Field: `#[serde(default)] pub response_adapter: ResponseAdapterConfig`
   - This requires `swarm-response` as a dependency of `swarm-core` OR moving `ResponseAdapterConfig` to `swarm-core`. Since swarm-core should not depend on swarm-response (that creates a cycle), instead:
     - Define `ResponseAdapterConfig` in `swarm-core::config` directly (just the config enum -- not the adapter implementations)
     - Have `swarm-response::config` re-export it from `swarm-core`
     - Update `swarm-response/src/dispatch.rs` to use the config from `swarm-core`
   - Actually simpler: add the `response_adapter` field to `SwarmConfig` using a new `ResponseAdapterConfig` defined right in `swarm-core::config` since it is just a data struct with no adapter logic. Then `swarm-response` imports it from `swarm-core` (which is already a dependency).
   - Implement `Default for ResponseAdapterConfig` returning `Sandbox`.
   - Add validation in `SwarmConfig::validate()`: if HttpEdr, endpoint must not be empty; if Webhook, url must not be empty.

3. Write unit tests:
   - `DispatchingExecutor::from_config(Sandbox)` execute DryRun returns Simulated
   - Config roundtrip with response_adapter field present and absent (default)
   - SwarmConfig validation rejects HttpEdr with empty endpoint

Note on dependency direction: `swarm-core` defines config data types. `swarm-response` depends on `swarm-core` for those types. This matches the existing pattern where `SwarmConfig` already contains `PolicyConfig` etc, and `swarm-policy` depends on `swarm-core`.
