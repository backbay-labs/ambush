   This keeps the Docker build context small by excluding build artifacts, reference material, and data directories.

2. Create `Dockerfile` at repo root with a multi-stage build:

   **Stage 1 -- Builder:**
   ```dockerfile
   FROM rust:1.85-bookworm AS builder
   WORKDIR /src

   # Copy workspace manifests first for layer caching
   COPY Cargo.toml Cargo.lock* ./
   COPY crates/ crates/

   # Build release binaries for the entire workspace
   RUN cargo build --release --workspace \
       --bin swarm_detect \
       --bin swarmctl \
       && strip target/release/swarm_detect \
       && strip target/release/swarmctl
   ```

   Notes on builder stage:
   - Use `rust:1.85-bookworm` (Debian Bookworm based, stable Rust with edition 2024 support). If 1.85 is not available on Docker Hub at build time, use `rust:latest-bookworm` -- the key constraint is edition 2024 support which requires Rust >= 1.85.
   - `Cargo.lock*` glob handles the case where Cargo.lock may not exist (it is gitignored).
   - `strip` reduces binary size by removing debug symbols.
   - Building with `--bin` flags avoids building test binaries.

   **Stage 2 -- Runtime:**
   ```dockerfile
   FROM debian:bookworm-slim AS runtime

   RUN apt-get update && apt-get install -y --no-install-recommends \
       ca-certificates \
       wget \
       && rm -rf /var/lib/apt/lists/*

   # Create non-root user
   RUN groupadd -r swarm && useradd -r -g swarm -d /app swarm

   WORKDIR /app

   # Copy binaries from builder
   COPY --from=builder /src/target/release/swarm_detect /usr/local/bin/swarm_detect
   COPY --from=builder /src/target/release/swarmctl /usr/local/bin/swarmctl

   # Copy default config (can be overridden via volume mount)
   COPY rulesets/ /app/rulesets/

   # Switch to non-root user
   USER swarm

   EXPOSE 9090

   ENTRYPOINT ["/usr/local/bin/swarm_detect"]
   CMD ["--config", "/app/rulesets/default.yaml", "--serve", "--bind", "0.0.0.0:9090"]
   ```

   Notes on runtime stage:
   - `debian:bookworm-slim` matches the builder's glibc version, avoiding compatibility issues.
   - `ca-certificates` needed for future HTTPS outbound calls (EDR adapter, webhook adapter from Phase 84).
   - `wget` needed for docker-compose health check commands against /healthz.
   - Non-root user `swarm` for security.
   - Default CMD starts the detection server on 0.0.0.0:9090 (all interfaces, necessary inside container).
   - No HEALTHCHECK directive in Dockerfile -- health checking is done in docker-compose.yml using wget against /healthz.
   - ENTRYPOINT is the binary; CMD provides default arguments that can be overridden.

<task type="auto">
  <name>Task 2: Create docker-compose.yml with detection service and optional NATS</name>
  <files>docker-compose.yml</files>
  <action>
Create `docker-compose.yml` at repo root:

```yaml
services:
  swarm-detect:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "9090:9090"
    volumes:
      # Mount rulesets for hot policy reload (Plan 01 watches this file)
      - ./rulesets:/app/rulesets:ro
    environment:
      - RUST_LOG=info
    restart: unless-stopped
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost:9090/healthz || exit 1"]
      interval: 10s
      timeout: 3s
      start_period: 10s
      retries: 3

  # Optional NATS sidecar for future v1.28 multi-instance coordination.
  # Start with: docker compose --profile nats up
  nats:
    image: nats:2-alpine
    profiles:
      - nats
    ports:
      - "4222:4222"
      - "8222:8222"
    command: ["--jetstream", "--store_dir", "/data", "--http_port", "8222"]
    volumes:
      - nats-data:/data
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost:8222/healthz || exit 1"]
      interval: 10s
      timeout: 3s
      retries: 3

volumes:
  nats-data:
```

Key design decisions:
- `./rulesets:/app/rulesets:ro` volume mount means editing `rulesets/default.yaml` on the host triggers the file watcher inside the container (from Plan 01), enabling hot policy reload without restart.
- NATS uses docker compose `profiles` so it is NOT started by default `docker compose up`. To include NATS: `docker compose --profile nats up`.
- NATS JetStream is enabled with `--jetstream` for future v1.28 durable substrate work.
- `wget` is installed in the runtime image (see Task 1) for the health check command.
