## Phase Details

### Phase 100: Escalation Records And Mode-Aware Environment
**Goal**: Swarm-mode transitions persist as queryable substrate records, and agents gain explicit accessors for current mode plus last transition timing
**Depends on**: Phase 99 (v1.33 complete)
**Requirements**: SUBSTRATE-01, SUBSTRATE-02
**Success Criteria** (what must be TRUE):
  1. `PheromoneSubstrate` persists `EscalationRecord` entries and can query them by timestamp through one shared async contract
  2. In-memory, local-journal, and JetStream substrate backends preserve escalation records consistently with backend-appropriate durability
  3. `ConcentrationMonitor` writes escalation records whenever swarm mode transitions upward
  4. `SwarmEnvironment` exposes explicit `current_mode()` and `mode_transition_at()` accessors instead of forcing agents to inspect raw fields
  5. Existing dispatcher, escalation, and substrate tests remain green after the substrate contract expansion
**Plans**: 2/2 plans complete

Plans:
- [x] 100-01-PLAN.md -- Add `EscalationRecord` persistence and `query_escalations` across all substrate backends
- [x] 100-02-PLAN.md -- Expose mode-aware `SwarmEnvironment` accessors and wire escalation recording through the live monitor path

### Phase 101: Threat-Class Pheromone Policy Storage And Reload
**Goal**: Per-threat-class pheromone policy lives in the substrate and can be reloaded at runtime through operator-managed state
**Depends on**: Phase 100
**Requirements**: SUBSTRATE-03
**Success Criteria** (what must be TRUE):
  1. The substrate stores per-threat-class pheromone overrides for half-life, evaporation threshold, alert threshold, and incident threshold
  2. Runtime concentration and deposit paths can resolve threat-class overrides without breaking current global `PheromoneConfig` behavior
  3. The operator API can write and reload threat-class policy records without restarting the process
  4. Missing threat-class overrides fall back cleanly to the existing repo-configured `PheromoneConfig`
  5. Backend tests cover persistence and reload behavior for stored threat-class policy
**Plans**: 2/2 plans complete

Plans:
- [x] 101-01-PLAN.md -- Add substrate-owned `ThreatClassConfig` storage and resolution helpers for runtime concentration/deposit paths
- [x] 101-02-PLAN.md -- Surface operator-managed reload and verification coverage for threat-class pheromone policy

### Phase 102: Threat Intel Cache And Operator Query Surface
**Goal**: Operators can seed and query TTL-bound threat-intel indicators through the substrate and operator API
**Depends on**: Phase 101
**Requirements**: SUBSTRATE-04
**Success Criteria** (what must be TRUE):
  1. The substrate stores threat-intel indicators with type, value, confidence, and expiration time
  2. Operators can add threat-intel entries through the existing operator surface without editing storage files directly
  3. Operators can query threat-intel entries by type and value through the same control surface
  4. Expired entries are ignored or removed fail closed during lookup
  5. Threat-intel persistence works across configured substrate backends
**Plans**: 2/2 plans complete

Plans:
- [x] 102-01-PLAN.md -- Add threat-intel entry storage and lookup primitives to the substrate contract
- [x] 102-02-PLAN.md -- Expose operator API endpoints and verification coverage for threat-intel seeding and querying

### Phase 103: Threat Intel Enrichment And Escalation Proof
**Goal**: Detectors consult the threat-intel cache during evaluation, and integration proof shows enriched DNS detections can trigger alert escalation
**Depends on**: Phase 102
**Requirements**: SUBSTRATE-05, SUBSTRATE-06
**Success Criteria** (what must be TRUE):
  1. Detection strategies can query the threat-intel cache during evaluation without breaking existing detector contracts
  2. Threat-intel matches boost `DetectionFinding.confidence` deterministically and cap at `1.0`
  3. DNS-focused integration proof seeds threat intel, sends matching telemetry, and produces an escalated finding path
  4. The resulting enriched detection crosses the configured alert threshold and records an alert escalation in the substrate
  5. Workspace verification remains green after the substrate/intel integration lands
**Plans**: 2/2 plans complete

Plans:
- [x] 103-01-PLAN.md -- Integrate threat-intel lookups into detector evaluation and confidence shaping
- [x] 103-02-PLAN.md -- Add end-to-end threat-intel escalation integration proof and milestone verification
