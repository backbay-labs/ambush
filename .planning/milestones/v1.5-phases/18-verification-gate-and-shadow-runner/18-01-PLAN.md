# Phase 18 Plan 01: Verification Gate And Shadow Runner

<objective>
Add repo-owned candidate verification and shadow comparison workflows that stay offline, persisted, and CI-safe.
</objective>

<read_first>
- .planning/phases/18-verification-gate-and-shadow-runner/18-CONTEXT.md
- .planning/phases/17-verification-corpus-and-invariants/17-01-SUMMARY.md
- crates/swarm-runtime/src/replay.rs
- crates/swarm-runtime/src/bin/swarmctl.rs
- docs/EVOLUTION.md
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add persisted candidate verification reports with per-invariant pass/fail results and failing references.</description>
<acceptance_criteria>
- Verification reports include explicit invariant names, expected vs actual values, and counterexamples or failing references.
- Verification artifacts persist to a dedicated store and reload by stable ID.
- Failed verification exits nonzero through the CLI.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Add persisted shadow reports that compare baseline and candidate behavior over the same recorded replay corpus.</description>
<acceptance_criteria>
- Shadow reports capture detection deltas, false-positive deltas, and latency deltas over the same corpus window.
- Shadow execution remains offline and non-destructive.
- Failed shadow gates exit nonzero through the CLI.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Document and test the verification and shadow workflows end to end.</description>
<acceptance_criteria>
- `.gitignore` covers the new durable stores.
- Docs show how to run and reload both artifact types.
- Focused tests cover persisted verification or shadow artifacts plus at least one failing gate.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-runtime replay --quiet
- cargo fmt --all --check
- cargo clippy --workspace -- -D warnings
- cargo run -p swarm-runtime --bin swarmctl -- verification-evaluate --experiment experiments/office-baseline-control.yaml
- cargo run -p swarm-runtime --bin swarmctl -- shadow-evaluate --experiment experiments/office-baseline-control.yaml
- cargo run -p swarm-runtime --bin swarmctl -- verification-evaluate --experiment experiments/office-python-parent-broadening.yaml
</verification>

<success_criteria>
- Candidate verification and shadow comparison are now first-class persisted workflows.
- Operators can inspect both artifact types without opening raw JSON.
- Phase 19 can assemble a promotion review packet from stable verification and shadow IDs.
</success_criteria>
