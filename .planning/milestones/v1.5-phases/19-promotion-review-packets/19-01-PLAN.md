# Phase 19 Plan 01: Promotion Review Packets

<objective>
Persist a manual-review packet that ties together candidate lineage, verification evidence, and shadow comparison evidence without introducing deployment automation.
</objective>

- .planning/phases/19-promotion-review-packets/19-CONTEXT.md

- docs/CONFIGURATION.md
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add promotion review packet types, persistence, and blocking-reason summaries.</description>
<acceptance_criteria>
- Review packets reference stable verification and shadow IDs.
- Packets preserve failed invariant references and failed shadow-gate reasons.
- Packets expose a clear ready-for-review or blocked recommendation.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Add `swarmctl` commands to create and reload promotion review packets.</description>
<acceptance_criteria>
- Operators can create one packet from an experiment plus stable verification/shadow IDs.
- Packets reload by stable review ID.
- Output remains readable without inspecting raw JSON.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Document and verify the end-to-end review workflow.</description>
<acceptance_criteria>
- `.gitignore` covers the promotion-review store.
- Docs explain verification -> shadow -> review packet creation and reload.
- Automated verification covers at least one packet creation and reload path.
</acceptance_criteria>
</task>
</tasks>

<verification>

</verification>

<success_criteria>
- Promotion review packets are durable, inspectable, and reference the right evidence artifacts.
- Operators can reload packets by stable ID without recomputing verification or shadow results.
- The milestone is ready for audit and archival after this phase.
</success_criteria>
