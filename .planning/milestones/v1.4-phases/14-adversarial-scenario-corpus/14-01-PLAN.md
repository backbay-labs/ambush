# Phase 14 Plan 01: Adversarial Scenario Corpus

<objective>
Turn the tracked replay corpus into a named adversarial suite with explicit metadata and a stable CLI execution path.
</objective>

<read_first>
- .planning/phases/14-adversarial-scenario-corpus/14-CONTEXT.md
- crates/swarm-runtime/src/replay.rs
- crates/swarm-runtime/src/bin/swarmctl.rs
- docs/EVOLUTION.md
- scenarios/
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add scenario metadata and named suite manifests to the replay model.</description>
<acceptance_criteria>
- Scenario manifests can declare benign/adversarial class, campaign, techniques, and tags.
- Suite manifests can declare name, description, corpus version, and scenario membership.
- Tracked repo scenarios exercise both adversarial and benign paths.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Extend the replay harness and CLI to execute named suites.</description>
<acceptance_criteria>
- `DefaultReplayHarness` can load and evaluate one suite manifest.
- `swarmctl replay-evaluate --suite ...` produces one aggregate report.
- Technique groups are surfaced in the suite output.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add tests for suite execution and metadata propagation.</description>
<acceptance_criteria>
- Tests prove named suites execute deterministically from tracked manifests.
- The tracked repo suite passes under the canonical config.
- Rendered suite output is operator-readable.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-runtime replay --quiet
- cargo run -p swarm-runtime --bin swarmctl -- replay-evaluate --suite scenario-suites/hellcat-office-v1.yaml
</verification>

<success_criteria>
- Named adversarial suite execution is real and reproducible.
- Repo-owned scenario metadata is visible in suite output.
- The replay corpus is ready for candidate detector comparison.
</success_criteria>
