<task type="auto">
  <name>Task 2: Create GitHub Actions CI workflow</name>
  <files>.github/workflows/ci.yml</files>
  <action>
Create `.github/workflows/ci.yml` with a single workflow:

1. **Workflow metadata:**
   - `name: CI`
   - Trigger on `push` to branches `[main]` and `pull_request` to branches `[main]`

2. **Environment:**
   - `env: CARGO_TERM_COLOR: always` (colored cargo output in logs)

3. **Single job: `check`**
   - `runs-on: ubuntu-latest`
   - `steps:`

   a. **Checkout:**
      - `uses: actions/checkout@v4`

   b. **Install Rust stable toolchain:**
      - `uses: dtolnay/rust-toolchain@stable`
      - `with: components: rustfmt, clippy`

   c. **Cache cargo registry and build artifacts:**
      - `uses: Swatinem/rust-cache@v2`

   d. **Format check:**
      - `name: Check formatting`
      - `run: cargo fmt --all -- --check`

   e. **Clippy lint:**
      - `name: Lint with clippy`
      - `run: cargo clippy --workspace --all-targets -- -D warnings`

   f. **Build:**
      - `name: Build`
      - `run: cargo build --workspace --all-targets`

   g. **Test:**
      - `name: Run tests`
      - `run: cargo test --workspace`

   h. **Install cargo-deny:**
      - `name: Install cargo-deny`
      - `run: cargo install cargo-deny --locked`

   i. **Dependency governance:**
      - `name: Check dependencies`
      - `run: cargo deny check`

The order matters: format and lint first (fast failures), then build, then test, then deny (slowest due to install). This gives the fastest feedback loop.

Do NOT use `--all-features` on build or test -- the workspace does not use feature flags that change compilation.
Do NOT add a matrix for multiple Rust versions -- the project targets stable only.
Do NOT add separate jobs -- one job is simpler to maintain and avoids redundant checkout/cache steps for this workspace size.
  </action>
