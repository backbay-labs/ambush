  <behavior>
    DNS Exfiltration:
    - High-entropy subdomain query (e.g. "a1b2c3d4e5f6.evil.com") -> finding with DataExfiltration, High/Critical severity
    - Excessive query volume from single host (>N queries in window) -> finding with DataExfiltration
    - Known tunneling TLD patterns (e.g. dnscat2 signatures) -> finding with high confidence
    - Normal DNS query ("www.google.com") -> no finding
    - Empty/short subdomain -> no finding

    Lateral Movement:
    - WMI remote execution (wmic /node:target process call create) -> finding with LateralMovement
    - PsExec-style remote service creation -> finding with LateralMovement
    - SSH from unusual source (internal host connecting to another internal host on port 22 when not in allowed_ssh_sources) -> finding
    - RDP brute-force indicator (multiple failed auth from same source) -> finding
    - Normal local process execution -> no finding
    - SSH from allowed source -> no finding

    Credential Access:
    - Process accessing LSASS memory (lsass.exe target) -> finding with CredentialAccess, Critical severity
    - SAM registry hive read -> finding with CredentialAccess
    - Kerberoasting pattern (TGS request for SPN from unusual process) -> finding with CredentialAccess
    - Normal registry read to HKLM\SOFTWARE -> no finding
    - Normal process memory access -> no finding

    Suspicious Scripting:
    - Encoded PowerShell command (-enc/-encodedcommand with base64) -> finding with Execution, High/Critical
    - Download-and-execute chain (IEX(New-Object Net.WebClient).DownloadString) -> finding with Execution
    - LOLBin abuse (mshta, certutil -urlcache, regsvr32 /s /i:http) -> finding with DefenseEvasion
    - Normal PowerShell "Get-Process" -> no finding
    - Normal certutil for certificate operations -> no finding

    **Step 1: Extend TelemetryPayload in detector.rs.**

    Add three new variants to `TelemetryPayload` and their corresponding event structs. Keep the `#[serde(tag = "kind", rename_all = "snake_case")]` tagging and `#[serde(deny_unknown_fields)]` on each struct:

    ```rust
    // Add to TelemetryPayload enum:
    DnsQuery(DnsQueryEvent),
    RegistryAccess(RegistryAccessEvent),
    AuthenticationEvent(AuthenticationEventData),

    // New structs:
    pub struct DnsQueryEvent {
        pub query_name: String,          // full domain queried
        pub query_type: String,          // A, AAAA, TXT, MX, etc.
        pub source_ip: Option<String>,
        pub process_name: Option<String>,
        pub response_code: Option<String>, // NOERROR, NXDOMAIN, etc.
    }

    pub struct RegistryAccessEvent {
        pub process_name: String,
        pub registry_path: String,       // e.g. HKLM\SAM, HKLM\SECURITY
        pub access_type: String,         // read, write, delete
        pub target_process: Option<String>, // for process memory access (LSASS)
    }

    pub struct AuthenticationEventData {
        pub auth_type: String,           // kerberos_tgs, ntlm, ssh, rdp
        pub source_host: Option<String>,
        pub target_host: Option<String>,
        pub target_service: Option<String>, // SPN for kerberos
        pub process_name: Option<String>,
        pub success: bool,
        pub user: Option<String>,
    }
    ```

    Also update the existing `SuspiciousProcessTreeDetector::evaluate` match to handle the new variants (return empty Vec for non-ProcessStart payloads -- add a wildcard arm or explicit arms returning Vec::new()).

    **Step 2: Create dns_exfiltration.rs.**

    Follow the SuspiciousProcessTreeDetector pattern exactly:
    - `DnsExfiltrationProfile` (Serialize, Deserialize, Default, deny_unknown_fields) with fields:
      - `entropy_threshold: f64` (default 3.5 -- Shannon entropy of subdomain labels)
      - `min_subdomain_length: usize` (default 20 -- minimum total subdomain char length to flag)
      - `suspicious_query_types: Vec<String>` (default ["TXT", "NULL", "CNAME"] -- types commonly abused for tunneling)
      - `known_tunneling_patterns: Vec<String>` (default ["dnscat", "iodine"] -- known tool signatures in query names)
      - `high_confidence_threshold: f64` (default 0.9)
      - `medium_confidence_threshold: f64` (default 0.7)
    - `DnsExfiltrationDetector` struct holding resolved config
    - `from_profile()` and `profile()` methods
    - `DetectionStrategy` impl with id "dns_exfiltration"
    - `evaluate` operates on `TelemetryPayload::DnsQuery` only; returns empty for others
    - Shannon entropy calculation: for the subdomain portion (everything before the registered domain), compute `-sum(p * log2(p))` over character frequencies. Flag if entropy > threshold AND subdomain length > min_subdomain_length.
    - Known tunneling pattern matching: case-insensitive substring match against query_name.
    - Suspicious query type matching: flag TXT/NULL queries with high-entropy subdomains at higher confidence.
    - Evidence JSON includes: query_name, query_type, computed_entropy, subdomain_length, matched_pattern (if any).
    - Unit tests: at minimum the 5 behaviors listed above.

    **Step 3: Create lateral_movement.rs.**

    - `LateralMovementProfile` with fields:
      - `remote_exec_indicators: Vec<String>` (default ["wmic", "psexec", "winrs", "smbexec"])
      - `remote_exec_command_patterns: Vec<String>` (default ["/node:", "\\\\", "-accepteula", "process call create"])
      - `allowed_ssh_sources: Vec<String>` (default [] -- empty means all SSH is flagged; populated means only non-listed sources flag)
      - `suspicious_ports: Vec<u16>` (default [22, 3389, 5985, 5986] -- SSH, RDP, WinRM)
      - `high_confidence_threshold: f64` (default 0.85)
      - `medium_confidence_threshold: f64` (default 0.65)
    - `LateralMovementDetector` with `from_profile()`, `profile()`
    - `DetectionStrategy` impl with id "lateral_movement"
    - Evaluates `ProcessStart` payloads for remote exec tool indicators (process_name or command_line matches remote_exec_indicators/patterns)
    - Evaluates `NetworkConnect` payloads for connections to suspicious_ports from sources not in allowed list
    - Evaluates `AuthenticationEvent` for failed auth attempts (success=false with auth_type in ["rdp", "ssh"])
    - Evidence JSON includes: matched_indicator, process/connection details, host context
    - Unit tests: at minimum the 6 behaviors listed above.

    **Step 4: Create credential_access.rs.**

    - `CredentialAccessProfile` with fields:
      - `protected_processes: Vec<String>` (default ["lsass", "lsass.exe"] -- process memory targets)
      - `sensitive_registry_paths: Vec<String>` (default ["HKLM\\SAM", "HKLM\\SECURITY", "HKLM\\SYSTEM"] -- credential store paths)
      - `kerberoasting_indicators: Vec<String>` (default ["kerberos_tgs"] -- auth types that indicate TGS requests)
      - `suspicious_spn_requestors: Vec<String>` (default ["mimikatz", "rubeus", "powershell", "cmd"] -- processes that shouldn't request SPNs)
      - `high_confidence_threshold: f64` (default 0.9)
      - `medium_confidence_threshold: f64` (default 0.7)
    - `CredentialAccessDetector` with `from_profile()`, `profile()`
    - `DetectionStrategy` impl with id "credential_access"
    - Evaluates `ProcessStart` payloads: check if command_line references protected processes (e.g., contains "lsass")
    - Evaluates `RegistryAccess` payloads: check registry_path against sensitive paths; check target_process against protected processes
    - Evaluates `AuthenticationEvent` payloads: check for kerberoasting (auth_type matches kerberoasting_indicators AND process_name matches suspicious_spn_requestors)
    - Evidence JSON includes: matched_indicator, process/registry/auth details, why flagged
    - Unit tests: at minimum the 5 behaviors listed above.

    **Step 5: Create suspicious_scripting.rs.**

    - `SuspiciousScriptingProfile` with fields:
      - `encoded_command_flags: Vec<String>` (default ["-enc", "-encodedcommand", "-e ", "frombase64string"])
      - `download_execute_patterns: Vec<String>` (default ["downloadstring", "downloadfile", "invoke-webrequest", "wget", "curl", "bitsadmin", "certutil -urlcache"])
      - `lolbins: Vec<String>` (default ["mshta", "regsvr32", "rundll32", "certutil", "cmstp", "msiexec", "wmic", "forfiles", "pcalua"])
      - `lolbin_abuse_patterns: Vec<String>` (default ["/i:http", "-urlcache", "scrobj.dll", "/s /i:", "mshta http", "mshta vbscript"])
      - `high_confidence_threshold: f64` (default 0.9)
      - `medium_confidence_threshold: f64` (default 0.7)
    - `SuspiciousScriptingDetector` with `from_profile()`, `profile()`
    - `DetectionStrategy` impl with id "suspicious_scripting"
    - Evaluates `ProcessStart` payloads only:
      - Encoded commands: process_name is a scripting engine (powershell, pwsh, cmd) AND command_line contains encoded_command_flags -> ThreatClass::Execution, high confidence
      - Download-and-execute: command_line contains download_execute_patterns -> ThreatClass::Execution, high confidence
      - LOLBin abuse: process_name matches lolbins AND command_line matches lolbin_abuse_patterns -> ThreatClass::DefenseEvasion, medium-high confidence
      - If both encoded AND download patterns match -> Critical severity
    - Evidence JSON includes: process_name, command_line, matched_patterns, heuristic flags
    - Unit tests: at minimum the 5 behaviors listed above.
