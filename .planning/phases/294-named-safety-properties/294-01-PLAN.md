# Phase 294 — Named Safety Properties And Partition-Lease Model

**Status:** implementation plan, 2026-09-08. Executed with subagent-driven-development. Branch
`feat/safep-294` off `main` `9f8c591c8` (Phase 293 complete). Third and final v1.81 phase — it names
the decision core's guarantees as falsifiable properties and model-checks the highest-risk concurrent
logic (the partition-contingency-lease protocol) with a TLA+/Apalache model.

**Goal (ROADMAP.md).** State the decision core's guarantees as named, mapped, falsifiable properties
(P1–P6), register the two remaining trust assumptions, and model-check the partition-contingency-lease
state machine with Apalache — including negative falsifiability that reproduces real defects.

**Requirements, verbatim (REQUIREMENTS.md:928–932).**
- **SAFEP-01**: `formal/PROPERTIES.md` defines P1–P6 (fail-closed evaluation, severity-gate soundness,
  partition-override receipt integrity, blast-radius conservation, quorum-transition soundness,
  rate-limit boundedness), each naming exact symbols and checking harnesses.
- **SAFEP-02**: P1–P6 gain rows in `docs/assurance/MAPPING.md` following its existing schema.
- **SAFEP-03**: `ASSUME-INJECTED-CLOCK` and `ASSUME-GOVERNOR-KEY-CUSTODY` are registered in
  `assumptions.toml` with owners and dependent properties.
- **SAFEP-04**: `formal/tla/PartitionContingency.tla` models the four partition states, lease issuance
  and redemption with blast-radius cap, and reconciliation on heal, with named invariants.
- **SAFEP-05**: At least 3 negative-falsifiability entries produce Apalache violations, each naming the
  runtime regression test pinning the same defect.

**Success criteria (ROADMAP.md).** (1) P1–P6 each defined with exact symbols + the harnesses that check
them, and appear as `docs/assurance/MAPPING.md` rows with valid existing Rust paths; (2)
`ASSUME-INJECTED-CLOCK` + `ASSUME-GOVERNOR-KEY-CUSTODY` registered with owners + dependent properties;
(3) Apalache model-checks the lease state machine clean in CI for its named invariants; (4) at least 3
negative-falsifiability entries produce the expected violation, each naming the runtime regression test
pinning the same defect.

## Design of record (controller rulings, 2026-09-08; re-verify at HEAD)

- **P1–P6 map to EXISTING symbols + harnesses — this phase names, it does not re-implement.** The
  decision core (292) and its Kani harnesses (293) already exist; P1–P6 are the named statements of
  what they guarantee. The expected mapping (the implementer verifies each symbol + harness resolves):
  - **P1 fail-closed evaluation** → `swarm_policy::static_gate::StaticApprovalGate::evaluate` +
    `formal_core::{severity_floor_denial,human_gate_decision}`; harnesses
    `kani_severity_floor_low_is_sound_for_every_action`, `kani_human_gate_holds_destructive_at_or_above_gate`;
    negative test `negative_policy_malformed_request_rejected`.
  - **P2 severity-gate soundness** → `formal_core::{severity_floor_denial,human_gate_decision,destructive_action}`;
    the severity + `kani_destructive_action_classifies_every_variant` harnesses.
  - **P3 partition-override receipt integrity** → `swarm_agents::tom_agent::ContingencyLease::verify`
    (receipt-bound, above swarm-policy); MODEL-ONLY harnesses
    `kani_model_only_{invalid_signature,non_approve_decision,hash_mismatch}_*`; runtime tests
    `keyless_policy_reloaded_into_a_partition_refuses_persisted_leases`,
    `governance_policy_approves_destructive_actions_with_signed_receipt_when_healthy`.
  - **P4 blast-radius conservation** → `formal_core::lease_redeem`; harness
    `kani_model_only_blast_radius_conservation`; unit tests `lease_redeem_records_a_new_scope_within_budget`,
    `lease_redeem_fails_closed_on_mismatch_expiry_and_cap`; TLA+ invariant `BlastRadiusNeverExceeded`.
  - **P5 quorum-transition soundness** → `formal_core::governance_quorum_threshold`; harnesses
    `kani_governance_quorum_threshold_is_2f_plus_1`, `..._is_monotonic_and_saturating`; TLA+ quorum
    transition invariant.
  - **P6 rate-limit boundedness** → `formal_core::evaluate_rate_limit`; the three `kani_rate_limit_*`
    harnesses; the `PolicyScopeRateLimitDeniesBurst` invariant.
- **SAFEP-02 MAPPING rows — satisfy `check-mapping.sh`, do not weaken it.** Read `tools/check-mapping.sh`
  FIRST. If it requires a `// INVARIANT:` (or equivalent) marker at the cited path for every row, then
  P1–P6 rows must cite symbols that either already carry a marker or gain one WITHOUT changing behaviour
  (a comment only). Prefer citing the exact `formal_core`/gate functions the 293 harnesses prove (they
  are the property's real home). If the checker distinguishes a PROPERTY row from an INVARIANT row,
  follow that schema. `check-mapping.sh` and `check-negative-registry.sh` MUST stay exit 0.
- **SAFEP-03 assumptions.** `ASSUME-INJECTED-CLOCK`: the clock is caller-supplied (`now_ms: i64`) at
  every `formal_core` entry (the 292 functional-core/imperative-shell result), so the pure decision
  functions never read the OS clock; owner `swarm-policy`; dependent properties P1/P2/P4/P6.
  `ASSUME-GOVERNOR-KEY-CUSTODY`: exactly one governor key is registered and its custody is not
  adversarially shared (the single-governor-key property, measured 2026-08-13); owner `swarm-agents`;
  dependent properties P3/P5. Match the existing `[assume.NAME]` schema (`owner`, `statement`, plus a
  `dependent_properties` list if the schema supports it — follow `check-mapping.sh`'s parse).
- **SAFEP-04 TLA+ model — typed, bounded, named invariants.** `formal/tla/PartitionContingency.tla`
  models: the four partition states (e.g. `Healthy`, `Degraded`, `Partitioned`, `Healing`), contingency
  lease issuance (only in a partition, with a `blast_radius_cap`) and redemption (bounded by the cap,
  denied when expired), and reconciliation on heal (leases pruned/settled). NAMED invariants at least:
  `BlastRadiusNeverExceeded` (redeemed scopes ≤ cap), `NoRedemptionAfterExpiry`, `OverrideRequiresReceipt`
  (a lease exists only via an approved receipt), and a quorum/transition invariant. Typed (`@type`
  annotations); bounded (`CONSTANT`s small, `--length` small) so Apalache terminates. Ships with a run
  helper (`scripts/run-apalache-partition.sh` or a `.cfg`) that checks every named invariant clean.
- **SAFEP-05 negative falsifiability — the TLA+ analog of the 285 negative registry.** ≥3 entries, each
  a deliberately-broken model variant (or an invariant negation) that Apalache reports as a VIOLATION
  (EXITCODE ERROR), each NAMING the runtime regression test that pins the same defect (e.g. breaking
  the cap check ↔ `lease_redeem_fails_closed_on_mismatch_expiry_and_cap`; removing the expiry guard ↔
  `lease_can_redeem_denies_an_expired_lease`; dropping the receipt requirement ↔
  `keyless_policy_reloaded_into_a_partition_refuses_persisted_leases`). A registry file + a check
  script that proves each broken variant fails (non-vacuous), mirroring `check-negative-registry.sh`.
- **SC3 CI.** Apalache runs in CI (a dedicated `apalache` job, engine-path-gated, installs Apalache +
  Java, checks the clean model's named invariants, and runs the negative-falsifiability check).
  Path-convention note: SAFEP names `formal/PROPERTIES.md`, `formal/tla/PartitionContingency.tla`,
  `assumptions.toml`, `MAPPING.md` — all used verbatim (no slip). The run/check scripts are runners, so
  they go in `scripts/` (like `run-kani-swarm-policy.sh`) and are wired by their CI job, not by
  `check-gates-wired.sh`.
