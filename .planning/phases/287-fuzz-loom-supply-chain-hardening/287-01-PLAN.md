## Design of record (controller rulings, 2026-09-08)

Codex's `287-CODEX-PREP.md` is a high-confidence read-only source audit; each task RE-VERIFIES the
seams it names against HEAD before relying on them (codex noted timing/acceptance unverified).

- **Three independent tracks + close.** SUPPLY (Task A), FUZZ (Task B), LOOM (Task C) touch disjoint
  files and can run in PARALLEL worktrees (like phases 290/291), cherry-picked onto the phase branch;
  Task D closes. The one shared surface is `.github/workflows/ci.yml` (FUZZ-04's 30s smoke step and
  SUPPLY-02's gate wiring are both additive ci.yml steps in different jobs) — the merge order nets
  the additive edits; if a textual conflict arises, the controller resolves it. Codex's order note
  ("supply can proceed in parallel with bounded independent parser work") corroborates independence.

- **FUZZ needs a NIGHTLY toolchain, isolated from the pinned stable.** cargo-fuzz requires `-Z`
  build-std / sanitizer flags (nightly). The repo pins Rust 1.97.1 (stable) via `rust-toolchain.toml`
  for the main workspace and its gates. The `fuzz/` directory is cargo-fuzz's OWN separate workspace
  (its `fuzz/Cargo.toml` is `[workspace]`-excluded from the root) — it may use nightly without
  touching the pinned stable. The fuzz CI jobs install nightly + `cargo-fuzz`; the main gates stay on
  1.97.1. FUZZ-04's 30s PR smoke uses `-runs=` or `-max_total_time=30` bounded so it is deterministic
  breakage detection, NOT a fuzzing budget; a real crash still fails the step.

- **FUZZ targets call REAL parse entry points, with corpus CONVERSION.** Each target's harness calls
  the actual decoder (Task B verifies the exact `fn` for `ingest_json_decode`,
  `ingest_sentinel_decode`, `ingest_tetragon_decode` in swarm-ingest-runtime, and `ruleset_yaml_parse`
  in the ruleset loader). Per codex: raw `scenarios/*.yaml` / `rulesets/*.yaml` are NOT automatically
  valid input for every decoder — `seed-fuzz-corpus.sh` CONVERTS each fixture into the target's real
  wire format (e.g. a JSON event body, a sentinel/tetragon record, a raw YAML document) before
  writing it into that target's corpus dir. Reuse the prior audit of public unresolved configuration
  parsing to avoid environment/filesystem secret resolution during ruleset fuzzing.

- **LOOM-01 includes a REAL PRODUCTION FIX, not only a model.** Codex found a PREEXISTING
  split-persistence race in `swarm-pheromone/src/substrate.rs` (deposit appends to disk; GC takes the
  still-old in-memory vector lock and rewrites disk without the fresh entry; deposit then pushes into
  memory; reopen loses the fresh deposit — blob identical at base `5ad9b6850` and 286 final, so NOT a
  286 regression). Task C REPRODUCES it with a Loom model AND REPAIRS the production append/GC
  ordering AND adds an actual concurrent-reopen regression test. The Loom model is a
  `bounded_abstract_model` (Loom instruments only `loom::sync` types, not the production std locks —
  use explicit Loom state or a reviewed shared seam, and label it exactly `scope =
  "bounded_abstract_model"` in MAPPING). Loom is 0.7.2 (cached; add as a `[dev-dependencies]` behind a
  `cfg(loom)` gate so it never enters the shipped graph); preemption bound 2 documented; leave
  `max_permutations`/`max_duration` UNSET (those caps can stop exploration with a false pass); CI
  timeout is the failing bound.

- **LOOM-02 models the policy decision-vs-reload seam.** Codex: `swarm-policy/src/configurable_gate.rs`
  rebuilds an immutable rule vector in a new gate (the policy crate has no reload op); the actual
  reload is in `swarm-ingest-runtime/src/ingest/mod.rs` (construction + separate ArcSwaps) with
  request routing reading a held generation. Assert ONE held runtime generation per decision/lease;
  do NOT claim all composition fields swap atomically. A supplemental last-slot test models atomic
  prune/check/increment under one mutex.

- **SUPPLY: validate metadata BEFORE cargo, correct stale rationales.** `tools/check-supply-chain.sh`
  parses `deny.toml` with a TOML parser (not a line regex), fails if any `[advisories].ignore` or
  version skip lacks a `last-checked` date + blast-radius + clearing condition, and DERIVES the
  `cargo audit --ignore` argv from the validated advisory entries so the two cannot drift (add/remove
  an advisory ⇒ the recorded argv gains/loses exactly one matching ignore). Preserve cargo-deny
  schema compatibility. Correct the stale rationales codex named (re-verify at HEAD): rustls-pemfile
  is a DIRECT dep (`swarm-runtime-http`), webpki-roots re-exports the locked roots (not two snapshots),
  instant is reachable via nostr (`swarm-perch-bridge`) not only notify, and the historical "nineteen
  skips" is actually twenty. Record/pin tool versions (the existing gate installs tools unpinned).

- **Scripts vs. tools + CI (repo convention).** New gate `tools/check-supply-chain.sh` (it already
  exists — ENHANCE it) and any new `tools/*.sh` are wired into `ci.yml` so `check-gates-wired.sh`
  stays green. New workflows `fuzz-nightly.yml` + `loom-nightly.yml` are scheduled (cron +
  workflow_dispatch), gated OUT of the fast PR lane; FUZZ-04's smoke and the supply gate are the only
  new PR-lane additions.
