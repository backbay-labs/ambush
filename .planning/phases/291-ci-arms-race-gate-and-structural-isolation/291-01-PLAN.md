# Phase 291 — CI Arms Race Gate And Structural Isolation

**Status:** implementation plan, 2026-09-07. Executed with the subagent-driven-development skill.
Branch `feat/red-swarm-291` off `main` `fb4eb7b22` (phases 288–290 landed). The LAST red-swarm
(v1.80) phase.

**Goal (ROADMAP.md).** Ship an *executed* gate rather than an attested one, and enforce
STRUCTURALLY that the red lane generates telemetry and scores detectors without ever reaching
response authority. Phase 290 built the campaign; 291 makes CI run it as a regression gate and adds
two isolation gates (a shell scan + a Rust test) that fail if the red lane ever grows a path to
response authority.

**Requirements, verbatim (REQUIREMENTS.md:890–894).**
- **ARMSCI-01**: CI runs a bounded campaign and fails the build if `final_blue_catch_rate` regresses
  below a checked-in threshold; the gate ships in the same phase as its executor.
- **ARMSCI-02**: `scripts/check-red-swarm-no-execution-authority.sh` fails if any forbidden symbol
  (`execute_response`, `ResponseAdapter`, `PolicyDecision::Authorize`, `live_response`) appears in
  red-swarm sources.
- **ARMSCI-03**: A Rust-side companion test performs the same check at `cargo test` time, with a
  documented counterexample fixture proving the check is not vacuous.
- **ARMSCI-04**: `swarmctl evolution status --json` includes a `red_swarm_campaign` object sourced
  from the on-disk report, reporting `null` rather than a stale value when absent.
- **ARMSCI-05**: A wall-clock budget guard fails the CI step loudly rather than silently inflating
  build time.

**Success criteria (ROADMAP.md).**
1. CI runs the bounded campaign and fails if final blue catch rate regresses below the checked-in
   threshold, reading the file the executor actually writes.
2. The isolation script exits 0 on the real tree and exits 1 against a fixture with an injected
   response-execution call, proving it is not vacuous.
3. A Rust-side companion test performs the same check at test time, with a documented counterexample.
4. `swarmctl evolution status --json` reports the campaign object, and reports null rather than a
   stale value when the report file is absent; a wall-clock guard fails a runaway campaign loudly.

**Design of record (controller rulings, 2026-09-07).**
- **The gate lives in `tools/`, not `scripts/`.** ARMSCI-02's text names `scripts/…`, but every gate
  in this repo lives in `tools/` and `tools/check-gates-wired.sh` scans `tools/check-*.sh`. Naming it
  `scripts/…` would leave it un-enforced by the wiring gate and break the repo convention. Ruling:
  `tools/check-red-swarm-no-execution-authority.sh`; note the requirement's path slip in the summary.
- **New gates MUST be wired into `.github/workflows/ci.yml`** in the SAME task that adds them —
  `check-gates-wired.sh` fails the build for any `tools/check-*.sh` no workflow invokes ("a gate that
  never runs is not a gate"). ci.yml already invokes 31 gates as `run: bash tools/check-X.sh` steps;
  the new gates follow that exact pattern.
- **The isolation gate proves it is not vacuous** the way `tools/check-no-unrouted-authorize.sh`
  does: before scanning, plant a synthetic forbidden symbol in a temp tree and assert the needle
  matches it; if it does not, exit non-zero WITHOUT scanning. An empty scan and a broken needle must
  never look identical.
- **"Red-swarm sources"** = the red lane only: `crates/swarm-runtime/src/red_swarm/**` plus the
  red-swarm CLI (`crates/swarm-cli/src/red_swarm_cmd.rs`). Exclude `#[cfg(test)]`/fixtures that
  deliberately contain a counterexample (or scope the scan so the ARMSCI-03 fixture does not trip it).

**What exists (verified in tree at `fb4eb7b22`).**
- `swarmctl red-swarm campaign … --json` (290) writes `data/red-swarm/campaigns/<campaign>-<seed>.json`
  and prints a report whose `final_blue_catch_rate` is the executor's own number.
- `.github/workflows/ci.yml` (name: CI) runs 31 `tools/check-*.sh` gates; `tools/check-gates-wired.sh`
  enforces every gate is invoked; `tools/check-no-unrouted-authorize.sh` is the plant-a-counterexample
  precedent. The four red-swarm gates already green: `check-{runtime-panic-contract,workspace-layering,
  visibility-baseline,gates-wired}.sh`.
- `crates/swarm-runtime/src/evolution_status.rs`: `EvolutionStatusReport` + `render_evolution_status`
  (:534); `EvolutionAdversarialSummary { corpus_sequence_id: Option<String>, .. }` (:192). `swarmctl
  evolution status` renders this. The red lane already carries ZERO response-authority symbols
  (290's whole-branch review confirmed), so ARMSCI-02/03 pass on the real tree from day one.

## Global constraints

Carried from 288–290 (still bind): Rust 1.97.1, edition 2024; `cargo fmt --all`; `cargo clippy
--workspace --all-targets -- -D warnings`; `unwrap_used`/`expect_used` denied outside `mod tests`; no

reaches no response authority; determinism where output-affecting. Shell gates are `bash`, `set
-euo pipefail`, portable (the repo's gates rely on plain `python3`/coreutils, no PyYAML). Public items
documented in the crate's voice; tests `a_thing_does_x_when_y`; commits `git commit -s`, Conventional
Commits. **Every new `tools/check-*.sh` is wired into `ci.yml` in its own task** (or `check-gates-wired.sh`
fails). CI edits are additive workflow steps — do not remove or reorder existing gates.

### Task 1: The structural-isolation gate + its Rust companion (ARMSCI-02, ARMSCI-03)

**Files.** `tools/check-red-swarm-no-execution-authority.sh` (new); a Rust test (in
`crates/swarm-runtime/src/red_swarm/`, e.g. a `mod isolation_gate` test or extend an existing test
module) + a documented counterexample fixture; a `run: bash tools/check-red-swarm-no-execution-authority.sh`
step in `.github/workflows/ci.yml`.

**Behaviour.**
- The shell gate scans the red-swarm sources (`crates/swarm-runtime/src/red_swarm/**`,
  `crates/swarm-cli/src/red_swarm_cmd.rs`) for the forbidden symbols `execute_response`,
  `ResponseAdapter`, `PolicyDecision::Authorize`, `live_response`; exits 1 if any appears (outside a
  clearly-scoped test/fixture region), 0 otherwise. Before scanning it PLANTS each forbidden symbol
  in a temp file and asserts the needle matches — else exits 2 without scanning (not-vacuous proof).
- ARMSCI-03: a Rust test performs the same scan at `cargo test` time over the same sources, with a
  **documented counterexample fixture** (a string the test constructs that WOULD trip the gate) proving
  the check catches a real injection. The test passes on the real tree (no forbidden symbol) and its
  counterexample assertion proves non-vacuity.

**Tests / verification.** The gate exits 0 on the real tree and exits 1 against a temp fixture with an
injected `execute_response(` call (SC 2). `cargo test` runs the companion test green. `bash tools/
check-red-swarm-no-execution-authority.sh` and `bash tools/check-gates-wired.sh` both pass (the new
gate is wired). fmt/clippy clean.

### Task 2: The executed CI arms-race gate + wall-clock guard (ARMSCI-01, ARMSCI-05)

**Files.** `tools/check-red-swarm-arms-race.sh` (new); a checked-in threshold (a small file, e.g.
`rulesets/red-swarm/arms-race-threshold.txt`, or a constant the gate documents); a `run:` step in
`.github/workflows/ci.yml`.

**Behaviour.**
- The gate builds `swarmctl` (or uses the CI-built binary), runs ONE bounded campaign
  (`red-swarm campaign` with fixed small `--max-generations`/seed/`--virtual-clock-start-ms`), reads
  the `final_blue_catch_rate` from the report file the executor actually writes
  (`data/red-swarm/campaigns/…`) — SC 1's "reading the file the executor actually writes", not
  re-parsing stdout — and FAILS (exit 1) if it is below the checked-in threshold, with a message
  naming the observed vs. required value.
- ARMSCI-05: the campaign run is wrapped in a wall-clock guard (`timeout <budget>`); on expiry the gate
  fails LOUDLY (exit non-zero, a message saying the campaign exceeded its budget), never silently
  hangs or inflates build time.

**Tests / verification.** The gate passes on the real tree (real campaign meets the threshold);
manually lowering the threshold makes it pass and raising it above the real value makes it fail
(prove the comparison bites); the timeout guard fires on a stubbed slow run. `bash tools/
check-red-swarm-arms-race.sh` and `bash tools/check-gates-wired.sh` pass. Keep the campaign bounded so
CI time stays small.

### Task 3: `red_swarm_campaign` in `evolution status --json` (ARMSCI-04)

**Files.** `crates/swarm-runtime/src/evolution_status.rs` (extend `EvolutionStatusReport` +
`render_evolution_status` and/or the harness that builds it); the `swarmctl evolution status` path if
it needs to pass a report path.

**Behaviour.** `swarmctl evolution status --json` includes a `red_swarm_campaign` object sourced from
the on-disk campaign report (`data/red-swarm/campaigns/…`): when a report exists, the object carries
its key facts (e.g. `final_blue_catch_rate`, `stop_reason`, generation count, `corpus_sequence_id`);
when ABSENT, the field is `null` — NEVER a stale value from a prior run. Deterministic; a missing/
malformed report file is `null` (fail-soft for a status read), not an error.

**Tests / verification.** With a report present → the object is populated; with it absent → `null`;
a stale prior value never survives. `render_evolution_status`'s existing tests still pass; the JSON
shape is stable (fixed field order). fmt/clippy clean; `cargo test -p swarm-runtime evolution_status`.
