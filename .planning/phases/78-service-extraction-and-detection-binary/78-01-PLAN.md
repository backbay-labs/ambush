<task type="auto">
  <name>Task 2: Create swarm-detect binary with config, scenario, and detection pipeline wiring</name>
  <files>crates/swarm-runtime/src/bin/swarm_detect.rs</files>
  <action>
Create `crates/swarm-runtime/src/bin/swarm_detect.rs` as a focused detection binary. The binary should:

**CLI structure (using clap derive):**
```
swarm_detect
  --config <path>       # default: "rulesets/default.yaml"
  --scenarios-dir <path> # optional: directory of scenario YAML files to process at startup
  --scenario <path>      # optional, repeatable: individual scenario file(s) to process
  --json                 # emit JSON output instead of human-readable
```

**Main flow:**
1. Parse CLI args with clap
2. Load config via `swarm_runtime::config::load_config(&cli.config)`
3. Log the runtime mode (`detect_only` or `live_response`) from `config.runtime.mode`
4. Build the detector via `swarm_runtime::control::supported_detector(&config.detection.strategy)`
5. Build an in-memory pheromone substrate via `swarm_pheromone::InMemoryPheromoneSubstrate::new(config.pheromone.clone())`
6. Create an `AgentId("swarm-detect".to_string())`
7. Collect scenario files:
   - If `--scenarios-dir` provided: read all `.yaml` files from that directory
   - If `--scenario` provided: use those paths directly
   - If neither provided: print config summary and exit cleanly (no scenarios to process)
8. For each scenario file:
   a. Load via `swarm_runtime::replay::load_scenario_manifest(&path)`
   b. Extract events from `manifest.input` (only handle `ReplayScenarioInput::Events` variant)
   c. For each `ReplayScenarioStep` in the events:
      - Call `swarm_runtime::pipeline::detect_and_deposit(&detector, &substrate, &step.event, &agent_id, &config.pheromone).await`
      - If `--json`: serialize the `DetectionPipelineOutcome` as JSON and print
      - Otherwise: print a human-readable summary line: event_id, finding count, deposit count
   d. Print scenario summary: total events, total findings, total deposits
9. Print overall summary: scenarios processed, total events, total findings

**Runtime mode handling:**
- The binary uses `config.runtime.mode` to report whether it is running in `detect_only` or `live_response` mode
- The actual mode affects the `SwarmRuntime` behavior if policy evaluation is invoked (but the minimal binary only needs detection + deposit for the hot path proof point)
- For the initial binary, policy evaluation happens implicitly through `process_event` if wired through `ConfiguredRuntimeStack`, but the minimal path uses `detect_and_deposit` directly which is mode-independent (the detection and deposit path is the same regardless of mode -- mode matters for response execution)
- Print the mode in startup banner so operators can confirm the binary respects config

**Error handling:**
- Use `Result<(), Box<dyn std::error::Error>>` for main
- Print actionable error messages for missing config, bad scenario files, unsupported detector strategy
- Do not use `.unwrap()` or `.expect()` -- use `?` operator throughout (this binary should be a model for Phase 80's lint enforcement)

**Imports needed:**


Keep the binary under 150 lines. This is intentionally minimal -- it proves the hot path runs standalone. Future phases may add a long-running event loop, metrics endpoint, etc.
