# Phase 288 — Red Operator Genome And Target Graph

**Status:** implementation plan, 2026-09-07. Executed with the subagent-driven-development
flow (each `### Task N` below is one dispatch); the GSD frontmatter above keeps the phase
directory legible to the engine's planning ledger.

**Goal (ROADMAP.md:1179).** `red_swarm.rs` today replays static suites verbatim. Give the red
lane a bounded mutation engine that recombines catalogued techniques rather than inventing
payload shapes, keeping the arms race classical and maintainable.

**Requirements, verbatim (REQUIREMENTS.md:869–872).**
- **OPFOR-01**: Six red operator roles (`ReconOperator`, `InjectionOperator`, `AuthOperator`,
  `EvasionOperator`, `ChainOperator`, `OpsecOperator`) implement a shared `RedOperator` trait
  with `propose_steps(&self, graph, rng) -> Vec<GeneStep>`.
- **OPFOR-02**: `TargetGraph` is built from `rulesets/evasion/attack-technique-catalog.yaml` and
  every scenario's `metadata.techniques`; nodes are the 11 catalogued detectors, techniques, and
  `ThreatClass` values.
- **OPFOR-03**: `RedGenomeRng` is a deterministic `rand_core::RngCore` + `SeedableRng` PRNG with
  zero OS-entropy paths.
- **OPFOR-04**: `RedGenome::plan(seed, generation, campaign)` resolves every
  `GeneStep.technique` only to techniques already in the `TargetGraph` (no invented techniques or
  payload shapes); `swarmctl red-swarm plan` prints the plan with a `determinism` object
  (`rng_seed`, `virtual_clock_start_ms`, `scheduler`).

**Success criteria (ROADMAP.md:1187–1191).**
1. Six operator roles implement a shared trait, and the target graph's technique-node set equals
   the union of the catalog's declared techniques and every suite scenario's declared techniques.
2. `RedGenome::plan` is proven pure: identical arguments produce byte-identical output, and a
   20-seed sweep produces at least one differing step per seed.
3. A test fails if any generated step names a technique absent from the target graph.
4. `swarmctl red-swarm plan` prints a `determinism` object with `rng_seed`,
   `virtual_clock_start_ms`, and `scheduler`, and no code path reads wall-clock for output bytes.

**What exists (from the 2026-09-07 survey).** `crates/swarm-runtime/src/red_swarm.rs` (385
lines): `ThreatContext`, `AdversarialSequenceArtifact`, `RedSwarmError`, the `RedSwarmAdapter`
trait, `SuiteRedSwarmAdapter` (verbatim suite replay, deterministic re-timestamping) and
`MockRedSwarm`; `crates/swarm-runtime/src/evasion_coverage.rs` loads the catalog

and the four suites under `scenario-suites/` carry `metadata.techniques`;

genome and mutation harness live in `crates/swarm-runtime/src/mutation/` and are NOT this

### Task 1: The module directory, the target graph, and the PRNG (OPFOR-02, OPFOR-03)

**Files.**
- `git mv crates/swarm-runtime/src/red_swarm.rs crates/swarm-runtime/src/red_swarm/mod.rs`
  (history preserved; the existing types and adapters stay exactly where callers find them:
  `crate::red_swarm::{ThreatContext, AdversarialSequenceArtifact, RedSwarmError, RedSwarmAdapter, SuiteRedSwarmAdapter, MockRedSwarm}`
  — `grep -rn 'red_swarm::' crates --include='*.rs'` for every call site, notably
  `kitten_agent.rs:1179` and `replay/`).
- `crates/swarm-runtime/src/red_swarm/graph.rs` — `TargetGraph`.
- `crates/swarm-runtime/src/red_swarm/rng.rs` — `RedGenomeRng`.
- Tests beside each (`#[cfg(test)] mod tests` in-file, or `graph_tests.rs`/`rng_tests.rs` via
  `#[path]` if the file would pass 800 lines).

**`TargetGraph`.** Built by `TargetGraph::from_repo(catalog_path, suite_paths) -> Result<Self, RedSwarmError>`
and, for tests, `TargetGraph::from_parts(catalog: &EvasionTechniqueCatalog, suites: &[LoadedSuite])`.
Reuse `evasion_coverage.rs`'s loader for the catalog (do not parse the YAML twice) and
`replay::load_replay_suite_manifest` + `load_scenario_manifest` for the suites. Nodes:
- `Node::Detector(String)` — the 11 catalogued detectors, in catalog order;
- `Node::Technique(String)` — the union of every `intentionally_uncovered[].technique` and every
  scenario's `metadata.techniques` (SC 1), sorted, deduplicated, each carrying
  `TechniqueNode { id, threat_classes: BTreeSet<ThreatClass>, scenarios: Vec<ScenarioRef>, declared_uncovered_by: Vec<String /*detector*/> }`
  where `ScenarioRef { suite: String, scenario: String, event_count: usize }`;
- `Node::ThreatClass(ThreatClass)` — every value that appears on a catalog gap or a scenario.
Edges are implicit in the node fields (a technique knows its classes, scenarios and the
detectors that declared it uncovered); expose `techniques()`, `technique(id)`, `detectors()`,
`threat_classes()`, `techniques_for(class)`, `is_technique(id)`, and `fingerprint() -> [u8; 32]`
(SHA-256 over the canonical JSON of the graph — `serde_json` with sorted keys via `BTreeMap`s —
so a plan can name the graph it was planned against). Serializable (`Serialize`/`Deserialize`),
`PartialEq`, `Debug`.

**`RedGenomeRng`.** SplitMix64 seeding into xoshiro256** (both are public-domain algorithms;
implement them in `rng.rs` with the reference constants, cite the reference in the doc
comment), implementing `rand_core::RngCore` and `rand_core::SeedableRng` with `Seed = [u8; 32]`;
`RedGenomeRng::from_u64(seed: u64)` derives the 256-bit state through SplitMix64;
`fork(&mut self, label: &str) -> RedGenomeRng` derives a child stream from the parent's next
64 bits XOR the FNV-1a hash of `label` so each operator gets its own stream and inserting an
operator never shifts another's draws. No `Default`, no `new()` without a seed, no `getrandom`
feature use: the type cannot be constructed from entropy. Provide `next_below(&mut self, n: u64) -> u64`
(rejection sampling, unbiased) and `choose<'a, T>(&mut self, items: &'a [T]) -> Option<&'a T>`.

**Tests.**
1. `the_graph_technique_set_is_the_union_of_catalog_and_suite_techniques` — from the real repo
   files (`rulesets/evasion/attack-technique-catalog.yaml` and the four suites): the technique
   set equals the union computed independently in the test from the raw YAML (SC 1); the
   detector set has exactly the 11 catalogued detectors in order; every technique's
   `threat_classes` is non-empty.
2. `a_technique_declared_uncovered_names_the_detector_that_declared_it`.
3. `the_graph_fingerprint_is_stable_and_changes_with_one_technique` — same inputs twice ⇒ same
   32 bytes; add one technique ⇒ different bytes.
4. `the_prng_matches_the_reference_vectors` — xoshiro256** first outputs for a known state
   (the reference implementation's published test vector, or vectors you compute by hand from
   the algorithm and pin — say which); SplitMix64 first outputs for seed 0 and seed 1.
5. `two_rngs_from_one_seed_agree_and_a_fork_diverges_without_disturbing_the_parent` —
   parent A and B from the same seed; fork A with "recon"; A and B continue identically only if
   B is forked the same way; A's post-fork sequence equals a third rng seeded and forked
   identically.
6. `next_below_is_unbiased_enough_and_never_out_of_range` — 100,000 draws below 7: every value
   in range; each bucket within 5 % of uniform.
7. `no_entropy_path_exists_in_the_red_lane` — the test reads every `.rs` under
   `crates/swarm-runtime/src/red_swarm/`, strips `#[cfg(test)]` modules and comments, and
   asserts none of `getrandom`, `OsRng`, `thread_rng`, `SystemTime`, `Instant::now`,
   `Utc::now`, `Local::now` appears (SC 4, half of it; Task 3 extends the list to the CLI
   output path).

### Task 2: The genome, the six operators, and the pure planner (OPFOR-01, OPFOR-04)

**Files.**
- `crates/swarm-runtime/src/red_swarm/genome.rs` — `GeneStep`, `RedGenome`, `RedPlan`,
  `CampaignParams`, `Determinism`.
- `crates/swarm-runtime/src/red_swarm/operators/mod.rs` — the `RedOperator` trait and the
  registry; one file per role: `recon.rs`, `injection.rs`, `auth.rs`, `evasion.rs`, `chain.rs`,
  `opsec.rs`.
- Tests beside each.

**Types.**
```rust
pub struct GeneStep {
    pub operator: OperatorRole,          // Recon | Injection | Auth | Evasion | Chain | Opsec
    pub technique: String,               // a TargetGraph technique node, always
    pub threat_class: ThreatClass,       // one the technique declares
    pub scenario: ScenarioRef,           // where the events come from
    pub event_indices: Vec<usize>,       // which events of that scenario, in order
    pub host_slot: u8,                   // 0..max_distinct_hosts (Phase 289 binds it)
    pub offset_ms: i64,                  // from the virtual clock start, never wall-clock
    pub intent: StepIntent,              // Probe | Exploit | Persist | Evade | Chain(from: usize) | Cover(step: usize)
}
pub struct RedPlan { pub generation: u32, pub campaign: String, pub graph_fingerprint: [u8;32], pub steps: Vec<GeneStep>, pub determinism: Determinism }
pub struct Determinism { pub rng_seed: u64, pub virtual_clock_start_ms: i64, pub scheduler: &'static str /* "round_robin_v1" */ }
pub struct CampaignParams { pub name: String, pub virtual_clock_start_ms: i64, pub steps_per_operator: u8 /* default 3 */, pub max_steps: u16 /* default 24 */ }
pub trait RedOperator: Send + Sync {
    fn role(&self) -> OperatorRole;
    fn propose_steps(&self, graph: &TargetGraph, rng: &mut RedGenomeRng) -> Vec<GeneStep>;
}
```
`RedGenome::plan(seed: u64, generation: u32, campaign: &CampaignParams, graph: &TargetGraph) -> RedPlan`
seeds `RedGenomeRng::from_u64(seed ^ (generation as u64).rotate_left(32))`, forks one child
stream per operator by role name, calls the six operators in the fixed order Recon, Auth,
Injection, Chain, Evasion, Opsec (the `scheduler` string names this order; changing it changes
the string), interleaves their proposals round-robin up to `max_steps`, assigns `offset_ms` as a
monotone schedule (`step_index * 1_000 + rng jitter below 250` — jitter from the planner's own
stream), and stamps `determinism` and `graph_fingerprint`. It is a pure function of its
arguments: no I/O, no clock, no globals.

**The six roles**, each choosing only among the graph's techniques and their scenarios' events:
- `ReconOperator` — techniques whose threat class is `discovery`/`initial_access` (fall back to
  the lowest-severity scenario events); intent `Probe`; prefers techniques declared uncovered
  by at least one detector (the gaps are where reconnaissance goes first).
- `InjectionOperator` — `execution` / `fileless_execution`-flavoured techniques
  (`suspicious_scripting`, `fileless_execution`, `suspicious_process_tree` detectors' gaps and
  scenarios); intent `Exploit`.
- `AuthOperator` — `credential_access` / `lateral_movement`; intent `Exploit`.
- `EvasionOperator` — rewrites one earlier step of the current plan (given via the graph +
  rng only? No: the trait takes the graph and rng; the planner passes each operator the steps
  proposed so far through a `PlanSoFar<'_>` argument — amend the trait to
  `propose_steps(&self, graph, rng, so_far: &[GeneStep])`; this is the one place the brief's
  signature is extended, and the reason is recorded in the doc comment) by choosing a technique
  that the same detector declares uncovered; intent `Evade`.
- `ChainOperator` — takes two existing steps whose threat classes form a kill-chain adjacency
  (initial_access→execution→persistence→credential_access→lateral_movement→exfiltration→impact,
  the order `standard_threat_classes()` already fixes) and proposes the bridging technique;
  intent `Chain(from)`.
- `OpsecOperator` — proposes at most `steps_per_operator` `Cover(step)` steps that reuse a
  benign-control scenario's events (the suites' `class: Benign` scenarios) after a noisy step;
  intent `Cover`.
Every operator is total: with an empty applicable set it returns an empty `Vec`, never panics.

**Tests** (all with the real repo graph, plus a hand-built `TargetGraph::from_parts` fixture
where a property needs a small graph):
1. `every_generated_step_names_a_graph_technique` — 20 seeds × 3 generations: every step's
   `technique` satisfies `graph.is_technique` and its `scenario`/`event_indices` exist (SC 3);
   this test must FAIL when a test-only operator that invents `"T9999.999"` is registered
   (include that negative control as a second test that asserts the planner's validation
   rejects it with `RedSwarmError::UnknownTechnique`).
2. `plan_is_byte_identical_for_identical_arguments` — serialize two plans from the same
   `(seed, generation, campaign, graph)` and compare bytes (SC 2).
3. `a_twenty_seed_sweep_differs_in_at_least_one_step_per_seed` (SC 2).
4. `each_operator_role_appears_and_the_scheduler_string_is_pinned` —
   `determinism.scheduler == "round_robin_v1"`, the six roles all appear in a plan with
   `max_steps = 24`.
5. `an_operator_with_nothing_applicable_proposes_nothing` — a graph with only `impact`
   techniques: Recon and Auth return empty, the plan is still valid.
6. `offsets_are_monotone_and_never_from_the_wall_clock` — offsets strictly increase; the
   entropy-path test from Task 1 covers the module tree.
7. `the_evasion_operator_only_rewrites_toward_a_declared_gap`.
8. `the_chain_operator_only_bridges_adjacent_classes`.

**Verification.** As Task 1's, plus `cargo test -p swarm-runtime red_swarm::genome red_swarm::operators`.
