<two_scope_two_freeze_finalization>
Closure has two physically and cryptographically separate scopes with an
ordered two-freeze protocol:

1. **Scope A — candidate/public freeze.** Plan 00's immutable allowlist,
   public semantic truth/baseline, upstream pin map, Phase 287/288 typed bridge
   pins, lifecycle export generation, and deterministic in-sample reports are
   frozen together. The coordinator emits a signed
   `CandidateFreezeReceipt` whose subject binds the allowlist/tree digest,
   public metric schema/version, upstream digests, export signer anchor,
   generation/predecessor/source high-water, and no evaluator or reviewer
   records. Scope A is immutable before any withheld evaluator or independent
   review process is opened.
2. **Scope B — external evaluator/review freeze.** Only after a valid Scope A
   receipt does the separately signed evaluator process issue the
   `SignedFreezeReceipt`/one-shot capability, and only after that receipt does
   the out-of-band review root issue assignment/provenance records. Scope B
   contains the evaluator bundle/root and review-root records outside the
   candidate tree; it may expose only opaque aggregate digests/results.

The final parser requires both receipts, exact scope tags, distinct process and
issuance nonces, matching candidate lineage/export generation, and the strict
ordering `Scope A freeze -> evaluator freeze -> reviewer assignment -> review
closure`. It rejects swapped/replayed receipts, a Scope B field in Scope A, a
candidate-tree evaluator/reviewer artifact, an evaluator opened before Scope A,
or a final review that omits either freeze. Mutations cover every scope tag,
freeze ID, predecessor, tree/allowlist/upstream/metric digest, evaluator
process nonce, issuance ID, reviewer assignment ID, expiry, and receipt
signature.
</two_scope_two_freeze_finalization>

<mutation_outcome_contract>
Mutation results are typed machine values; reviewer prose cannot choose a
severity or status:

```rust
pub enum MutationOutcome {
    ExpectedReject { exit_code: i32, evidence_digest: Digest64 },
    ExpectedPass { exit_code: i32, evidence_digest: Digest64 },
    UnexpectedPass { exit_code: i32, evidence_digest: Digest64 },
    UnexpectedReject { exit_code: i32, evidence_digest: Digest64 },
    MissingEvidence,
    MalformedEvidence,
    NotApplicable { reason_digest: Digest64 },
}
pub enum MutationStatus { Closed, Open, NotApplicable }
pub enum MutationSeverity { None, P0, P1, P2, P3 }
pub struct MutationDisposition { status: MutationStatus, severity: MutationSeverity }
```

The parser exhaustively maps `ExpectedReject` and `ExpectedPass` to
`(Closed,None)`, `UnexpectedPass` to `(Open,P1)`, `UnexpectedReject` to
`(Open,P2)`, `MissingEvidence` or `MalformedEvidence` to `(Open,P0)`, and
`NotApplicable` to `(NotApplicable,P3)` only when its declared control class
is explicitly N/A. Any unrecognized enum tag, zero-execution/no-op mutation,
missing exit/evidence digest, negative/ambiguous status, or author-provided
severity/status is `(Open,P0)` and fails the parser. Mapping is pure,
order-independent, and recomputed from observed exit code plus evidence bytes;
every enum variant and each boundary is mutated in both review artifacts.
</mutation_outcome_contract>
