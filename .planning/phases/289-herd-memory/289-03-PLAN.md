<objective>
Implement the restart-safe herd-memory lifecycle: durable refusal/quarantine/contradiction state, atomic accepted imports, revocation/expiry/deletion, and tombstone-first garbage collection.

Purpose: a correct envelope is not enough if accepted state, indexes, heads, or refusal reasons can diverge across a crash. Lifecycle state must be authoritative and non-actionable after expiry, revocation, quarantine, contradiction, or deletion.
Output: memory and local-file stores with identical logical semantics, atomic generations, durable refusal reasons, and complete restart/fault/GC tests.
</objective>

review artifact. Export signing has a separate config-bound private-key

```rust
impl ExportSignerAnchor {
    pub(crate) fn root_subject_bytes(&self) -> Vec<u8> {
        // Canonical root subject excludes anchor_digest and root_signature (and
        // no nested signature/self digest is included), while retaining every
        // key/path/owner/mode/scope/epoch/generation/predecessor binding.
        canonical_anchor_subject_without_self_fields(self)
    }
}

impl HerdMemoryLifecycleSnapshot {
    pub(crate) fn export_signature_subject_bytes(&self) -> Vec<u8> {
        // This is a distinct subject from ExportSignerAnchor's root subject.
        // It excludes only the lifecycle snapshot's own signature/digest fields
        // and includes the already-verified anchor_digest and anchor reference;
        // it never recursively signs or self-includes the root signature.
        canonical_lifecycle_export_subject_without_self_fields(self)
    }
}
```

`HerdMemoryExportSigner::from_config` is a private constructor reachable only
through the crate-private `HerdMemoryExportSignerFactory::from_config` called
by `HerdMemoryLifecycleHandle::from_config` (a runtime config factory may
receive only the resulting opaque lifecycle handle). It opens a distinct
owner-only, no-follow 0700/0600 export-key root from the configured
`HerdMemoryConfig.export_signer_key_root` (external custody is pinned at
`/run/ambush/phase289/export-signer/root.v1`); it is
not constructed from caller bytes, an injected signer, an environment value,
or the HMAC provider. Private key bytes are zeroized and the signer is not
`Debug`, `Clone`, `Serialize`, or `Deserialize`. The signer validates the
external root key ID/digest, root-signed issuer anchor, tenant/receiver scope,
domain, schema, registry generation, current epoch, active signer generation,
expiry, and revocation/rotation chain before `sign_export` returns a detached
signature. The exporter has no API that accepts a caller signer or raw key.
Rotation and revocation are root-authenticated, generation-bound, durable, and
rechecked on restart and immediately before commit; old/revoked/foreign/wrong-
scope keys cannot sign. `ExportSignerAnchor` is root-signed by the external
issuer root, not by the export signer itself, and binds the exact key digest,
no-follow custody path, owner UID, owner mode, tenant/receiver scope, epoch,
signer generation, registry generation, external root, and predecessor. The
anchor digest is a required lifecycle field and is revalidated at startup,
prepare, and commit. The external-root anchor subject excludes exactly
`anchor_digest` and `root_signature`—there is no second anchor
signature-digest field—but includes every anchor key/path/owner/mode/scope/
epoch/generation/predecessor binding. The lifecycle signing subject excludes
exactly `snapshot_digest` and `signature` and includes every
lifecycle/lineage/generation/predecessor/source-highwater/nonce/fence field
plus the verified anchor digest and signer generation.
The two subjects are deliberately distinct: `ExportSignerAnchor::root_subject_bytes()`
is the external-root subject and excludes only that anchor's own
`anchor_digest` and `root_signature`; `HerdMemoryLifecycleSnapshot::export_signature_subject_bytes()`
is the lifecycle subject and excludes only the snapshot's own `signature` and
`snapshot_digest` while retaining the verified `export_signer_anchor_digest`
and `root_anchor_digest` references. Neither subject contains the other
subject's signature/digest or a recursively serialized object. Tests replace
each excluded field, each anchor reference, and each lifecycle field
independently and require the corresponding subject/signature refusal.
Mutating key bytes/digest, path, owner, mode, scope, epoch, signer generation,
registry generation, root, predecessor, or anchor digest fails closed.

<lifecycle_export_contract>

before this plan and again before each lifecycle test wave. Import and export
share one fixed lock order (`lifecycle OS lock -> registry lock`) and one

The coordinator and decoder token remain private to the spine crate. The only
cross-crate import surface is the bounded raw-byte entrypoint
`HerdMemoryLifecycleHandle::import_untrusted_bytes(&[u8])`; no public candidate,
typed envelope, token, ticket, or verified value exists. That entrypoint creates
one private `HerdMemoryDecodeToken` after duplicate-aware canonical decoding,
rechecks its canonical byte digest, performs trust/poisoning/registry/head/nonce
validation, and consumes it inside the one locked CAS. Decode and verification
failures use the same handle-owned `record_refusal_cas` generation, so a crash
cannot turn a refusal into an accepted value. The only cross-crate export surface is
`HerdMemoryLifecycleHandle::prepare_export(...) ->
Result<HerdMemoryExportReservation, ExportRefusal>` followed by
`HerdMemoryLifecycleHandle::commit_export(HerdMemoryExportReservation, ...)`;
the reservation has private fields and no public constructor, serializer, or
field mutators, so callers cannot assemble a second coordinator or bypass the
handle-owned lock/signer. `prepare_export` validates the detached
`ArenaLineage`, expected generation, predecessor, source high-water, nonce
reservation, issuer root anchor, export-signer anchor, scope, schema, domain,
epoch, and fencing token under the lock. `commit_export` calls
only the config-bound `HerdMemoryExportSigner::sign_export` after revalidating
root/scope/domain/schema/epoch/key status, then writes a durable digest-only
crash journal, canonical signed snapshot, payload/index state, and fence in one
CAS; it syncs file and parent directory and then clears the journal in a second
durable generation. Recovery converts orphan prepare
records to a typed refusal/retry fence and never makes an uncommitted payload
actionable. Tests cover crash before journal, after journal, before CAS, after
CAS/before journal clear, retry, concurrent same generation, stale predecessor,
nonce/fence reuse, and exact memory/file canonical parity.
</lifecycle_export_contract>
