    "chain_recall_improvement_bp",
    "false_edge_bp",
    "duplicate_work_bp",
    "evidence_coverage_bp",

`GitObjectId::parse` accepts only the current repository object format `sha1`
and exactly `^[0-9a-f]{40}$`; it rejects uppercase, `0x`, 64-hex SHA-256,
abbreviations, whitespace, and algorithm substitution. `Digest64` remains
exactly `^[0-9a-f]{64}$`. Every parser mutation changes algorithm, length, case,
prefix, or one byte and proves refusal.

Every report declares `metric_schema_version: herd-memory-metrics-v1`, uses only
the six names in `METRIC_NAMES`, and uses the four exact formula identifiers in
`METRIC_FORMULA_IDS`; aliases such as `false_causal_edges_bp`,
`evidence_coverage_percent`, or an unversioned `formula_id` are rejected. For
every report arm, evidence coverage is the exact integer metric
`evidence_coverage_bp = floor_div_u128(covered_evidence * 10_000,
required_evidence)`, with `required_evidence > 0`, checked `u128` widening and
product, and `0 <= covered_evidence <= required_evidence`; an empty numerator
is exactly `0`, and a non-divisible numerator rounds down (for example
`1/3 -> 3333`, never 3334). Zero denominator, over-count, overflow, alternate
rounding, missing numerator/denominator, and float mutations fail closed. The
numerator, denominator, formula identifier, and rounded value are persisted;
this definition is authoritative for the manifest, benchmark, oracle, review,
and verification parser.
</typed_id_and_metric_contract>
