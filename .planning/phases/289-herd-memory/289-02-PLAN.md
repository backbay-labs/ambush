<objective>
Build the registry-anchored trust and strict signed-stream verification layer for herd-memory records.

Purpose: self-carried public keys, loose sequence checks, or in-memory refusal errors would let a validly signed peer splice data across tenants/epochs or replay stale memory. Trust admission, content integrity, freshness, nonce, and predecessor checks must be one typed contract before lifecycle persistence.
Output: trusted issuer registry/rotation, domain-separated envelope signing and verification, strict chain/nonce state contracts, and a comprehensive negative mutation suite.
</objective>

Existing generic envelope/chain code is a precedent only. Its issuer-derived public key is not a federation trust anchor; this plan must perform registry admission first.

The verified handoff is explicit and data-only:
```rust
pub struct VerifiedHerdMemory {
    pub envelope: HerdMemoryEnvelope,
    pub body_hash: String,
    pub registry_generation: u64,
    pub verified_epoch: u64,
}
```
`VerifiedHerdMemory` is constructed only after every ordered trust/content/freshness/nonce/chain check succeeds, is exported from `swarm-spine`, and carries no policy, approval, receipt, action, dispatcher, or response authority.
