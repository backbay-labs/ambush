Trust admission, content integrity, freshness, nonce, and predecessor checks must be one typed contract before lifecycle persistence.
Output: trusted issuer registry/rotation, domain-separated envelope signing and verification, strict chain/nonce state contracts, and a comprehensive negative mutation suite.

`NeutralSignatureBytes` is the only Phase 289 signature value: it contains
bounded signature bytes and no embedded public key, key path, custody proof,
issuer identity, or resolver. `ExternallyKeyedVerifier::verify(subject,
signature)` receives the canonical subject and the neutral bytes after the
caller has resolved an independently authenticated key. The resolver is the
sole implementation of that trait; callers cannot select a key from the
signature. The legacy self-key verifier, any `DetachedSignature` type that
embeds/derives a public key, and any `verify(subject, self_carried_key, ...)`
API are forbidden and are source-scanned as mutations. Every test substitutes
the subject bytes, one signature byte, external key bytes, key ID, path, root
artifact, custody record, and replacement root independently; each mutation
must fail closed. `issuer_signature` and all export/evaluator signatures use
the same bytes-only `NeutralSignatureBytes` representation.

The independently provisioned root key/digest/custody evidence is resolved only
through `ExternalRootKeyResolverFactory::from_config` and
`ExternalRootKeyResolver::resolve_and_verify_pin` from the accepted out-of-band
pin, with owner-only no-follow custody and explicit operator/CI provisioning
evidence. `ExternalRootKeyPin` is resolver-only configuration state: its fields
are private, it has no public literal/deserialize constructor, and only the
root-provisioning/config resolver may create it after authenticating the
external path, key digest, and custody evidence. `RootDetachedSignature`
carries only the external root key ID and signature bytes; it contains no public
key, path, custody proof, or authority material. Its canonical subject is the typed statement with
`subject_digest`, `root_signature`, and all self digest/signature fields
excluded, but it retains the statement's typed `root_key_id` binding. The
resolver supplies the authenticated key and requires both the statement key ID
and detached signature key ID to equal the externally pinned root key ID;
excluding the detached signature's duplicate key ID is only self-field
exclusion, not a loss of key binding. Root-signed rotation
and revocation statements form a predecessor/generation chain; the root
signature is verified against the externally resolved root before any issuer
entry can become active. A self-carried legacy keyed signature, public key, path,
or key ID can never authenticate that external root. Exact mutation tests
substitute the canonical subject, external key bytes, key ID, external path,
root artifact digest, root custody evidence, and root replacement independently;
each fails closed before issuer admission. The explicit
`ExternallyKeyedVerifier for ResolvedExternalRootKey` implementation accepts
only canonical subject bytes plus `NeutralSignatureBytes`; callers cannot
construct, replace, serialize, clone, or debug-print the resolved key. The
public `HerdMemoryRootVerifier` is an opaque config-bound facade for runtime
and test crates: `from_config` invokes the private resolver factory, and
`verify_detached` accepts only the public bytes-only `RootDetachedSignature`.
It exposes no `ExternalRootKeyPin`, path, public-key bytes, custody record, or
caller-selected verifier, so Plan 07 can verify out-of-band review/evaluator
signatures without importing private resolver types or creating a second root
authority. The facade has no constructor from signature-carried key material
and rejects a self-key/legacy verifier mutation.
