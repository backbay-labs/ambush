`derive_logical_task_id` derives the claimant-independent `TaskId` from graph,
typed target, kind, and seed bytes. The existing `TaskClaimRequest` continues
to derive its claimant-scoped `IdempotencyKey`; the two values are never
interchangeable. `TaskDecisionLink` is the narrow additive lineage path:
challenge links task -> `TaskTarget::Edge` -> decision/evidence, and
falsification links task -> `TaskTarget::Hypothesis` -> decision/evidence.
`TaskTerminalEnvelope` wraps the existing completion rather than changing its
wire fields. `validate_completion_kind` accepts only
`AcquireEvidence -> EvidenceAdded|NoFinding`, `ChallengeEdge -> EdgeChallenged`,
and `FalsifyHypothesis -> HypothesisFalsified`; it also requires producer and
capability witness identities to match the claimant key.

`GraphSchedulerKey` remains canonical. Its dispatch comparator is explicit:
ready time ascending, `priority_basis_points` descending (higher score first),
closed `TaskKind` rank ascending, and `TaskId` ascending. `SchedulerBudget`
counts work and claims per injected logical tick; either limit rejects before
side effects. `GraphPolicyMode` is closed and behavioral: EvidenceFirst blocks
convergence until evidence coverage, ChallengeContradictions emits
falsification work and retains alternatives, and ConservativeContainment
admits only reversible bounded simulations. Canonical policy bytes include the
mode; digest-only mutations fail the behavior oracle.

The existing `StrategyMemory` wire shape remains unchanged for old signed
records. New stores sign a separate version-1 `StrategyMemoryExpiryEnvelope`
over `memory_id` and `memory_digest`. A missing envelope is legacy/quarantined
and cannot influence priority; an unknown version, digest mismatch, bad
signature, zero/overflow TTL, or `expires_at <= created_at` fails closed. New
memory applies only for `created_at <= now < expires_at`, so exact expiry is
observable without rewriting old memory bytes. `max_memory_ttl_ticks`,
`max_work_units_per_tick`, and `max_claims_per_tick` are serde-defaulted config
limits; absent fields use bounded defaults and are covered by migration tests.
