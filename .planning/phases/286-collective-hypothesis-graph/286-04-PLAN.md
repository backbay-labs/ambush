Terminal publication is one state transition. `accept_terminal_once` builds
one next `GraphStoreState` from one `GraphStoreSnapshot`, updates the task to
its terminal state, applies the evidence and decision/hypothesis-history delta,
and inserts a core `TaskTerminalOutboxEntry` containing the optional strategy
memory and signed expiry envelope. It calls exactly one
`HypothesisGraphStore::compare_and_swap`; it must not call a separate
`StrategyMemoryStore` write. A post-CAS outbox consumer may index or drain the
already-committed memory idempotently, but memory is not visible as durable
strategy state until the outbox-bearing CAS succeeds. A failed CAS, stale
lease, duplicate terminal, or validation error leaves the task, reasoning
state, memory payload, and outbox byte-identical.

The core DTO validates the exact task ID/descriptor, claimant and producer

The durable state and store seam are also explicit, rather than an
implementation-detail promise. Plan 03's existing state schema remains
`GRAPH_STORE_SCHEMA_VERSION = 1`; the reasoning extension uses a separate
closed migration marker so old signed graph/task records can be upgraded
without pretending that a new schema byte was already persisted:

```rust
pub const GRAPH_STATE_MIGRATION_LEGACY: u32 = 0;
pub const GRAPH_STATE_MIGRATION_HYPOTHESES: u32 = 1;
pub const GRAPH_STATE_MIGRATION_CURRENT: u32 = GRAPH_STATE_MIGRATION_HYPOTHESES;
pub const fn legacy_graph_state_migration_marker() -> u32 {
    GRAPH_STATE_MIGRATION_LEGACY
}
```

Deserialization may default a missing marker to `LEGACY` (`0`) only after the
stored legacy bytes have been authenticated. The file reader must first parse
the exact Plan 03 wire shape (including its absent new fields), recompute the
legacy canonical state bytes and digest, verify the detached state signature
and high-water anchor, and only then normalize into the current struct with
empty bounded reasoning fields. It must never serde-default the new fields and
then verify the old signature: doing so changes signed canonical bytes and
would turn a migration into signature bypass. A tampered legacy state, digest,
anchor, or signer is rejected before any defaulting or migration side effect.

`GraphStoreState::with_reasoning_state` must run the exact `LEGACY -> HYPOTHESES`
transformation: add empty bounded `hypotheses`, cross-links,
`logical_task_descriptors`, decision/projection maps, and terminal outbox, and
set the current marker while preserving graph/tasks/tombstones/fencing/high-
water, the verified predecessor digest, and every verified legacy signature
input. New tasks cannot enter the current marker without a persisted
`LogicalTaskDescriptor`; legacy tasks without one remain readable but are
quarantined from terminal admission until an independently signed descriptor
backfill is supplied. Markers above `CURRENT` or a transformed record with
mismatched graph ID, limits, descriptor/task ID, digest, or signer are
rejected. The migration test names are
`legacy_signed_bytes_are_verified_before_reasoning_defaults`,
`legacy_graph_state_migrates_v0_to_v1_preserving_logical_time_high_water`, and
`unknown_graph_state_migration_marker_is_rejected`; all run against memory and
reopened file stores, with the tampered-legacy case asserting no state change.

`HypothesisTaskLedger::from_config` constructs
`SchedulerBudget::new_with_config(config, logical_tick)` and stores that
config-bound budget in the runtime coordinator/ledger. Every logical tick
uses the stored budget for both work and claim admission; it may advance only
through the injected `GraphLogicalTime`, and serialization/restart cannot reset
its counters. No `SchedulerBudget::default()`, global ceiling, or unbounded
`u64::MAX` lease validation is permitted. Production task creation and
completion call the exact existing `snapshot`/`compare_and_swap` seam. Repeated
creation with the same graph/target/kind/seed descriptor returns the existing
task without a second task or CAS side effect; a different seed derives a
different `TaskId`, and a descriptor mutation for an existing ID is rejected.

`HypothesisTaskLedger::complete_task` validates the admitted task, key-bound
capability proof, signed terminal witness,
`validate_completion_kind(task.kind, envelope.completion.kind)`,
lease/fence, claimant-scoped `IdempotencyKey`, persisted descriptor/task ID,
task/completion-kind mapping, and full `TaskDecisionLink` before constructing
one next `GraphStoreState`. It performs exactly one
`HypothesisGraphStore::compare_and_swap` containing the terminal task record,
graph evidence, hypothesis decision history, and core outbox entry; when
memory is present its signed `StrategyMemoryExpiryEnvelope` is stored in that
same entry and checked against the injected logical time. Publication is
drained only after that CAS succeeds. A stale lease, failed validation,
duplicate terminal, wrong producer key, or CAS conflict returns without
changing tasks, hypotheses, decisions, memory, or outbox. The accepted
terminal result therefore cannot publish partial evidence or memory.
`swarm_core::hypothesis_graph::TaskTerminalOutboxEntry::new` rejects a challenge without its target edge or
hypothesis and evidence/decision lineage, rejects a falsification without its
target hypothesis and decision/evidence lineage, and rejects any producer key
different from the claimant key. It also requires a memory expiry envelope when
memory is present, rejects a dangling envelope or digest/time/signature mismatch,
and rejects an expiry envelope without memory. Tests cover success, stale/fenced completion,
wrong kind, claimant-key substitution, duplicate logical task versus retry
idempotency, and publication atomicity after a forced CAS failure.
