Plan 04 owns the runtime-neutral containment input and pure planner operation;
it must not import the later service module or own its result adapter. The

Durable hypothesis and decision state is not a process-local coordinator map.
Plan 04 extends `GraphStoreState` with a signed/CAS/fenced
`hypotheses: BTreeMap<HypothesisId, Hypothesis>` field; each `Hypothesis` owns
its append-only `decision_history: Vec<DecisionRecord>`. `GraphStoreState.graph`
remains the source of truth for evidence, nodes, causal edges, contradictions,
and conflicts, while `GraphStoreState.tasks` remains only the durable task
ledger and `GraphStoreState.terminal_outbox` is the typed atomic publication
boundary. Every hypothesis/edge/decision/task-terminal mutation is committed
through one graph-store transition and revalidated on reload; runtime projections use
`GraphStoreSnapshot::hypotheses() -> &BTreeMap<HypothesisId, Hypothesis>` and
`GraphStoreSnapshot::decision_history() -> impl Iterator<Item = &DecisionRecord>`
in deterministic hypothesis/sequence order, never a second in-memory
hypothesis/decision store. The durable `GraphStoreState` also owns
`limits: GraphResourceLimits`, bounded cross-graph links, a schema migration
marker, and the last `GraphInvestigationResult`/operator projection digest;
`GraphStoreSnapshot` exposes those typed projections without copying a second
store. Every CAS commit carries and preserves `logical_time_high_water:
GraphLogicalTime`; a stale logical time, generation, predecessor, fence, or
signature is rejected and cannot lower that high-water mark. The exact
existing Plan 03 public seam is
`swarm_spine::hypothesis_graph_store::HypothesisGraphStore::snapshot()` plus
`HypothesisGraphStore::compare_and_swap(&GraphStoreRevision, GraphStoreState)`;
Plan 04 owns only the reasoning-state extension and its adapter, while Plan 03
owns the backend protocol. No `GraphStore` alias, `load_snapshot`, or `commit`
facade may be added. The Plan 04 compile contract must call the exact existing
methods and prove that the coordinator receives the same `GraphStoreSnapshot`
after the adapter CAS.

Normalized telemetry never emits support/refute assignments. Plan 04 therefore
publishes an explicit neutral seed contract rather than guessing from payloads:
`HypothesisSeedInput { graph_id, candidate_hypothesis_ids,
assessments: Vec<HypothesisSeedAssessment>, logical_time }`, where each
`HypothesisSeedAssessment { hypothesis_id, evidence_ids, disposition,
provenance }` must carry a closed `HypothesisDisposition` of
`Supports`, `Refutes`, `Unresolved`, or `Contradicts`. The only adapter from a
plain normalized envelope creates `Unresolved`; support/refute/contradiction
must be supplied explicitly by a signed role assessment or fixture truth. An
empty/ambiguous seed becomes an evidence-acquisition task, never a heuristic
classification.
</ownership_boundary>

The durable state and store seam are also explicit, rather than an
implementation-detail promise. Plan 03's existing state schema remains
`GRAPH_STORE_SCHEMA_VERSION = 1`; the reasoning extension uses a separate
closed migration marker so old signed graph/task records can be upgraded
without pretending that a new schema byte was already persisted:

```rust
pub const GRAPH_STATE_MIGRATION_LEGACY: u32 = 0;
pub const GRAPH_STATE_MIGRATION_HYPOTHESES: u32 = 1;

}
```

Deserialization defaults a missing marker to `LEGACY` (`0`) so a Plan 03
record is never silently labeled current. `GraphStoreState::with_reasoning_state`
must run the exact `LEGACY -> HYPOTHESES` transformation: add empty bounded
`hypotheses`, cross-links, decision/projection maps, terminal outbox, and current marker while
preserving graph/tasks/tombstones/fencing/high-water and the signed predecessor.
Markers above `CURRENT` or a transformed record with mismatched graph ID,
limits, digest, or signer are rejected. The migration test names are
`legacy_graph_state_migrates_v0_to_v1_preserving_logical_time_high_water` and
`unknown_graph_state_migration_marker_is_rejected`; both run against memory
and reopened file stores.

`GraphStoreState::with_reasoning_state` validates the hypothesis/decision, task, terminal-outbox, cross-link,
projection, limit, and migration bounds before admission.
`HypothesisGraphStore::compare_and_swap` requires the existing
`GraphStoreRevision` generation and predecessor digest, verifies every edge
and decision through the injected Plan 02 `GraphRecordSigner`, and rejects a
stale logical time or fencing token. A successful CAS sets
`logical_time_high_water = max(previous_high_water, logical_time)` and a
reopen/replay can never lower it. `GraphStoreSnapshot` exposes the exact
`hypotheses`, each hypothesis's append-only `decision_history`, the task
ledger, limits/cross-links/migration marker, and result/operator projection
digests; no coordinator-local mirror is permitted. The tuple cross-link is a
bounded, capability-neutral reference only and is not an authority or a
cross-graph mutation channel.

`accept_terminal_once` validates the admitted task, key-bound capability proof,
lease/fence, claimant-scoped `IdempotencyKey`, task/completion-kind mapping, and
full `TaskDecisionLink` before constructing one next `GraphStoreState`. It performs
exactly one `HypothesisGraphStore::compare_and_swap` containing the terminal
task record and its evidence, decision, and optional memory in
`terminal_outbox`; when memory is present its signed
`StrategyMemoryExpiryEnvelope` is stored in the same entry and checked against
the injected logical time. Publication is drained only after that CAS succeeds. A stale
lease, failed validation, duplicate terminal, wrong producer key, or CAS conflict
returns without changing tasks, hypotheses, decisions, memory, or outbox. The
accepted terminal result therefore cannot publish partial evidence or memory.
`TaskTerminalOutboxEntry::new` rejects a challenge without its target edge or
hypothesis and evidence/decision lineage, rejects a falsification without its
target hypothesis and decision/evidence lineage, and rejects any producer key
different from the claimant key. It also requires a memory expiry envelope when
memory is present, rejects a dangling envelope or digest/time/signature mismatch,
and rejects an expiry envelope without memory. Tests cover success, stale/fenced completion,
wrong kind, claimant-key substitution, duplicate logical task versus retry
idempotency, and publication atomicity after a forced CAS failure.
