The bridge invokes the service-layer result adapter; “bridge-owned” in the
one-shot behavior below describes invocation ownership only. The public
`ContainmentPlanner::simulate(&GraphInvestigationResult)` symbol and its
implementation remain Plan 06 service symbols, while Plan 04 owns only
`ContainmentPlanner::simulate_input`.

The handoff is a single typed capture, not three independent projections:
`Phase286StrategyBridge::investigate_once(replay)` invokes the injected
`HypothesisGraphCoordinator` once, receives one `GraphInvestigationResult`
(including its durable `hypotheses` map), converts that same result once to
the existing `InvestigationOutcome` and typed `InvestigationDecision`, and
passes that same result once to `ContainmentPlanner::simulate`. The returned
`Phase286InvestigationCapture` retains all four values plus the source replay
and event-local invocation receipt. The configured stack moves this capture
directly into its `Phase286StackResult::Actionable` handoff; neither the stack
nor Arena may re-run the coordinator, reconstruct a result, or call the
planner independently.

The exact public `GraphInvestigationStrategy` contract is
`{ strategy_id: String, detector_profile_digest: String,
graph_policy_mode: swarm_core::hypothesis_graph::GraphPolicyMode,
graph_policy_digest: String, memory_digest: Option<String> }`. Its constructor
is `GraphInvestigationStrategy::new(strategy_id, detector_profile_digest,
graph_policy_digest, graph_policy_mode, memory_digest)`. The mode is not a
decorative digest input: `EvidenceFirst` requires evidence coverage before
convergence, `ChallengeContradictions` schedules challenge/falsification and
retains alternatives, and `ConservativeContainment` filters to reversible,
bounded-blast-radius simulations after policy/evidence checks. Canonical
policy bytes include the closed mode and are used to recompute
`graph_policy_digest`; a mode mutation must change graph task/convergence or
containment behavior, while a digest-only mutation is rejected.

`GraphInvestigationInput` carries normalized `seed_evidence` plus an explicit
`seed_assessments: Vec<HypothesisSeedAssessment>` from Plan 04. The closed
disposition is `Supports`, `Refutes`, `Unresolved`, or `Contradicts`; ordinary
normalizers populate only `Unresolved`, so no runtime layer may infer
support/refute semantics from a payload.

`RuntimeService::process_event_with_store_and_finding_observer_without_investigation`
returns `Result<FindingReplayOutcome, ServiceError>` with the exact detector,
substrate, store, event, execution, `Fn(&DetectionFinding) ->
Option<swarm_core::types::ResponseAction>`, and observer arguments frozen by
Plan 06B. The helper performs no policy, response, receipt, dispatcher, or
generic-investigation call. The graph-enabled stack maps `NoFinding`, `NoAction`,
and `Actionable` to the corresponding `Phase286StackResult`; only Actionable

The capture counters are event-local deltas, never bridge-lifetime counters:
`investigate_once` reads `coordinator_before`/`planner_before` immediately
before the calls and `coordinator_after`/`planner_after` immediately after,
then stores `coordinator_invocations = coordinator_after -
coordinator_before` and `planner_invocations = planner_after -
planner_before` in the capture's event-local invocation receipt. The handoff
oracle asserts those deltas are one for the current replay and zero for
no-finding/no-action paths; it never resets shared counters or infers an event
count from bridge construction.
