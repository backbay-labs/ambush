The bridge invokes the service-layer result adapter; “bridge-owned” in the
one-shot behavior below describes invocation ownership only. The public
`ContainmentPlanner::simulate(&GraphInvestigationResult)` symbol and its
implementation remain Plan 06 service symbols, while Plan 04 owns only
`ContainmentPlanner::simulate_input`.

The handoff is a single typed capture, not three independent projections:
`Phase286StrategyBridge::investigate_once(replay)` invokes the injected
`HypothesisGraphCoordinator` once, receives one `GraphInvestigationResult`
(including its durable `hypotheses` map), converts that same result once to
the existing `InvestigationOutcome` and typed `InvestigationDecision`, and
passes that same result once to `ContainmentPlanner::simulate`. The returned
`Phase286InvestigationCapture` retains all four values plus the source replay
and event-local invocation receipt. The configured graph stack submits the
replay exactly once through the existing investigation coordinator, waits for
the worker's persisted terminal record and bundle-ID capture, and then moves
that capture into its `Phase286StackResult::Actionable` handoff; neither the
stack nor Arena may re-run the coordinator, reconstruct a result, or call the
planner independently.

The exact public `GraphInvestigationStrategy` contract is
`{ strategy_id: String, detector_profile_digest: String,
graph_policy_mode: swarm_core::hypothesis_graph::GraphPolicyMode,
graph_policy_digest: String, memory_digest: Option<String> }`. Its constructor
is `GraphInvestigationStrategy::new(strategy_id, detector_profile_digest,
graph_policy_digest, graph_policy_mode, memory_digest)`. The mode is not a
decorative digest input: `EvidenceFirst` requires evidence coverage before
convergence, `ChallengeContradictions` schedules challenge/falsification and
retains alternatives, and `ConservativeContainment` filters to reversible,
bounded-blast-radius simulations after policy/evidence checks. Canonical
policy bytes include the closed mode and are used to recompute
`graph_policy_digest`; a mode mutation must change graph task/convergence or
containment behavior, while a digest-only mutation is rejected.

`GraphInvestigationInput` carries normalized `seed_evidence` plus an explicit
`seed_assessments: Vec<HypothesisSeedAssessment>` from Plan 04. The closed
disposition is `Supports`, `Refutes`, `Unresolved`, or `Contradicts`; ordinary
normalizers populate only `Unresolved`, so no runtime layer may infer
support/refute semantics from a payload.

`RuntimeService::process_event_with_store_and_finding_observer_without_investigation`
returns `Result<FindingReplayOutcome, ServiceError>` with the exact detector,
substrate, store, event, execution, `Fn(&DetectionFinding) ->
Option<swarm_core::types::ResponseAction>`, and observer arguments frozen by
Plan 06B. The helper performs no policy, response, receipt, dispatcher, or
generic-investigation call. The graph-enabled stack maps `NoFinding`, `NoAction`,

The capture counters are event-local deltas, never bridge-lifetime counters:
`investigate_once` reads `coordinator_before`/`planner_before` immediately
before the calls and `coordinator_after`/`planner_after` immediately after,
then stores `coordinator_invocations = coordinator_after -
coordinator_before` and `planner_invocations = planner_after -
planner_before` in the capture's event-local invocation receipt. The handoff
oracle asserts those deltas are one for the current replay and zero for
no-finding/no-action paths; it never resets shared counters or infers an event
count from bridge construction.

<authority_composition>
The policy/governance objects are not reconstructed in the graph service. The
real Pouncer, Tom, operator approval harness, and dispatcher are composed by
`swarm-ingest-runtime::ingest::mod` and are not imported by `swarm-runtime`
(the normal dependency direction is ingest -> runtime; reversing it would form
a crate cycle). Plan 06 therefore owns the smallest runtime-side injection
contract in `crates/swarm-runtime/src/service/graph_authority.rs`:

```rust
#[async_trait]
pub trait GraphAuthorityHandoff: Send + Sync {
    async fn rehearse_selected_simulation(
        &self,
        binding: BoundContainmentRequest,
        finding: &swarm_whisker::DetectionFinding,
        context: &swarm_policy::ApprovalContext,
    ) -> Result<DryRunTraversalReceipt, swarm_runtime::RuntimeError>;
}
```

`BoundContainmentRequest` contains the exact `ActionRequest` value together
with the selected `ContainmentOption`; it is constructed only after the
service finds that option by its content-derived `option_id`, recomputes the
simulation/option digest, and verifies that the exact request action and
target graph-node IDs are the declared mapping for that option.
The mapping is closed and explicit (for example, an `IsolateAsset` option may
bind only an `IsolateHost` request whose `host_id` is the admitted asset-node
identity); a missing or ambiguous mapping is refused. The request digest,
simulation digest, graph ID, option ID, and target-node set are signed into the
binding. A caller cannot select an option with an unrelated `ActionRequest`,
and the adapter never invents a target or identifier.

`RuntimeService::rehearse_selected_simulation` accepts only this bound value
and an injected `Arc<dyn GraphAuthorityHandoff>` with the exact async
signature `(&self, binding: BoundContainmentRequest,
finding: &swarm_whisker::DetectionFinding,
context: &swarm_policy::ApprovalContext) ->
Result<DryRunTraversalReceipt, swarm_runtime::RuntimeError>`. It performs
structural and digest checks, then delegates; it never imports Pouncer/Tom/dispatcher, creates
an approval/receipt/admission ID, mints a lease, or calls a response executor.
The ingest adapter is the only implementation used in the end-to-end test. It
is composed from the existing `RequestResponseRouter`, `GovernanceAuthority`,
`DefaultApprovalHarness`, and dispatcher admission path already owned by
`swarm-ingest-runtime::ingest`; it does not import ingest into runtime or make
runtime depend on its composition root. That adapter invokes the actual
Pouncer-issued request, Tom/governance decision, persisted operator approval
route, request-bound receipt, and dispatcher admission in that order, and
copies only IDs/authenticated artifacts returned by those stages into the
receipt. Any missing stage, ID mismatch, stale approval, or non-simulated
response fails closed before the response adapter. Test doubles are limited to
recording the real typed stage interfaces; they may not supply synthetic IDs or
a caller boolean claiming that a stage ran.

The graph store signer and graph record signer are one trusted identity
binding, not two configurable labels. The ingest graph builder derives the
`GraphStoreSigner` identity from the concrete `HypothesisGraphStore` signer
and the record signer identity from the admitted `KeypairGraphRecordSigner`
public key, then passes a `GraphSignerBinding` containing both derived
identities and the snapshotted `WitnessAdmission`. Construction rejects any
mismatch or unadmitted key before a coordinator/store is created. Every
coordinator snapshot/CAS re-verifies the store signature and every edge/decision
uses the same admitted `GraphRecordSigner`; a swapped signer, scoped alias, or
reopened store with another key is rejected before mutation. No graph signer
identity is accepted from a request, route, or arbitrary string.
</authority_composition>
