<interfaces>
The corrective pass preserves the existing public names and signatures. The
admission contract is the existing `WitnessAdmission` base-identity set,
`KeypairGraphRecordSigner::with_admission(key, &admission) ->
Result<KeypairGraphRecordSigner, GraphAdmissionError>`, and
`GraphRecordSigner: Send + Sync` with its existing `sign_edge`, `sign_decision`,
`verify_edge`, and `verify_decision` methods. `EvidenceRegistry::admit` and
`EvidenceRegistry::admit_into_graph` must reject an `EvidenceWitness` whose
key-derived `AgentId` is absent from that snapshotted allowlist before any
graph/store mutation. Scoped role labels never substitute for a base key;
allowlist mutation after signer construction cannot grant capability.

Normalization must continue to call the core
`EventNode::new(event_kind, source_record_id, observed_at)` API with the stable
source evidence record identity. The follow-up tests must prove distinct
source-record IDs at one kind/time produce distinct node IDs and exact retries
are idempotent. Reuse Plan 02's single CloudTrail path and preserve its
existing event-scoped unknown-principal/account and lower-priority identity
digest regression; do not create a second CloudTrail adapter or duplicate
ownership of that fix.

The scheduler contract is the existing
`DeterministicScheduler::pop_ready(now: GraphLogicalTime) ->
Result<Option<GraphSchedulerKey>, GraphAdmissionError>`. It may remove a key
only when `key.ready_at <= now`; a future key must remain in `ordered()`,
`contains()`, and canonical scheduler state byte-for-byte. It uses the core
`GraphLogicalTime` and `GraphSchedulerKey`; no runtime replacement types or
host-clock ordering are allowed.

`EvidenceWitness` role/scope fields are trusted only when they are included in
the signed canonical binding and the key-derived identity is admitted. An
unsigned/default witness is explicitly untrusted and may be retained only as
pre-admission input; it cannot pass `EvidenceRegistry` or graph admission.

The existing convenience `KeypairGraphRecordSigner::new(key)` and
`EvidenceRegistry::witness_admission_mut()` are residual hardening hazards.
Either remove/deprecate them or make their unadmitted state incapable of
signing/admitting; the acceptance test must prove that `new` cannot sign and
that changing a caller-owned allowlist after registry construction cannot grant
capability. `EvidenceRegistry` owns a snapshot for every admission decision.
</interfaces>
