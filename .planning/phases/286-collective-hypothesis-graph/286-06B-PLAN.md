<objective>
Freeze the executable handoff between the Phase 286 graph bridge and the
existing runtime stack. The arena must consume one captured graph result rather
than re-running investigation while it builds a containment simulation.
</objective>

<legacy_worker_suppression>
When `SwarmConfig.hypothesis_graph.enabled` is true, the configured graph stack
constructs the existing concrete
`InvestigationCoordinator<Phase286StrategyBridge, ConfiguredInvestigationBundleStore>`
with the configured worker count, scheduler, queue budget, and time budget. An
actionable replay enters the real `submit(&ReplayBundle)` path exactly once;
the concrete worker invokes `Phase286StrategyBridge::investigate` exactly once,
which records the one graph capture that the stack later returns. The graph
branch never constructs `SummaryInvestigator`, a generic placeholder strategy,
or a second queue. The disabled graph path retains the existing
`InvestigationCoordinator<SummaryInvestigator, _>` behavior unchanged. Tests
assert the real queue snapshot (`worker_count`, queued/running/completed
counts), the persisted investigation record, and the bridge capture lineage;
they do not use an invented worker-spawn or submit spy in place of the runtime.
</legacy_worker_suppression>

Plan 06 owns the public `Phase286StrategyBridge` with private fields and the
constructor `Phase286StrategyBridge::new(coordinator, planner, graph_id, clock,
strategy, learned_state_digest) -> Self`. It also owns
`Phase286InvestigationCapture` and the public
`bridge.investigate_once(replay: &swarm_spine::ReplayBundle) ->
Result<Phase286InvestigationCapture, String>`. The concrete coordinator worker
calls the bridge's `InvestigationStrategy::investigate` implementation, which
delegates to `investigate_once` and stores the resulting capture in a bounded,
bundle-ID keyed handoff buffer. The stack retrieves that exact capture only
after the existing worker has persisted a terminal investigation record; it
never calls the bridge directly from the stack. The capture contains the source
`ReplayBundle`, one `GraphInvestigationResult`, the existing
`swarm_runtime::investigation::InvestigationOutcome`, the typed
`swarm_spine::InvestigationDecision`, one core-owned
`ContainmentSimulation`, and the coordinator/planner invocation counters.

The captured `GraphInvestigationResult` publicly includes the durable
`hypotheses: BTreeMap<HypothesisId, Hypothesis>` alongside graph, tasks,
kill-chain, memory, strategy, observed logical time, and graph digest. Its
constructor takes that map explicitly; `into_investigation_outcome` and
`to_investigation_decision` project the same evidence-linked claims and never
reconstruct a second investigation. The coordinator is constructed with the
injected `Arc<dyn swarm_spine::hypothesis_graph_store::HypothesisGraphStore>` and the
admitted `Arc<dyn GraphRecordSigner>` in addition to graph ID, limits,
`Arc<dyn GraphClock>`, and `Arc<dyn InvestigationStrategyAdapter>`.

The bridge has the existing runtime trait implementation, not a new strategy
type:
```rust
#[async_trait]
impl swarm_runtime::investigation::InvestigationStrategy for Phase286StrategyBridge
where
    Phase286StrategyBridge: Clone + Send + Sync + 'static,
{
    fn id(&self) -> &str;
    async fn investigate(
        &self,
        replay: &swarm_spine::ReplayBundle,
    ) -> Result<swarm_runtime::investigation::InvestigationOutcome, String>;
}
```
Its body calls `input_from_replay`, invokes the coordinator exactly once,
converts the single result to the existing `InvestigationOutcome` and typed
`InvestigationDecision`, and uses the one-shot capture/planner path. It never
constructs or falls back to `SummaryInvestigator`; the configured-stack compile
contract proves this exact concrete strategy is installed.

The bridge's bounded handoff buffer is not a second graph/task store or an
authority cache. It retains at most the configured pending-worker count,
requires the source replay bundle ID, and removes a capture only after the
stack has matched its persisted terminal investigation record and graph
digest. A missing, duplicate, mismatched, or expired capture is a hard error.

Those counters are per-event deltas, not bridge-construction resets or
bridge-lifetime totals. The worker's `investigate_once` records
`coordinator_before`/`planner_before` and `coordinator_after`/`planner_after`
around the current replay, stores the subtraction in an event-local
`Phase286InvocationReceipt`, and the handoff oracle checks the current event's
delta. A second event is checked independently; no test may reset counters to
make a cumulative count appear to be one.

`request_builder` is called exactly once for each detector finding. If the
critical path produces no finding, the method returns
`Ok(Phase286StackResult::NoFinding)` and does not invoke the bridge or planner.
If a finding has no action, it returns
`Ok(Phase286StackResult::NoAction(NoActionFindingReplay))`, retains normalized
evidence, and makes zero policy/response/receipt/dispatcher/adapter calls. If a
finding produces a persisted replay, the method returns
`Ok(Phase286StackResult::Actionable(capture))`: investigation is mandatory for
that replay, the existing coordinator `submit` method is called exactly once,
the concrete worker invokes the bridge exactly once, and the returned capture
is the only source for the existing outcome, decision, and containment
simulation. The specialized method does not call
`process_event_with_finding_observer`, does not construct a second queue, and
does not invoke the coordinator/planner outside the worker path.
`Phase286StackResult` makes the no-finding and no-action cases explicit; no
optional action is smuggled into a mandatory replay.

The compile contract also constructs the mode-bearing strategy. The exact
`GraphInvestigationStrategy` fields are `strategy_id: String`,
`detector_profile_digest: String`,
`graph_policy_mode: swarm_core::hypothesis_graph::GraphPolicyMode`,
`graph_policy_digest: String`, and `memory_digest: Option<String>`, with
constructor `new(strategy_id, detector_profile_digest, graph_policy_digest,
graph_policy_mode, memory_digest)`. The closed mode maps to evidence-first
convergence, contradiction challenge/falsification, or conservative reversible
containment as specified by Plan 06. The compile/behavior contract mutates the
mode and requires a changed typed graph task/convergence/simulation, rejecting
a digest-only change.
