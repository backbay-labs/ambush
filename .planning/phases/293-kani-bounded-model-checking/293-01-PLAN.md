# Phase 293 — Kani Bounded Model Checking

**Status:** implementation plan, 2026-09-08. Executed with subagent-driven-development. Branch
`feat/kani-293` off `main` `1b8809279` (Phase 292 pure decision core complete). Second v1.81
Machine-Checked Decision Core phase — it turns the IO-free `swarm-policy::formal_core` surface that
292 carved out into machine-checked proofs that run in CI.

**Goal (ROADMAP.md).** Catch regressions in fail-closed behavior, blast-radius conservation, and
lease-forgery rejection in CI rather than in an incident — by proving, with the Kani bounded model
checker, that the real pure decision functions in `formal_core.rs` hold their safety properties for
every input in a bounded domain.

**Requirements, verbatim (REQUIREMENTS.md:919–923).**
- **KANI-01**: An optional `kani` feature and `crates/swarm-policy/src/kani_public_harnesses.rs` hold
  `#[kani::proof]` functions calling the real `pub fn`s from `formal_core.rs`.
- **KANI-02**: Harnesses prove fail-closed evaluation, severity-gate soundness, and rate-limit
  boundedness within a 60,000ms trailing window.
- **KANI-03**: Harnesses prove lease integrity: invalid signature, non-approve decision, and
  hash-mismatched proposal always deny; redemption never exceeds `blast_radius_cap`; expiry always
  denies. Model-only harnesses are labeled `MODEL-ONLY`.
- **KANI-04**: `formal/kani/swarm-policy-harnesses.toml` enumerates every harness; a unit test fails
  the build if a `#[kani::proof]` function is missing from the manifest.
- **KANI-05**: `scripts/run-kani-swarm-policy.sh` runs every PR-lane harness in CI.

**Success criteria (ROADMAP.md).** (1) At least **8** `#[kani::proof]` harnesses call the real public
functions from `formal_core.rs`; (2) every harness that models an abstraction rather than the literal
production symbol is labeled `MODEL-ONLY`, naming the runtime test that provides complementary
coverage; (3) a manifest lists every harness, and a unit test fails the build when a harness is
missing from it; (4) the PR-lane runner completes within configured timeouts and is wired into CI.

## Design of record (controller rulings, 2026-09-08; re-verify at HEAD)

- **KANI-01 gating — `#[cfg(kani)]` is load-bearing; the `kani` feature is the requirement's literal
  ask.** The harness module must NOT enter the shipped dependency graph or the normal build. The
  canonical, correct mechanism is `#[cfg(kani)]` on `mod kani_public_harnesses` (Kani sets `--cfg
  kani` when it runs; the normal build never compiles it, and NO `kani` crate is added to normal
  `[dependencies]`). To also satisfy KANI-01's literal "optional `kani` feature", declare
  `[features] kani = []` in `crates/swarm-policy/Cargo.toml` and gate the module on
  `#[cfg(any(kani, feature = "kani"))]`. The `#[kani::proof]`/`kani::any()`/`kani::assume()` bodies
  resolve only under the real Kani cfg — that is expected. **Hard constraints the implementer must
  verify: (a) a normal `cargo build -p swarm-policy` and `cargo test -p swarm-policy` are byte-for-
  behaviour unchanged (harnesses absent, no new normal dependency — `cargo tree -p swarm-policy` and
  the DCORE-03 boundary gate stay clean); (b) `cargo kani --harness <NAME>` actually PROVES each
  harness; (c) the KANI-04 manifest unit test runs in the NORMAL `cargo test` lane (it is a plain
  `#[cfg(test)]` test that reads files, NOT behind the kani gate).** Choose the exact cfg wiring that
  satisfies all three against the real toolchain; do not weaken (a).
- **KANI-03 REAL vs MODEL-ONLY split — dictated by the 292 TCB boundary.** `formal_core`
  deliberately excludes the cryptographic `ConsensusGovernanceReceipt` (it lives in `swarm-consensus`,
  above `swarm-policy`); the pure lease predicates decide on scope/expiry/blast-radius over plain
  values. Therefore:
  - **REAL harnesses (call the literal `formal_core` fn):** redemption never exceeds
    `blast_radius_cap` (over `lease_redeem`/`lease_can_redeem`); expiry always denies (`now_ms >`
    expiry ⇒ deny); `validate_lease_terms` rejects malformed terms; the rate-limit and severity
    properties in KANI-02.
  - **MODEL-ONLY harnesses (label `MODEL-ONLY`, name the complementary runtime test):** "invalid
    signature always denies", "non-approve decision always denies", "hash-mismatched proposal always
    denies" — these are properties of the receipt/decision that `formal_core` does not see. Model the
    guard as an abstract boolean and prove the deny logic; the `MODEL-ONLY` comment MUST name the
    swarm-agents runtime test (`tom_agent`/`governance`) that verifies the real crypto. Do NOT fake a
    `formal_core` signature check that does not exist.
- **Bounded proofs.** `evaluate_rate_limit` prunes a `VecDeque` in a `while` loop; Kani needs a finite
  unwind. Harnesses bound the domain (e.g. `kani::assume(window.len() <= N)` for a small `N`, and
  bound `now_ms`/timestamps to a small symbolic range) so proofs terminate within the PR-lane timeout.
  State the bound in each harness and in the manifest; a bounded proof is still a proof over its
  bounded domain — that is the point of KANI, not a weakness, but the bound must be honest and named.
- **PR-lane vs nightly.** SC4 requires the PR-lane runner to finish within timeouts. Classify each
  harness `pr` or `nightly` in the manifest; `scripts/run-kani-swarm-policy.sh` runs the `pr` set
  (fast, tightly bounded) and the CI job runs that script. A heavier/looser-bound harness may be
  `nightly`. Every harness (both lanes) still counts toward the ≥8 and the manifest.
- **CI wiring (KANI-05).** Add a CI job that installs Kani (`cargo install --locked kani-verifier`
  then `cargo kani setup`, or the `model-checking/kani-github-action`) and runs
  `scripts/run-kani-swarm-policy.sh`. Keep it a real `run:` step. It is engine-lane work, so place it
  behind the same `needs.changes.outputs.engine == 'true'` path gate the other engine jobs use.

## Global constraints

Rust 1.97.1 for the normal build; Kani 0.67.0 for proofs. `cargo fmt --all`; `cargo clippy
--workspace --all-targets -- -D warnings` (the harness module is `#[cfg(kani)]`, so clippy on the
normal build does not see it — run `cargo clippy` as usual; do not disable lints crate-wide to
accommodate harnesses). The existing `tools/check-*.sh` gates stay green — in particular
**`tools/check-decision-core-boundary.sh` and `tools/check-workspace-layering.sh` must stay 0**: the
`kani` feature must add NO forbidden or non-TCB dependency to `swarm-policy`'s normal graph.
`unwrap_used`/`expect_used` remain denied outside tests; harness code under `#[cfg(kani)]` may use
Kani's asserts but should avoid `unwrap` on symbolic values unless the surrounding `assume` makes it
total. **No change to any `formal_core` verdict or signature** — 293 PROVES the 292 surface, it does
not modify it; if a proof reveals a real bug, STOP and surface it (that is a finding, not a silent
fix). No pre-existing test assertion changes. **Resource discipline (critical):** Kani proofs are
CPU/time heavy — run **one harness at a time** (`cargo kani --harness <NAME>`), foreground, NEVER
concurrent, NEVER a bare `cargo kani` that runs all harnesses at once during development; scoped
`cargo test -p swarm-policy` for the manifest test. Tests `a_thing_does_x_when_y`; commits `git
commit -s`, Conventional Commits, with the standard `Co-Authored-By` + `Claude-Session` trailers.

**Pre-flight.** Sequential pipeline T1→T5 (T2 builds on T1's scaffolding; T3's manifest+test needs the
T1+T2 harness set; T4 runs them; T5 closes). Review each task; a whole-branch review before merge.
Because Kani execution is slow, the reviewer VERIFIES a representative subset of harnesses rather than
re-running all of them, and confirms the manifest test + normal-build-unaffected constraints in full.

### Task 1: Kani scaffolding + rate-limit and severity/fail-closed harnesses (KANI-01, KANI-02)

**Files.** `crates/swarm-policy/Cargo.toml` (`[features] kani = []`); `crates/swarm-policy/src/lib.rs`
(gated `mod kani_public_harnesses`); `crates/swarm-policy/src/kani_public_harnesses.rs` (new).

**Behaviour.** Stand up the `#[cfg(any(kani, feature = "kani"))]` harness module calling the real
`formal_core` `pub fn`s, and author the KANI-02 harnesses:
- **rate-limit boundedness:** for a symbolic window (bounded length) + symbolic `now_ms` + symbolic
  `limit`, prove `evaluate_rate_limit` returns `Denied` when the pruned window is already at `limit`,
  returns `Allowed` otherwise, and the returned window never exceeds `limit` after an `Allowed`, and
  every retained timestamp is within the 60,000ms trailing window (the `RATE_LIMIT_WINDOW_MS`
  boundary). (≥2 harnesses.)
- **severity-gate soundness / fail-closed:** prove `severity_floor_denial` denies every destructive
  action at `Severity::Low` under `static.minimum_severity`, and every `DeployDecoy` at `Low` under
  `static.deploy_decoy_min_severity`; prove `human_gate_decision` returns `RequireHuman` for every
  destructive action at-or-above the gate severity and `None` below it. (≥2 harnesses.)

**Verification.** Each harness PROVES via `cargo kani --harness <NAME>` (run individually,
foreground). Normal `cargo build -p swarm-policy` + `cargo test -p swarm-policy` unchanged; `cargo
tree -p swarm-policy` + `tools/check-decision-core-boundary.sh` + `tools/check-workspace-layering.sh`
all still 0 (the `kani` feature adds no normal dep). fmt/clippy clean.

### Task 2: Lease-integrity harnesses — real + MODEL-ONLY (KANI-03)

**Files.** `crates/swarm-policy/src/kani_public_harnesses.rs` (extend).

**Behaviour.** Author the KANI-03 harnesses over the real lease predicates and the MODEL-ONLY

- **REAL:** redemption never exceeds `blast_radius_cap` (a successful `lease_redeem` never authorizes

  runtime test that covers the real cryptographic check. (≥3 harnesses.)

Total across T1+T2 ≥ 8 real-fn-calling harnesses (the MODEL-ONLY ones still call a real `formal_core`
deny path where possible; where they cannot, they are explicitly MODEL-ONLY).
