# Phase 3 Plan 01: Policy Gate Hardening

<objective>
Expand the policy layer so it can deny, authorize, or require human approval with explicit capability leases.
</objective>

<read_first>
- .planning/phases/03-safe-live-response/03-CONTEXT.md
- .planning/REQUIREMENTS.md
- crates/swarm-policy/src/lib.rs
- crates/swarm-policy/src/static_gate.rs
- crates/swarm-runtime/src/lib.rs
</read_first>

<tasks>
<task number="1" type="auto">
<description>Replace boolean-heavy policy outcomes with an explicit decision model.</description>
<acceptance_criteria>
- Policy can represent deny, authorize, and human-required outcomes explicitly.
- Runtime code no longer has to infer intent from a pair of booleans.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Add denial rules for malformed, weak, or out-of-mode requests and harden capability lease issuance.</description>
<acceptance_criteria>
- Malformed evidence or invalid request targets can be denied deterministically.
- Capability leases carry scope and expiration information that tests validate.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add policy-focused tests covering deny, authorize, and human-gated paths.</description>
<acceptance_criteria>
- Tests prove all three decision outcomes.
- Runtime-facing tests exercise the policy contract rather than adapter internals.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-policy -p swarm-runtime
</verification>

<success_criteria>
- Policy outcomes are explicit and deterministic.
- Lease issuance is scoped and test-covered.
</success_criteria>
