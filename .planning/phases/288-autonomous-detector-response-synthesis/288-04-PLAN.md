<interfaces>
The Arena test harness must run each lane by calling
`BlueRuntimeAdapter::run(&self, campaign: &Campaign,
learned_state: &SignedBlueLearnedState, target: &FixtureTarget,
partition: PartitionKind, clock: &mut VirtualArenaClock)` twice: once with the admitted candidate
state and once with `SignedBlueLearnedState::empty_frozen()`. Each run must
cross `FixtureTarget::normalize_event` and
`IngestState::process_bridge_event_at` with Phase 287's six-argument
`ConfiguredRuntimeStack::from_graph_components(config, policy, response, bridge,
authority, signer_binding)` and produce `BlueOutcome` from
`ArenaIngestResult`/`Phase286InvestigationCapture`. The Arena side also records
`ArenaArtifactStore` evidence and the exact concrete `PairReport` from
`Evaluator::compare_learning_and_single_agent(ControlInput)`. Arena then uses
the sole `Phase287ArenaSynthesisAdapter` to emit the Runtime-owned
`PairReportView` and `ArenaArtifactView` inside one canonical
`ArenaSynthesisInput`; Runtime scoring consumes those views only. No
generic/default replay fixture, direct detector call, copied fixture bytes, or
Red projection may stand in for this bridge. The Phase 287 common-pair digest
intentionally excludes both learned-state digests; the concrete `PairReport`
records the candidate and `empty_frozen()` state digests separately and rejects
equal states or a learning difference that changes only event IDs. Evaluation
uses only the four admitted Phase 287 learned families; the six additional
typed-genome families are factory-only and are rejected before Blue admission.
</interfaces>
