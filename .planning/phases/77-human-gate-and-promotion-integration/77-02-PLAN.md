  <action>
Add quorum validation and cryptographic verification to `promotion.rs`:

1. **Add quorum gate configuration type:**
   ```rust
   /// Structural quorum-gate configuration for the promotion path.
   /// Advisory-only when threshold is None (activates with trust boundaries).
   #[derive(Debug, Clone, Serialize, Deserialize)]
   pub struct PromotionQuorumGateConfig {
       pub required_threshold: Option<usize>,
       pub required_voter_ids: Vec<String>,
   }

   impl Default for PromotionQuorumGateConfig {
       fn default() -> Self {
           Self { required_threshold: None, required_voter_ids: Vec::new() }
       }
   }
   ```

2. **Add `validate_quorum_gate()` function:**
   ```rust
   pub fn validate_quorum_gate(
       votes: &[PromotionApprovalVoteRef],
       config: &PromotionQuorumGateConfig,
   ) -> Result<(), ProductionPromotionError>
   ```
   - If `config.required_threshold` is None, return Ok (advisory pass-through -- no quorum configured yet).
   - If threshold is Some(n), verify `votes.len() >= n`.
   - If `config.required_voter_ids` is non-empty, verify every required voter ID appears in the vote list.
   - On failure, return a new `QuorumNotMet` error variant:
     ```rust
     #[error("quorum not met: {have} of {need} votes, missing voters: {missing}")]
     QuorumNotMet { have: usize, need: usize, missing: String },
     ```

3. **Add `verify_vote_signature()` function:**
   ```rust
   pub fn verify_vote_signature(
       vote: &PromotionApprovalVoteRef,
       promotion_id: &str,
   ) -> bool
   ```
   - Reconstruct the canonical signing payload: `canonical_json_bytes` of a struct containing `promotion_id`, `voter_id`, `approved_at_ms`, `ledger_entry_id`.
   - Use `swarm_crypto::signing::PublicKey::from_hex(&vote.public_key_hex)` and `Signature::from_hex(&vote.signature_hex)` to verify.
   - Return false on any parse or verification failure (fail-closed).

4. **Add `verify_consensus_receipt_signature()` function:**
   ```rust
   pub fn verify_consensus_receipt_signature(
       receipt: &PromotionConsensusReceipt,
   ) -> bool
   ```
   - Reconstruct the canonical signing payload: `canonical_json_bytes` of the receipt fields minus the signature fields.
   - Verify using `swarm_crypto::verify_detached_signature`.
   - Return false on any failure.

5. **Update `approve_pending_run()` to call the quorum gate:**
   - Before transitioning to Active, call `validate_quorum_gate(&votes, &self.quorum_config())`.
   - Add a `quorum_config()` method to `DefaultProductionPromotionHarness` that returns `PromotionQuorumGateConfig::default()` for now (advisory pass-through). The config can later be loaded from `SwarmConfig` when approval set configuration exists.
   - Verify each vote signature using `verify_vote_signature`. If any vote fails verification, return a new error:
     ```rust
     #[error("vote signature verification failed for voter `{voter_id}`")]
     VoteSignatureInvalid { voter_id: String },
     ```
   - If a consensus receipt is provided, verify its signature. If invalid, return:
     ```rust
     #[error("consensus receipt signature verification failed for receipt `{receipt_id}`")]
     ReceiptSignatureInvalid { receipt_id: String },
     ```

6. **Add `quorum_gate_config` field to `ProductionPromotionReport`:**
   ```rust
   pub quorum_gate_config: Option<PromotionQuorumGateConfig>,
   ```
   Persisted on the promotion record so the gate configuration at approval time is preserved for audit.

7. **Update `render_production_promotion_report()`:**
   - Add "Quorum Gate" section showing threshold config (or "advisory-only: no threshold configured")
   - If votes present, show per-vote verification status
   - If consensus receipt present, show receipt verification status

Write tests using `swarm_crypto::signing::Keypair::generate()` to create real Ed25519 keys, sign vote payloads, and verify the round-trip through the gate.
