`ArenaIngestResult` is the single handoff boundary into this plan:
```rust
pub struct BlueOutcome {
    pub phase286_capture: Option<
        swarm_runtime::hypothesis_graph::service::Phase286InvestigationCapture,
    >,
    pub no_action: Option<swarm_runtime::service::NoActionFindingReplay>,
    pub policy_receipt: Option<swarm_runtime::service::DryRunTraversalReceipt>,
    // campaign, findings, policy, preview, rollback, metrics, ...
}
impl BlueOutcome {
    pub fn from_ingest_result(
        ingest: swarm_ingest_runtime::ingest::ArenaIngestResult,
        policy_receipt: Option<swarm_runtime::service::DryRunTraversalReceipt>,
    ) -> Result<Self, BlueRuntimeError>;
}
```
`from_ingest_result` moves (not clones from a side channel) the one
`ingest.phase286_capture: Option<Phase286InvestigationCapture>` and the legal
`ingest.no_action: Option<NoActionFindingReplay>` into the outcome. It rejects
a `None` capture for a finding-bearing scoreable/actionable event, but retains
the explicit no-action DTO for the legal no-action finding case. It never calls
`Phase286StrategyBridge::investigate_once`, `HypothesisGraphCoordinator`, or
`ContainmentPlanner`; those have already run once inside
`process_bridge_event_at`. The compile/integration test
`arena_ingest_capture_is_single_source` compares the capture graph digest,
investigation outcome, decision, simulation, and invocation counters in the
ingest result and Blue outcome, and asserts exactly one detector, coordinator,
planner, request builder, policy, receipt, dispatcher, recording response-adapter,
and rehearsal traversal.
`policy_receipt` is `Some(_)` exactly when the single `request_builder` returned
an action and the single rehearsal traversal completed; it is `None` for the
legal no-action finding case, which retains `no_action` evidence and performs no policy,
receipt, dispatcher, or response-adapter traversal. A scoreable actionable
outcome may not carry `Some(action)` without `Some(policy_receipt)`.
Replacing the typed field with a rerun, digest-only copy, optional second
replay, or `audit_authorize_and_execute` duplicate is a mutation failure.

The Phase 286 coordinator remains the graph/planning implementation. The
runner consumes only the public `Phase286InvestigationCapture` produced by the
post-Plan-06B one-shot bridge/stack handoff; it never invokes
`HypothesisGraphCoordinator::investigate` or `ContainmentPlanner::simulate`
independently. The existing fenced graph/task/memory stores remain Phase 286
owned. Arena artifacts use the Arena-owned
`ArenaArtifactStore`; there is no Phase 286 artifact-store dependency. The
runner may not rebuild graph nodes, replace the coordinator with
`SummaryInvestigator`, or promote a candidate.

The runner must call `SwarmConfig::arena.require_enabled()` before it creates
`CoEvolutionArena`, `BlueRuntimeAdapter`, `IngestState`, a target resolver, a
detector, or a configured runtime stack. A default-disabled config is a typed
refusal with zero runner/ingest construction or downstream calls. The only
configured investigation strategy passed to the Blue stack is the Phase 286
owned `swarm_runtime::hypothesis_graph::service::Phase286StrategyBridge`,
which implements the existing `swarm_runtime::investigation::InvestigationStrategy`
trait; `SummaryInvestigator` is not a legal fallback.

`ArenaRunConfig::run_root` is required and is the only root for artifact,
learned-state, partition-copy, task, and temporary-resource paths. The runner
records a run-root ownership token, refuses a non-empty/unowned root, and
returns a cleanup report. The final gate checks that exact root is empty and
that no process/socket/task remains; it never runs broad `git clean` or deletes
the repository worktree.
