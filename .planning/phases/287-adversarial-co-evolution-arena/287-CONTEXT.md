# Phase 287 Context: Adversarial Co-evolution Arena

## Objective

Build a bounded Red/Blue Co-evolution Arena that exercises the real Ambush investigation and containment-planning path. Red campaigns should adapt from observed blue behavior; blue should learn from escapes and falsified hypotheses. A larger agent count is not evidence of intelligence—the arena must show measurable improvement and generalization.

## Required shape

- Red agents compose multi-stage campaigns from the catalogued tactic/technique corpus using deterministic seeds, `swarm_core::hypothesis_graph::GraphLogicalTime`, event budgets, and closed `FixtureTargetId` mappings to isolated synthetic fixtures. They cannot implement/depend on the runtime `GraphClock`, invent unbounded capabilities, or access live targets.
- Blue agents investigate generated campaigns through real ingest, graph, detector, policy, and containment-planning boundaries. Red code has no response-adapter or policy-authority capability.
- Red mutation receives only the signed authority-free `RedOutcomeProjection` derived from the Arena-owned full `BlueOutcome` and records the outcome/projection digest that caused each surviving change in timing, ordering, or tactic composition. Campaigns terminate on hard safety/authority refusal, partition/withheld boundary, generation, event/work, virtual-time, mutation, plateau, or coverage bounds in fixed precedence order.
- Blue emits detector and response candidates from escapes and falsified hypotheses with evidence lineage, affected telemetry, expected coverage, safety constraints, and reproducible candidate IDs.
- Candidates compete on historical attacks, benign controls, counterexamples, and withheld campaigns. False positives, latency/resource cost, containment safety, and withheld generalization are separate dimensions. When detector-escape and containment/planning-gap signals are both applicable, both detector and response candidates are required; accepted candidates enter only a bounded learned-state projection for later Phase 288 evaluation.
- The exact Blue seam is `FixtureTarget::normalize_event(&FixtureEvent, GraphLogicalTime) -> Result<TelemetryEvent, FixtureError>` followed by `IngestState::process_bridge_event_at<D,P,E>(&self, TelemetryEvent, &dyn GraphClock, &ArenaDetectionStrategyAdapter<D>, &ConfiguredRuntimeStack<P,E,Phase286StrategyBridge>)`; the supplied sized detector adapter and graph-only stack are mandatory and the fixed `IngestState` stack cannot be silently used. The seam returns the exact `swarm_ingest_runtime::ingest::ArenaIngestResult { normalized_event, normalized_event_digest, findings, phase286_capture: Option<Phase286InvestigationCapture>, no_action: Option<NoActionFindingReplay>, safety }` constructed only by `ArenaIngestResult::from_injected_runtime`; `no_action` is retained evidence for a legal finding with `None` action and is mutually exclusive with `phase286_capture` for the single-finding fixture. The valid Arena fixture is single-finding, `Phase286InvestigationCapture.replay` is the sole replay carrier, and no side-channel replay, multi-finding fan-out, or rerun is allowed. It rejects default-disabled `ArenaConfig`, non-DetectOnly mode, graph-disabled state, investigation-enabled worker configuration, fixed-stack substitution, and any external effect before graph/planning. Phase 286's post-Plan-06B compile-checked `GraphInvestigationInput`/`GraphInvestigationResult` (including explicit neutral `HypothesisSeedAssessment` values and durable hypotheses), `GraphInvestigationStrategy`, `InvestigationStrategyAdapter`, `Phase286StrategyBridge` (the existing async `swarm_runtime::investigation::InvestigationStrategy` implementation), `Phase286InvestigationCapture`, injected `HypothesisGraphStore`/`GraphRecordSigner`, `HypothesisGraphCoordinator`, and core-owned `ContainmentSimulation`/`ContainmentPlanner` are consumed at their exact public paths. The specialized stack is constructed only by `ConfiguredRuntimeStack::from_graph_components(config, policy, response, bridge)`, which calls `InvestigationCoordinator::new_without_worker`; its worker-spawn probe remains zero, and no graph-enabled construction may instantiate or fall back to `SummaryInvestigator`. It invokes `Phase286StrategyBridge::investigate_once` once: one captured graph result feeds the existing investigation outcome, typed decision, and containment simulation; no generic investigation queue is also used. The same finding invokes one request builder and one `ArenaActionContext` construction; `Some(action)` yields at most one `RuntimeService::rehearse_selected_simulation` traversal and receipt, while `None` yields the explicit no-action DTO with retained evidence and no policy/receipt traversal. `audit_authorize_and_execute` and its instrumented duplicate remain at zero calls.
- `BlueRuntimeAdapter::run` accepts a bounded signed `BlueLearnedState`; it calls `apply_detector_profile(&DetectionConfig)` and `apply_graph_strategy(&GraphInvestigationStrategy)` to materialize admitted detector/config and graph-policy changes before the next Blue run. The paired control passes `SignedBlueLearnedState::empty_frozen()`. A learned state that changes only a digest or event ID is not learning evidence and must fail the direct outcome-change test.
- Learned-state detector families, graph strategy IDs, and graph policy modes are closed enums with a finite vocabulary; patch selection is deterministic from canonical candidate order and a fixed seed, with unknown strings, ties, reorderings, digest-only changes, and no-op patches rejected.

## Measurement contract

Report time to containment, containment blast radius, previously unseen evasions, improvement over the single-agent baseline, and withheld-campaign generalization. Acceptance requires at least 15% median containment-time improvement, no increase in median blast radius, at least one previously unseen evasion in three consecutive seeded runs, at least 10% improvement over baseline, and withheld performance no worse than 5% relative to in-sample score.

## Safety boundary

The no-action contract is explicit: Phase 286's
`FindingReplayOutcome::{NoFinding,NoAction,Actionable}` maps to
`Phase286StackResult` with the same three cases. `NoActionFindingReplay` keeps
the normalized event/finding/deposit evidence but has no `ActionRequest`; its
path makes zero policy, receipt, dispatcher, response-adapter, and generic
investigation calls. `ArenaIngestResult` carries
`no_action: Option<NoActionFindingReplay>` alongside
`phase286_capture: Option<Phase286InvestigationCapture>`, and only the
actionable case may populate the latter. The exact normalizer always returns
`Result<TelemetryEvent, FixtureError>`; the injected ingest API is concrete over
`ConfiguredRuntimeStack<P,E,Phase286StrategyBridge>`, not generic over an
arbitrary investigation strategy.

Static and runtime isolation controls must fail closed if red code imports response execution or any authority reachable through `swarm-core`, a blue simulation bypasses graph-enabled runtime/policy/governance/dispatcher, or a generated action lacks the receipt/approval boundary. Include negative fixtures that prove each isolation check can fail on the same `RuntimeService::rehearse_selected_simulation` traversal used by Blue. Its exact public `swarm_runtime::service::DryRunTraversalReceipt` fields are `policy_verdict`, `pouncer_selection_id`, `tom_governance_receipt_id`, `operator_approval_id`, `dispatcher_admission_id`, `simulated_receipt_id`, and `response_status`; its constructor rejects empty IDs/non-`Simulated` status, and the async `RuntimeService::rehearse_selected_simulation(&ContainmentSimulation, &DetectionFinding, &ActionRequest, &ApprovalContext)` is the only construction path. That traversal must prove policy, Pouncer, Tom/governance, operator approval, bound receipt, dispatcher admission, and `ResponseStatus::Simulated` without enforced adapter side effects. `swarm_core::config::arena::ArenaConfig` is the sole owner of serde-defaulted, validated bounds and the relative run root; `require_enabled()` must run before runner or ingest construction, and omitted `arena` in the signed ruleset must preserve the raw signed bytes. All artifacts live below that configured run root and are CAS/fence protected; Arena results are evidence for synthesis, not permission to deploy a candidate.
