**PART A: Production code fixes (49 violations)**

Run `cargo clippy -p swarm-runtime --all-targets -- -D clippy::unwrap_used -D clippy::expect_used 2>&1 | grep "^\s*-->"` to get the exact violation locations. For each production (non-test) violation, apply the appropriate fix:

**General fix patterns:**

1. `.expect("message")` on an infallible-looking operation (e.g., `HashMap::get_mut` after insertion):
   - Replace with `.ok_or_else(|| SomeError::Internal("message".into()))?` if the function returns `Result`
   - Or use `if let Some(v) = map.get_mut(k) { ... }` pattern

2. `.expect("checked")` or `.expect("field")` on Option fields (like `request.import_id.as_deref().expect("checked")`):
   - Replace with `.ok_or_else(|| SomeError::InvalidInput("import_id required".into()))?`

3. `.expect("system time...")` on `SystemTime::duration_since(UNIX_EPOCH)`:
   - Replace with `.unwrap_or_default()` (system time before epoch is a safe default of Duration::ZERO)
   - Or `.map_err(|_| SomeError::Internal("system clock error".into()))?`

4. `args.field.expect("field")` in swarmctl CLI arg parsing:
   - Replace with `.ok_or_else(|| anyhow::anyhow!("--field is required"))?`
   - The swarmctl binary uses `anyhow::Result`, so `anyhow!()` is the right error constructor

5. `.unwrap()` in example code (`examples/fast_detection_bench.rs`):
   - Add `#![allow(clippy::unwrap_used, clippy::expect_used)]` at the top of the file (examples are not production code)

**File-specific guidance (by violation count):**
