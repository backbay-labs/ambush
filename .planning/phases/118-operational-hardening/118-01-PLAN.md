<objective>
Implement independent secret-dir hot rotation so that when a file changes in `secret_dir`, only the affected `@secret:` references are re-resolved and injected into active adapter configs without triggering a full config reload.

Purpose: Close HARDEN-08 audit finding — currently a secret file change triggers `reload_from_disk()` which parses the entire YAML, rebuilds the detector, and replaces the full runtime stack. This is heavy and unnecessary when only a secret value changed.
Output: `reload_secrets_only()` method on `IngestState`, updated `swarm_detect` binary handler, tests proving secrets-only reload path works.
</objective>

2. In `crates/swarm-runtime/src/ingest.rs`:
   - Add a `pub fn reload_secrets_only(&self) -> Result<(), IngestBuildError>` method to `IngestState`.
   - This method:
     a. Loads the current `ConfiguredRuntimeStack` from `self.stack.load_full()`
     b. Clones the current `config` from the stack's `service.config`
     c. Calls `resolve_outbound_secrets(config, Some(self.config_path()))` to re-resolve all `@secret:` references from disk
     d. Rebuilds only the `ConfiguredRuntimeStack` from the updated config (calls `Self::build_runtime(config)`)
     e. Stores the new stack via `self.stack.store(new_stack)` but does NOT update the detector or detector_status (the detector is not secret-dependent)
     f. Logs at info level: `"reloaded secrets without full config reload"`
   - NOTE: Because `build_runtime` also rebuilds the detector, an alternative lighter approach is: read the raw YAML from disk, re-resolve secrets on it, and call `self.reload(updated_config)`. This still replaces the detector but avoids re-parsing behavior. The requirement says "without triggering a full config reload" — the key distinction is that we skip disk YAML parsing and validation. The simplest correct approach: read current config from the loaded stack, re-resolve secrets, then call `self.reload(resolved_config)`. This avoids re-reading the YAML file. Document in code comment that the detector rebuild is lightweight since config is reused.
