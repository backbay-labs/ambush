# Phase 292 — Pure Decision Core Extraction

**Status:** implementation plan, 2026-09-08. Executed with subagent-driven-development. Branch
`feat/decision-core-292` off `main` `440a34cb4` (v1.80 milestone complete). First v1.81
Machine-Checked Decision Core phase — the prerequisite for Kani (293) and named safety properties
(294): a proof apparatus needs an IO-free decision surface.

**Goal (ROADMAP.md).** Carve out total, clock-injected, lock-free decision functions from the policy
gate and the governance predicates, enforced by a dependency-boundary gate. `can_act` currently reads
the OS clock internally and the gates hold rate-limit state in a `Mutex`; this phase makes the
decision logic pure.

**Requirements, verbatim (REQUIREMENTS.md:909–913).**
- **DCORE-01**: `crates/swarm-policy/src/formal_core.rs` holds the approval and rate-limit logic as
  pure total functions taking window state and `now_ms: i64` explicitly, returning updated state
  instead of mutating `Arc<Mutex<HashMap<..>>>` in place.
- **DCORE-02**: The partition and governance predicates (`GovernancePolicy::can_act`,
  `ContingencyLease::verify`/`can_redeem`/`redeem`, `governance_quorum_threshold`) are ported into
  `formal_core.rs` with no `Mutex`, no `fs`, and no direct clock; the internal `now_ms()` call at
  `tom_agent.rs:508` becomes an explicit parameter.
- **DCORE-03**: `cargo tree -p swarm-policy` contains no `axum`, `hyper`, `tokio-rustls`, `reqwest`,
  `opentelemetry*`, `clap`, or `x509-parser`.
- **DCORE-04**: `docs/adr/ADR-0002-decision-core-boundary.md` plus
  `scripts/check-decision-core-boundary.sh` enforce the forbidden-dependency list in CI.
- **DCORE-05**: Every pre-existing `static_gate`, `configurable_gate`, and `tom_agent` governance
  test passes unchanged against the new call paths.

**Success criteria (ROADMAP.md).** (1) `formal_core.rs` holds the approval/severity/rate-limit/lease
predicates as pure functions — no mutex/fs/clock/network in their bodies; (2) `GovernancePolicy::can_act`
no longer calls `now_ms()` internally — the clock is caller-supplied at every `formal_core` entry;
(3) `cargo tree -p swarm-policy` has no transport/telemetry/CLI crate, enforced by the boundary gate
in CI; (4) every pre-existing gate + governance test passes unchanged.

## Design of record (controller rulings, 2026-09-08; grounded in 292-SCOPING.md, re-verify at HEAD)

- **DCORE-03 is ENFORCE-only.** `cargo tree -p swarm-policy` is ALREADY clean of all seven forbidden
  deps (swarm-policy depends only on `swarm-core`). No dependency removal is needed — DCORE-03/04 add
  the gate that KEEPS it clean. (Re-verify at HEAD before writing the gate.)
- **DCORE-04 path slip → repo convention.** The requirement names `docs/adr/ADR-0002-…` and
  `scripts/check-decision-core-boundary.sh`, but this repo's ADRs are `docs/decisions/NNNN-…`
  (0001–0011 exist; next is **0012**) and its gates are `tools/check-*.sh` (`check-gates-wired.sh`
  scans `tools/`; a gate in `scripts/` would be unenforced). RULE: ADR at
  `docs/decisions/0012-decision-core-boundary.md`, gate at `tools/check-decision-core-boundary.sh`,
  wired into `ci.yml`. Record the slip (same as phases 283/285/291).
- **DCORE-01 keeps the Mutex at the EDGE, the core PURE.** The rate-limit window state
  (`Arc<Mutex<HashMap<String, VecDeque<i64>>>>` at `static_gate.rs:18` scope_windows +
  `configurable_gate.rs:16` agent_windows) stays owned by the gate structs; the pure `formal_core`
  functions take the window state (or a slice/`&VecDeque`) + `now_ms: i64` and RETURN the decision +
  updated window, and the gate applies the update under its lock. No behaviour change — the gate is a
  thin stateful shell over a pure total core.
- **DCORE-02 moves the predicate LOGIC down the dep graph (cycle-free).** `GovernancePolicy::can_act`,
  `ContingencyLease::{verify,can_redeem,redeem}`, `governance_quorum_threshold`, and the internal
  `now_ms()` at `swarm-agents/src/tom_agent.rs:508` live in **swarm-agents**, which depends ON
  swarm-policy (swarm-policy depends only on swarm-core) — so moving the pure predicate logic INTO
  `swarm-policy::formal_core` is a legal downward move, no cycle. Types the predicates need
  (`ContingencyLease`, the `GovernancePolicy` decision inputs) move to `swarm-core` (the shared type
  crate) or `swarm-policy` as the port requires; `swarm-agents` then calls `swarm-policy::formal_core`
  with the clock supplied explicitly. Behaviour is preserved exactly; the move must not change any
  verdict for any input.
- **Preserve the phase-285 fail-closed invariants.** The 285 `// INVARIANT:` markers, negative tests,
  and `docs/assurance/MAPPING.md` rows for swarm-policy (static_gate `evaluate`/`validate_request`,
  the scope-rate-limit, human-gate) sit exactly where this phase refactors. The extraction MUST keep
  each invariant enforced at a resolvable `crate::module::function` (update the MAPPING path + move
  the `// INVARIANT:` marker WITH the logic if it moves into `formal_core`), so `check-mapping.sh` +
  `check-negative-registry.sh` stay green and no fail-closed behaviour weakens. This is TCB-adjacent
  (swarm-policy is in the TCB per ADR 0009) — review it as a security change.

unbounded recursion in their bodies. **Behaviour-preserving**: DCORE-05 requires every existing
static_gate/configurable_gate/tom_agent test to pass UNCHANGED — a changed test assertion is a red
flag, not an allowed edit. No new non-dev dependency. Tests `a_thing_does_x_when_y`; commits
`git commit -s`, Conventional Commits. **Resource discipline:** scoped tests
(`cargo test -p swarm-policy`, `cargo test -p swarm-agents <filter>`), foreground, one at a time;
NEVER `cargo test --workspace`; NEVER background. The closing task updates only `.planning/`.

**Pre-flight scan.** Sequential pipeline T1→T2→T3→T4 — the extraction is interdependent (T2 builds on
T1's `formal_core`; T3's boundary gate follows the extraction; the tests (DCORE-05) are verified in
every task, not deferred). Not parallel. Review each task as a TCB-adjacent security change; a
whole-branch review before merge.

### Task 1: `formal_core.rs` + the pure approval/rate-limit core (DCORE-01)

**Files.** `crates/swarm-policy/src/formal_core.rs` (new); `crates/swarm-policy/src/lib.rs` (module
decl); `static_gate.rs` + `configurable_gate.rs` (call the pure core, keep the Mutex at the edge).

**Behaviour.** Extract the approval + rate-limit logic into `formal_core` as pure total functions
that take the window state (the `VecDeque<i64>` of timestamps for a scope/agent) + `now_ms: i64` +
the limit, and RETURN the decision (allow/deny + reason) and the updated window (prune-then-check).
The gate structs keep `Arc<Mutex<HashMap<..>>>` and, under the lock, read the window, call the pure
core, and write the returned window back. No verdict changes for any input.

**Tests / verification.** SC1: `formal_core` bodies have no `Mutex`/`fs`/clock/network (grep + read).
`cargo test -p swarm-policy` — every existing static_gate + configurable_gate test passes UNCHANGED
(DCORE-05). The 285 invariants for swarm-policy still resolve (`bash tools/check-mapping.sh`,
`check-negative-registry.sh` → 0; move any `// INVARIANT:` marker with its logic). fmt/clippy clean.
