# Phase 298 — Cross-Hunt Correlation

**Status:** implementation plan, 2026-09-08. Executed with subagent-driven-development. Branch
`feat/xhunt-298` off `main` `be91c5572` (Phase 297 complete). Third phase of v1.82. Depends on 297
(the graph traversal + `provenance_paths`/`causal_provenance_paths`), which is met.

**Goal (ROADMAP.md).** Retire pairwise heuristics in favour of graph-native traversal, make
incidents durable across restarts, and prove the optional lanes never gate detection or response.

**Requirements, verbatim (REQUIREMENTS.md:963–966).**
- **XHUNT-01**: `CorrelationEngine`'s pairwise heuristics are replaced by graph traversal; all four
  `IncidentGraphDimension` tags come from real graph edges rather than string overlap.
- **XHUNT-02**: `IncidentEvidenceLink` gains an optional `graph_path` so a reopened incident is
  re-explainable without recomputation; pre-existing JSON still deserializes.
- **XHUNT-03**: An integration test disables `correlation.enabled` and `memory.enabled` together and
  asserts identical policy decisions, proving the optional lanes never gate the critical path.
- **XHUNT-04**: A restart-simulation test proves incidents reload with identical dimensions and evidence.

**Success criteria (ROADMAP.md).** (1) Candidate selection uses graph traversal rather than
recent-investigation scanning, and all pre-existing correlation tests still pass. (2) Evidence links
carry a graph path for every newly created link, and pre-existing JSON still deserializes. (3)
Disabling correlation and memory together yields policy decisions identical to the enabled case. (4)
Incidents assembled before a simulated restart reload with identical dimensions and evidence.

## Current code (from the 2026-09-08 exploration — re-verify at HEAD)

- **`CorrelationEngine`** (`crates/swarm-runtime/src/correlation.rs`): today it is entirely
  string/field-overlap. `correlate_hunt_at(investigations, incidents, hunt_id, created_at_ms)`
  (L67-98) enumerates candidates via `investigations.recent(config.candidate_limit)` (default 32) and
  scores them with the private `assemble_incident_at` (L136-259) → free functions `weighted_score`
  (L279-367), `shared_keys`, `shared_receipts`, `semantic_values`, `shared_summary_terms`,
  `tokenize_summary` (L262-457). All four dimensions come from strings: **Entity** = `is_entity_key`
  prefix match over `correlation_keys`; **Causal** = shared `related_receipt_ids` + `trail_id` string
  equality; **Semantic** = `threat_class`/`process_name`/`response_kind` equality + free-text summary
  token overlap; **Temporal** = `time_delta_ms <= time_window_ms`. `config.enabled` is read once
  (L78, returns `Ok(None)` when false). `memory.enabled` is NOT read here — it only gates whether
  `SphinxAgent` is registered (`swarm-runtime-http/src/bin/swarm_detect.rs:82`).
- **`graph_provenance_link(&self, graph: &KnowledgeGraphSnapshot, from, to, max_hops) -> Vec<ProvenancePath>`**
  (correlation.rs:115-123): a 1:1 pass-through to `provenance_paths`, added by Phase 296, **currently
  unused** by any correlation logic (its doc comment names this migration — XHUNT-01 — as its purpose).
- **`KnowledgeGraphSnapshot`** (`crates/swarm-runtime/src/sphinx_agent.rs`): post-297 exposes
  `provenance_paths(from,to,max_hops)` (all edges) and `causal_provenance_paths(from,to,max_hops)`
  (`Causal`-only), both undirected, hub-degree-capped (`PROVENANCE_HUB_DEGREE_CAP=32`), returning at
  most one shortest `ProvenancePath { node_ids, edge_ids }`. There is **no public accessor** to a live
  `SphinxAgent`'s private `graph`; the only external route is re-reading the persisted signed snapshot
  via `FileKnowledgeGraphStore::open(path).load_trusted_snapshot(expected_signer)` /
  `load_snapshot()` (sphinx_agent.rs:~1801-1829) against the same `memory_root` the agent writes.
- **Anchors (load-bearing).** No node carries a `hunt_id`. The per-observation anchor is
  `EngagementNode`, id `engagement:{sanitize_id(observation_id)}` where `observation_id` resolves from
  the deposit indicator's `observation_id` → `event_id` → `hunt_id` (first present).
  **In production a single hunt splits into two disjoint Engagement nodes:** detection findings key on
  `event_id` (`detection/pipeline.rs:560`), the Stalker's post-investigation deposit keys on `hunt_id`
  (`stalker_agent.rs:184`). They connect only through a shared `Entity(host)` node. An
  `InvestigationBundle` carries both `hunt_id` and `event_id` (`swarm-spine/src/investigation.rs:118`).
- **`IncidentGraphDimension`** (`crates/swarm-spine/src/incident.rs:113-121`): enum `Temporal`,
  `Causal`, `Entity`, `Semantic` (snake_case serde). Populated on `CorrelatedIncident.graph_dimensions`
  by collecting `link.dimension` off included members (correlation.rs L201-207).
- **`IncidentEvidenceLink`** (incident.rs:123-132): `{ dimension: IncidentGraphDimension, explanation:
  String, #[serde(default)] shared_values: Vec<String>, #[serde(default)] weight: usize }`. Persisted
  verbatim inside `CorrelatedIncident.included_members[].evidence_links` as pretty JSON by
  `FileIncidentStore::write_incident`. **A second hand-mapped mirror exists:**
  `PerchIncidentEvidenceLink` (`crates/swarm-ingest-runtime/src/ingest/perch_ops/incident_read.rs:20-26`,
  mapped field-by-field in `member_view` L88-97) — must be updated in lockstep or the operator `GET`
  read silently drops the new field.
- **`ReconstructedChainHop`** (incident.rs:281-285): `{ node_ids: Vec<String>, edge_ids: Vec<String> }`
  — the existing spine-local, plain-id mirror of `ProvenancePath`, added in 297 precisely because
  swarm-spine may not depend on swarm-runtime (ADR 0009 / `check-workspace-layering.sh`).
- **`IncidentStore`** (incident.rs:374-410): `persist`/`load_by_incident_id`/`load_by_hunt_id`/`recent`
  + kill-chain methods, across `Memory`/`File`/`Configured` backends. `FileIncidentStore` already
  reloads on reopen (tested by `file_store_persists_and_loads_by_hunt_id`).
- **Critical-path decoupling (already true).** `crates/swarm-runtime/src/lib.rs`
  (`authorize_and_execute` → `policy.evaluate`, the policy/response critical path) has ZERO references
  to `Correlation`/`Sphinx`/`memory`. `ConfiguredRuntimeStack::correlate_hunt` (stack.rs:188) is a
  separate method invoked by callers AFTER `process_event*` has returned an already-final, persisted
  audit (`ingest/mod.rs:1317`, `weaver_agent.rs:96`). No existing test asserts "correlation+memory
  disabled → identical decision".
- **Pre-existing correlation tests** (correlation.rs `mod tests`, L578-920): tests 1-4
  (`correlate_hunt_includes_matching_candidates_and_rejects_others`,
  `cross_strategy_bonus_allows_one_real_overlap_to_meet_threshold`,
  `cross_strategy_bonus_is_rejected_without_real_overlap`,

## Design of record (controller rulings, 2026-09-08; re-verify at HEAD)

- **RULING — SC1 vs XHUNT-01 (the load-bearing tension).** XHUNT-01 is the binding requirement:
  pairwise heuristics are REPLACED by graph traversal, dimensions come from real graph edges "rather
  than string overlap". SC1's "all pre-existing correlation tests still pass" is therefore read as:
  every correlation/persistence test that does NOT pin the replaced string-overlap internals stays
  green, and the 4 heuristic-semantics tests (correlation.rs tests 1-4) are REWRITTEN in lockstep to
  construct a `KnowledgeGraphSnapshot` fixture and assert the new graph-derived dimensions. This is the
  requirement's intended change, not incidental breakage — a reviewer seeing tests 1-4 change is
  expected; a reviewer seeing the pass-through test (5) or any incident-persistence test change without
  cause is a red flag. Cost if wrong: rework of the correlation test suite; visible and cheap to undo.
- **RULING — snapshot as an argument, no new coupling.** `CorrelationEngine` gains graph awareness by
  taking `graph: Option<&KnowledgeGraphSnapshot>` on the correlation entry point (new
  `correlate_hunt_with_graph_at(...)`, with `correlate_hunt_at` delegating with `None` to preserve the
  no-graph path). The runtime caller (`RuntimeService::correlate_hunt` / `ConfiguredRuntimeStack::correlate_hunt`)
  loads the snapshot from the same persisted `FileKnowledgeGraphStore` the SphinxAgent writes
  (`load_trusted_snapshot` against `memory_root` + the SphinxAgent signer id), passing `None` when
  `memory.enabled` is false or no snapshot exists. This mirrors how `chain_reconstruction` and
  `graph_provenance_link` already take a snapshot argument, adds NO in-process SphinxAgent↔Correlation
  channel, and keeps the graph a strictly advisory input off the critical path.
- **RULING — hunt→anchor resolution.** A helper resolves an `InvestigationBundle` to its candidate
  graph anchor node ids: BOTH `engagement:{sanitize_id(hunt_id)}` and `engagement:{sanitize_id(event_id)}`
  (production splits a hunt across both). Reuse sphinx_agent's exact `sanitize_id` + engagement-id
  format (make `sanitize_id` / an `engagement_node_id(&str)` helper `pub(crate)` in sphinx_agent;
  same crate, no layering issue) and pin format-equality with a test. Correlation considers a candidate
  connected if ANY (seed_anchor, candidate_anchor) pair over these ids has a graph path.
- **RULING — dimensions strictly from graph edges.** For a (seed_anchor, candidate_anchor) pair, run
  `provenance_paths(seed, cand, max_hops)` (all-edge, hub-capped). Classify the edge kinds crossed on
  the returned path into `IncidentGraphDimension`s: a `Causal` edge → `Causal`, `Entity` → `Entity`,
  `Semantic` → `Semantic`, `Temporal` → `Temporal`. Each contributing dimension yields one
  `IncidentEvidenceLink` whose `graph_path` (XHUNT-02) is that `ProvenancePath` (→ `ReconstructedChainHop`),
  `shared_values` = the node ids the path crossed, `weight` = a count derived from the path (e.g. edges
  of that kind). NO string overlap (`correlation_keys`, summary tokens, `trail_id` equality) survives in
  the decision. A candidate with no graph path (unreachable, or only reachable through a hub the cap
  refuses) is REJECTED with a graph-derived reason.
- **RULING — Causal fabrication guard (GRAPH-03 carries forward).** The `Causal` dimension must be
  justified by `causal_provenance_paths` (the 297-hardened `Causal`-only walk), NOT by "a causal edge
  happened to sit on the all-edge path". This reuses the exact cross-hunt-bridge lesson: a `Causal` tag
  is emitted only when a genuine causal-only path connects the anchors; otherwise the pair may still
  correlate on `Entity`/`Semantic`/`Temporal` but is never labeled causal. The hub-degree cap keeps a
  shared high-degree node (a popular host) from bridging unrelated hunts — the same GRAPH-03 property.
- **RULING — candidate selection.** Enumeration stays bounded by `investigations.recent(candidate_limit)`
  (a scalability window, not a heuristic), but INCLUSION and all four dimensions are decided ENTIRELY by
  graph traversal between anchors — the graph is the sole arbiter; `recent()` only bounds which incidents
  are in scope. This satisfies SC1 ("selection uses graph traversal rather than recent-investigation
  scanning" — the scanning no longer *decides* anything) without a lossy engagement-node→bundle reverse
  index. If review judges the bound itself must be graph-derived, that is a follow-on; the decision logic
  is fully graph-native here.
- **RULING — `graph_path` type + both mirrors.** `IncidentEvidenceLink.graph_path:
  Option<ReconstructedChainHop>` with `#[serde(default, skip_serializing_if = "Option::is_none")]`
  (reuse the existing spine-local plain-id type; keeps swarm-spine TCB-clean). Update
  `PerchIncidentEvidenceLink` + its `member_view` mapping in lockstep. A back-compat test deserializes
  pre-`graph_path` JSON and round-trips.
- **Honest caveat carried forward (from 296/297).** Entity(host)/Semantic(KillChainStage)/Temporal
  edges DO fire from live telemetry, so the graph has real cross-hunt structure; but the deep OS-causal
  edges (FileWrite/FileExecute/DnsResolution/CredentialAccess) still require raw `pid`/`process_key`/
  resolved-IP that no normalized telemetry event carries, so the `Causal` dimension will be sparse on
  production traffic until that producer-wiring lands. Record this in the SUMMARY; do NOT expand scope
  into telemetry normalization here unless an XHUNT requirement cannot otherwise be met.
