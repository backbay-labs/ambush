# Phase 1 Plan 01: Runtime Config Contract

<objective>
Replace doc-only configuration with a strict Rust-owned contract that loads repository YAML and rejects unknown or malformed fields.
</objective>

<read_first>
- .planning/phases/01-baseline-contracts/01-CONTEXT.md

- crates/swarm-core/src/types.rs
- crates/swarm-runtime/src/config.rs
- crates/swarm-runtime/src/lib.rs
- rulesets/default.yaml
</read_first>

<tasks>
<task number="1" type="auto">
<description>Define typed runtime and ruleset configuration with explicit runtime mode and strict serde validation.</description>
<acceptance_criteria>
- Runtime mode is an enum, not a free-form string.
- Unknown YAML fields are rejected during deserialization.
- Config structs model the v1 Rust-only lane instead of the older swarm population and BFT scaffold.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Add repository file-loading helpers and actionable validation errors for configuration.</description>
<acceptance_criteria>
- Config can be loaded from a repository path.
- Errors include enough context to identify the bad file or field.
- The default repository ruleset can be parsed by tests.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add unit tests for valid config, unknown fields, and invalid runtime modes.</description>
<acceptance_criteria>
- A passing test covers the default config file.
- A failing test demonstrates unknown-field rejection.
- A failing test demonstrates invalid runtime mode rejection.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-core -p swarm-runtime
</verification>

<success_criteria>
- Config loading is repository-owned and typed.
- Unknown or malformed config fails fast.
- Runtime mode is explicit and test-covered.
</success_criteria>
