# Phase 8 Plan 01: Async Investigation Pipeline

<objective>
Introduce a durable async investigation lane that enriches persisted replay bundles without delaying the critical detect and response path.
</objective>

<read_first>
- .planning/phases/08-async-investigation-pipeline/08-CONTEXT.md
- crates/swarm-runtime/src/service.rs
- crates/swarm-runtime/src/lib.rs
- crates/swarm-spine/src/store.rs
- crates/swarm-core/src/config.rs
</read_first>

<tasks>
<task number="1" type="auto">
<description>Add repository-owned investigation configuration and durable investigation bundle storage.</description>
<acceptance_criteria>
- Config supports enablement, worker count, queue depth, time budget, and investigation bundle storage backend.
- Investigation bundles persist with hunt, trail, and receipt identifiers.
- Memory and local-files investigation stores mirror the replay-store durability pattern.
</acceptance_criteria>
</task>

<task number="2" type="auto">
<description>Build an async investigation coordinator and deterministic default investigator.</description>
<acceptance_criteria>
- Persisted replay bundles can be submitted to a background queue without waiting for completion.
- Background workers persist queued, completed, failed, or timed-out investigation outcomes.
- Default investigation strategy produces stable summaries and evidence points from replay-bundle data.
</acceptance_criteria>
</task>

<task number="3" type="auto">
<description>Add runtime integration tests proving nonblocking submission, retrieval, and degraded async outcomes.</description>
<acceptance_criteria>
- Tests prove the event-processing path returns before slow investigation completes.
- Tests can retrieve a persisted investigation bundle by hunt or receipt ID.
- Tests show timeout or queue-pressure outcomes remain visible without failing the hot path.
</acceptance_criteria>
</task>
</tasks>

<verification>
- cargo test -p swarm-core -p swarm-spine -p swarm-runtime
</verification>

<success_criteria>
- Async investigation is decoupled from the hot path.
- Investigation configuration is repository-owned and validated.
- Durable investigation bundles are linked to replay-bundle identifiers and retrievable by hunt or receipt.
</success_criteria>
