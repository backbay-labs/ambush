Create `crates/swarm-runtime/tests/critical_path_integration.rs` as a Rust integration test file. This file lives outside `src/` so it tests the crate as an external consumer via its public API.

The file must contain at minimum these test scenarios:

**Test 1: `full_critical_path_detect_to_receipt`**
- Build a `ConfiguredRuntimeStack` using `from_components()` with:
  - `SwarmConfig` loaded from `rulesets/default.yaml` using `swarm_core::config::SwarmConfig` deserialization (or construct a minimal in-memory config with `detect_only` mode, in-memory pheromone backend, and memory bundle stores).
  - `StaticApprovalGate::default()` for policy.
  - `SandboxExecutor` for response.
  - A no-op investigation strategy (implement a trivial `InvestigationStrategy` that returns empty results).
- Create a `TelemetryEvent` with `TelemetryPayload::ProcessStart` matching the suspicious process tree pattern (parent `winword`, child `powershell`, encoded command line) that the `SuspiciousProcessTreeDetector` will match.
- Call `process_event()` with the event, an `EventExecutionContext`, and a `request_builder` closure that maps findings to `ResponseAction::BlockEgress`.
- Assert:
  - Result is `Some` (detection produced a finding and execution proceeded).
  - `replay.bundle.findings` is non-empty (whisker detected).
  - `replay.bundle.deposits` is non-empty (pheromone deposited).
  - `replay.bundle.action_request.action` is a `BlockEgress` variant (request was built).
  - `replay.bundle.audit.policy.verdict` is not `Deny` (policy authorized).
  - `replay.bundle.audit.response` matches `AuditResponseRecord::Success(_)` (response executed).
  - `replay.record.bundle_id` is non-empty (replay bundle persisted).
  - `replay.record.hunt_id` matches the event_id (lineage preserved).

**Test 2: `benign_event_produces_no_bundle`**
- Same runtime setup as Test 1.
- Create a `TelemetryEvent` with a benign payload that the detector will NOT match (e.g., parent `explorer`, child `notepad`, no suspicious command line).
- Call `process_event()`.
- Assert result is `None` (no detection, no bundle produced).

**Test 3: `full_path_with_scenario_fixture`**
- Load `scenarios/office-dropper-correlation.yaml` using `serde_yaml::from_str` or `serde_yaml::from_reader`.
- Parse the scenario's `input.events[0].event` into a `TelemetryEvent`.
- Run through the same `ConfiguredRuntimeStack` as Test 1.
- Assert the result is `Some` and the replay bundle contains a finding, deposit, action request, and successful audit trail.
- Verify the replay bundle's `hunt_id` matches the scenario's expected hunt ID (`hunt-evt-1`).

**Test 4: `policy_deny_produces_bundle_with_skipped_response`**
- Build a runtime in `detect_only` mode with a custom policy gate that denies all actions (or use `StaticApprovalGate` and craft a request that gets denied -- low-severity destructive action as shown in existing unit tests).
- Process a suspicious event.
- Assert the result includes an audit trail where `response` is `AuditResponseRecord::Skipped { .. }`.
- This proves the full path runs even when policy denies -- the bundle still records the decision.

Note: Since `process_event` on `ConfiguredRuntimeStack` returns `None` when no finding is produced and also `None` when the finding is present but no action is proposed by `request_builder`, use the lower-level `RuntimeService::process_event` for Test 4 if needed, or use `process_event_with_store_and_investigation` directly. Alternatively, use the `RuntimeService` (not the `ConfiguredRuntimeStack`) directly as the unit tests in `lib.rs` do, calling `audit_authorize_and_execute_instrumented` and verifying the `RuntimeExecutionReport`.

Implementation notes:
- Use `#[tokio::test]` for all async tests.
- The file needs these imports at minimum: `swarm_runtime` (the crate under test), `swarm_core`, `swarm_whisker`, `swarm_policy`, `swarm_response`, `swarm_pheromone`, `swarm_spine`.
- For the no-op investigation strategy, implement a minimal struct: `struct NoOpInvestigation;` with `#[async_trait] impl InvestigationStrategy for NoOpInvestigation { ... }` that returns an empty investigation result. Look at the `InvestigationStrategy` trait definition in `crates/swarm-runtime/src/investigation.rs` for the exact method signature.
