<objective>
Create the approval domain types, file-backed stores, and harness that let operators define approval sets and append signed votes to approval ledgers with threshold tracking.

Purpose: This is the foundational data model and persistence layer that all downstream approval work (swarmctl, HTTP, verdicts, receipt packs) depends on. Without durable approval sets and signed ledger entries, no governance workflow can proceed.

Output: `crates/swarm-runtime/src/approval.rs` with full type definitions, two file-backed stores, a domain harness, and comprehensive tests.

   - Checks voter_id is in set.eligible_voters
   - Checks voter_id has not already voted in ledger.entries
   - Canonicalizes a vote payload `{"approval_set_id": set.set_id, "ledger_id": ledger.ledger_id, "voter_id": voter_id}` and verifies the DetachedSignature against those canonical bytes using `swarm_crypto::verify_detached_signature`
   - Appends the new entry to ledger.entries
