Output: A new `ingest.rs` module in swarm-runtime, an updated swarm-detect binary with `--serve` mode, and integration tests proving valid events enter the pipeline and invalid events are rejected with structured errors.

  <action>
Create `crates/swarm-runtime/src/ingest.rs` containing:

1. **Request/Response types** (all derive Serialize, Deserialize):
   - `IngestRequest`: a newtype over `Vec<serde_json::Value>` -- accept raw JSON values so we can validate each event individually rather than failing the entire batch on one bad event.
   - `IngestResponse { accepted: Vec<IngestEventResult>, rejected: Vec<IngestEventResult> }`
   - `IngestEventResult { event_id: Option<String>, status: IngestEventStatus, reason: Option<String> }`
   - `IngestEventStatus` enum: `Accepted`, `Rejected`, `ProcessingError`

2. **Validation function** `validate_and_parse(value: serde_json::Value) -> Result<TelemetryEvent, String>`:
   - Attempt `serde_json::from_value::<TelemetryEvent>(value)`
   - On success return Ok with the parsed event
   - On failure return Err with the serde error message (which will include missing fields, unknown variants, etc.)
   - This leverages the existing `deny_unknown_fields` and `serde(tag = "kind")` on TelemetryPayload for strict validation

3. **Handler function** `pub async fn ingest_events_handler`:
   - Extract `Json<Vec<serde_json::Value>>` from request body (raw JSON array deserialization -- if body is not a JSON array, axum returns 400 automatically)
   - For each value in the array:
     - Call `validate_and_parse` -- on Err, push to rejected with reason
     - On Ok, try to extract `event_id` from the raw value before parsing for the response
     - Call `service.process_event(detector, &event, execution_ctx, request_builder).await`
     - On Ok push to accepted, on Err push to rejected with processing error
   - Return `Json(IngestResponse { accepted, rejected })`

4. **Shared state type** `IngestState`: Hold what the handler needs:
   - An `Arc` wrapping the `ConfiguredRuntimeStack` (or the service + substrate + detector)
   - The handler needs a detector and a request_builder. For ingest, use the `supported_detector` from config and a no-op request_builder (`|_| None` -- detect-only, no response action from ingest).
   - Use `AgentId("ingest")` for the execution context.
   - Build `ApprovalContext { live_mode: false, receipt_chain: vec![], now_ms: event.timestamp }` per event.

5. **Router constructor** `pub fn ingest_router<S>(state: IngestState) -> Router` (or similar) that returns a `Router` with the POST route.

Add `pub mod ingest;` to `crates/swarm-runtime/src/lib.rs`.

Follow the same error handling patterns as operator_http.rs -- no `unwrap()` or `expect()` in production code (clippy denies them workspace-wide).
