# Phase 296 — Provenance Graph Substrate

**Status:** implementation plan, 2026-09-08. Executed with subagent-driven-development. Branch
`feat/graph-296` off `main` `7081537d2` (v1.81 complete). First phase of the v1.82 Provenance Memory
And Correlation milestone. Depends only on v1.81 (met).

**Goal (ROADMAP.md).** The four-graph model exists but `CausalRelation` has only two variants, so the
causal graph cannot express file writes, execution, DNS, or credential access. Deepen the provenance
graph with real causal node/edge types, add a bounded-hop traversal read path with a hub-degree cap,
and prove GC keeps the graph bounded — before anything traverses it.

**Requirements, verbatim (REQUIREMENTS.md:947–952).**
- **GRAPH-01**: `KnowledgeGraphNode` gains `Process`, `File`, and `NetworkFlow` variants carrying raw
  telemetry identifiers, distinct from the existing detection-level `EngagementNode`.
- **GRAPH-02**: `CausalRelation` (today only `ProcessParentChild` and `NetworkFlowOrigin`) gains
  `FileWrite`, `FileExecute`, `DnsResolution`, and `CredentialAccess`, emitted from every processed
  observation.
- **GRAPH-03**: `KnowledgeGraphSnapshot::provenance_paths(from, to, max_hops)` returns bounded-hop
  paths and becomes the single read path `CorrelationEngine` uses, with a hub-degree cap so
  high-degree nodes cannot connect unrelated hunts.
- **GRAPH-04**: A property test over 200+ randomized `prune_stale` sequences proves GC never orphans
  an edge, never deletes a retention-window-protected record, and is idempotent.
- **GRAPH-05**: A soak test replays 100k synthetic events and asserts post-GC node+edge count stays
  under a fixed ceiling.
- **GRAPH-06**: Config validation rejects or loudly warns on `knowledge_retention_days == 0` while
  `memory.enabled` is true, closing the silent-no-op GC footgun at `sphinx_agent.rs:1097`.

**Success criteria (ROADMAP.md).** (1) the three provenance node variants + the four causal relations
exist and are emitted; (2) `provenance_paths` returns bounded-hop paths with a hub-degree cap and is
the graph's traversal read path; (3) the `prune_stale` property test + the soak-test ceiling pass;
(4) the retention-days footgun is closed in config.

## Design of record (controller rulings, 2026-09-08; re-verify at HEAD)

- **GRAPH-01/02 extend, don't restructure.** Add `Process`, `File`, `NetworkFlow` to
  `KnowledgeGraphNode` (each with a node struct carrying raw telemetry ids — pid/path/5-tuple etc. —
  keyed distinctly from `EngagementNode`'s `observation_id`), a matching `KnowledgeNodeKind` variant,
  and arms in all four exhaustive `impl` matches. Add `FileWrite`, `FileExecute`, `DnsResolution`,
  `CredentialAccess` to `CausalRelation`. "Emitted from every processed observation" (GRAPH-02): the
  emission lives in `ingest_pheromone`; wire new entity/telemetry extraction so these relations are
  emitted whenever the observation carries the corresponding facts (a file write/exec, a DNS
  resolution, a credential access), the same shape as the existing ProcessParentChild/NetworkFlowOrigin
  construction. Preserve serialize/deserialize round-trip + the persisted index (`KnowledgeNodeRecord`
  / `KnowledgeEdgeRecord`), and the restart/tamper/replay guards the existing tests pin. No verdict or
  detection-path behaviour change — this is graph enrichment.
- **GRAPH-03 provenance_paths + hub cap; CorrelationEngine coupling scoped, 298 owns the full
  migration.** Add `KnowledgeGraphSnapshot::provenance_paths(from: &str, to: &str, max_hops: usize)`
  — a bounded-hop BFS/DFS over `edges` returning the path(s) (bounded by `max_hops`), with a
  **hub-degree cap**: a node whose degree exceeds a configured cap is NOT traversed through (so a
  high-degree hub cannot bridge unrelated hunts — the security property). Make it the SOLE
  graph-traversal API: route the existing in-file traversal (`matching_contributions`) through it (or
  through a shared private neighbor helper) so there is exactly one traversal implementation. GRAPH-03
  says provenance_paths "becomes the single read path `CorrelationEngine` uses" — `CorrelationEngine`
  does not read the graph today and phase 298 (Cross-Hunt Correlation, XHUNT-01) is the migration.
  RULING: 296 delivers `provenance_paths` + the hub cap as the graph's read path AND gives
  `CorrelationEngine` a graph-backed provenance lookup that calls `provenance_paths` (the coupling
  GRAPH-03 names), scoped to a bounded-hop query; the broader correlation-onto-graph migration stays
  298's. If the reviewer judges 296 must not touch `CorrelationEngine` at all, the fallback is to make
  `provenance_paths` the documented sole traversal API and record the CorrelationEngine wiring as a
  298 dependency — but prefer the minimal real coupling so GRAPH-03 is literally satisfied. The
  hub-degree cap must be UNIT-TESTED as a security property (a high-degree hub does NOT connect two
  otherwise-unrelated hunt subgraphs).
- **GRAPH-04 proptest.** Add `proptest` as a **dev-dependency** of `swarm-runtime` (dev-only, never in
  the shipped graph — confirm `check-workspace-layering.sh` stays 0). A property test generates 200+
  randomized sequences of `(insert nodes/edges, advance clock, prune_stale)` and asserts the three
  invariants after every prune: (a) no edge references a pruned node (no orphan) — the property the
  `:1130-1134` guard already provides; (b) no record inside the retention window
  (`last_observed_at_ms >= cutoff`) is deleted; (c) `prune_stale` is idempotent (a second immediate
  prune returns `false` / changes nothing). If the proptest finds a real bug, STOP and surface it.
- **GRAPH-05 soak + ceiling.** A soak test replays 100k synthetic events through the ingest/prune path
  (or a representative reduction that exercises the same GC) and asserts the post-GC `nodes.len() +
  edges.len()` stays under a fixed ceiling. The ceiling is a real bound implied by the retention window
  + event rate; state it as a named constant with the arithmetic. This proves GC actually bounds
  growth, not just that it runs. Keep it reasonably fast (a 100k-event soak must fit the test lane; use
  a tight retention window so pruning is exercised, and avoid O(n^2) blowups — the flat-Vec prune is
  O(n) per call).
- **GRAPH-06 close the footgun; the hard reject already exists.** `MemoryConfig::validate()` ALREADY
  rejects `knowledge_retention_days == 0` when enabled (`state.rs:127-132`, tested at
  `config/tests.rs:911`) — GRAPH-06's "rejects" clause is satisfied. What remains is defense-in-depth
  so the `prune_stale` `retention_days == 0` silent no-op (`:1112-1114`) can never be reached with
  memory enabled: RULING — keep the hard config reject (do not weaken it to a warn), and add a
  belt-and-suspenders guard/log at the `prune_stale` no-op (or its `tick` call site) that makes a
  `retention_days == 0`-with-memory-enabled reachability a loud, tested condition rather than a silent
  skip; add a test asserting the footgun is closed (config rejects it AND the runtime path cannot
  silently no-op with memory enabled). The `sphinx_agent.rs:1097` line reference is stale (it falls in
  `attack_technique_for_node` now); the substantive target is the `prune_stale` no-op — record the
  line-slip.
