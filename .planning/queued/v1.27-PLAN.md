# Queued Milestone: v1.27 Live Response Adapters And Deployment

**Status:** Queued (activates after v1.26 completes)
**Created:** 2026-04-05

## Goal

Implement real response adapters that execute actual side effects (EDR block/isolate, webhook notifications), containerize the detection service for deployment, and add runtime policy reload.

## Requirements

- **RESP-01**: At least two real response adapters exist behind the ResponseExecutor trait (HTTP-based EDR block/isolate, webhook-based credential revocation or escalation notification)
- **RESP-02**: Response adapters fire only after guard pipeline and policy gate approval with signed receipt
- **DEPLOY-01**: Dockerfile exists with multi-stage build for swarm-detect and swarmctl binaries
- **DEPLOY-02**: docker-compose exists for local development (runtime + optional NATS)
- **DEPLOY-03**: Health check endpoint and graceful shutdown are implemented
- **DEPLOY-04**: Policy can be reloaded at runtime without binary restart

## Proposed Phase Structure

Starting from phase 84 (v1.26 ends at 83).

### Phase 84: Real Response Adapters
**Goal**: Response actions produce real side effects through HTTP-based adapters
**Requirements**: RESP-01, RESP-02
**Success Criteria**:
1. An HTTP EDR adapter sends block/isolate requests to a configurable endpoint with auth headers and receives confirmation
2. A webhook adapter sends escalation notifications (Slack/PagerDuty compatible JSON) to a configurable URL
3. Both adapters fire only after guard pipeline approval and policy gate verdict
4. Each response produces a signed receipt with the adapter's result status (success/failure/timeout)
5. reqwest HTTP client handles timeouts, retries, and TLS correctly

### Phase 85: Container And Deployment Infrastructure
**Goal**: The detection service is containerized and deployable with operational basics
**Requirements**: DEPLOY-01, DEPLOY-02, DEPLOY-03, DEPLOY-04
**Success Criteria**:
1. Dockerfile produces minimal images for swarm-detect and swarmctl via multi-stage build
2. docker-compose brings up the detection service with optional NATS sidecar
3. /healthz endpoint returns service readiness status
4. SIGTERM triggers graceful shutdown (drain in-flight events, flush metrics)
5. Policy file changes are detected and reloaded without restart (file-watch or SIGHUP)

## Dependencies

- Phase 84 depends on v1.26 (telemetry ingest must exist for end-to-end response testing)
- Phase 85 depends on Phase 84 (container should include working response adapters)
