# Queued Milestone: v1.30 Structured Observability And Adapter Resilience

**Status:** Queued (activates after v1.29 completes)
**Created:** 2026-04-05

## Goal

Add structured JSON logging with correlation IDs, expand Prometheus metrics with counter dimensions, implement retry/circuit-breaker for response adapters, add dead-letter persistence, Kubernetes probes, and config validation.

## Requirements

- **OBS-01**: All ingest and response operations emit structured JSON logs with request correlation IDs
- **OBS-02**: Prometheus metrics include counters for decision verdicts, guard rejections, adapter outcomes, and detector findings per threat class
- **OBS-03**: HTTP EDR and webhook adapters implement retry with exponential backoff and circuit breaker
- **OBS-04**: Failed response actions are persisted to a dead-letter journal
- **OBS-05**: /readyz and /livez endpoints exist for Kubernetes-style probe separation
- **OBS-06**: All detector profiles validate configuration thresholds on load

## Proposed Phase Structure

Starting from phase 90 (v1.29 ends at 89).

### Phase 90: Structured Logging And Expanded Metrics
**Goal**: Operations are traceable through correlation IDs and metrics cover all decision dimensions
**Requirements**: OBS-01, OBS-02
**Success Criteria**:
1. Every ingest request gets a unique trace ID that appears in all downstream log entries
2. Logs are JSON-formatted with timestamp, level, trace_id, module, message fields
3. Prometheus counters track: verdicts (allow/deny/require_human), guard rejections by guard name, adapter outcomes (success/timeout/failure), findings by threat class and detector

### Phase 91: Adapter Resilience And Operational Probes
**Goal**: Response adapters handle transient failures gracefully and the service exposes proper health probes
**Requirements**: OBS-03, OBS-04, OBS-05, OBS-06
**Success Criteria**:
1. HTTP EDR and webhook adapters retry transient failures with exponential backoff (configurable max retries)
2. Circuit breaker disables adapter after N consecutive failures, re-enables after configurable cooldown
3. Failed responses are written to a dead-letter journal file for later inspection
4. /readyz returns strict readiness (all components healthy), /livez returns liveness (process alive)
5. Detector profiles reject invalid thresholds (negative entropy, out-of-range confidence) at load time with clear error messages
