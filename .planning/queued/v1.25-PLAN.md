# Queued Milestone: v1.25 Operational Hardening And Service Extraction

**Status:** Queued (activates after v1.24 completes)
**Created:** 2026-04-05

## Goal

Extract the detection hot path into a standalone service binary, wire rulesets and scenarios into detection config, add Prometheus metrics on the critical path, cover the full critical path with integration tests, and enforce strict clippy lints across the workspace.

## Requirements (already defined in REQUIREMENTS.md)

- **OPS-26**: Detection hot path runs as a standalone binary separate from the operator workbench
- **OPS-27**: Rulesets and scenarios are wired into detection config rather than only the workbench CLI
- **OPS-28**: Critical path emits structured Prometheus metrics for detection latency, policy evaluation time, and response execution time
- **OPS-29**: Integration tests cover the full critical path from telemetry to verified receipt
- **OPS-30**: Workspace enforces clippy unwrap_used and expect_used denial across all crates

## Proposed Phase Structure

Starting from phase 78 (v1.24 ends at 77).

### Phase 78: Service Extraction And Detection Binary
**Goal**: Detection hot path runs as a standalone `swarm-detect` binary separate from the swarmctl operator workbench
**Requirements**: OPS-26, OPS-27
**Success Criteria**:
1. A `swarm-detect` binary exists that loads config, runs detection, deposits pheromones, and evaluates policy without the operator workbench
2. Rulesets from `rulesets/` and scenarios from `scenarios/` are loaded by the detection binary at startup via config
3. The binary runs in `detect_only` and `live_response` modes with the same runtime modes as the library

### Phase 79: Metrics And Integration Tests
**Goal**: Critical path emits Prometheus metrics and integration tests prove the full detect-to-receipt flow
**Requirements**: OPS-28, OPS-29
**Success Criteria**:
1. Detection latency, policy evaluation time, and response execution time are emitted as Prometheus histogram metrics
2. A `/metrics` endpoint serves OpenMetrics-format data from the detection service
3. Integration tests exercise the full critical path: telemetry event in -> whisker detect -> pheromone deposit -> policy authorize -> response execute -> receipt verify
4. Integration tests run as part of `cargo test --workspace`

### Phase 80: Clippy Enforcement
**Goal**: Workspace enforces strict error handling lints to prevent panics in production
**Requirements**: OPS-30
**Success Criteria**:
1. `[lints.clippy]` in workspace Cargo.toml denies `unwrap_used` and `expect_used`
2. All existing code compiles cleanly under the new lint rules (fix violations)
3. CI workflow validates the stricter lints

## Dependencies

- Phase 78 depends on v1.24 being complete (stable runtime to extract from)
- Phase 79 depends on Phase 78 (binary must exist before metrics and integration tests)
- Phase 80 is independent (lint enforcement can happen after any phase)

## Activation

When v1.24 completes, run `/gsd:new-milestone` with this plan as context. The requirements are already in REQUIREMENTS.md. This doc provides the phase structure and success criteria for the roadmapper.
