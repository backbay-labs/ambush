# Queued Milestone: v1.31 Runtime Agent Dispatcher And Pheromone-Driven Escalation

**Status:** Queued (activates after v1.30 completes)
**Created:** 2026-04-05

## Goal

Add a minimal agent dispatcher to swarm-detect that runs registered SwarmAgent implementations on a tick interval, implement WhiskerAgent as the first real agent, and wire pheromone concentration monitoring into live mode transitions.

## Requirements

- **AGENT-01**: A configurable agent dispatcher runs registered SwarmAgent implementations on a tick interval within swarm-detect
- **AGENT-02**: WhiskerAgent wraps the existing detection pipeline as the first SwarmAgent trait implementation
- **AGENT-03**: Pheromone concentration monitoring triggers mode transitions (Normal → Alert → Incident) when thresholds are crossed
- **AGENT-04**: min_sources_for_escalation is enforced as a live gate on escalation events
- **AGENT-05**: Integration tests prove multi-source deposit → threshold crossing → escalation event emission

## Proposed Phase Structure

Starting from phase 92 (v1.30 ends at 91).

### Phase 92: Agent Dispatcher And WhiskerAgent
**Goal**: The runtime has a tick-based agent execution loop with the detection pipeline wrapped as an agent
**Requirements**: AGENT-01, AGENT-02
**Success Criteria**:
1. AgentDispatcher struct manages a vec of registered SwarmAgent implementations
2. Dispatcher runs each agent's tick() on a configurable interval (default 100ms)
3. WhiskerAgent implements SwarmAgent, calling detect_and_deposit on each tick with buffered telemetry
4. Dispatcher integrates into swarm-detect's serve mode alongside ingest/metrics
5. Agent health is reported in /healthz

### Phase 93: Pheromone Escalation And Mode Transitions
**Goal**: The runtime reacts to pheromone concentration by transitioning modes and emitting escalation events
**Requirements**: AGENT-03, AGENT-04, AGENT-05
**Success Criteria**:
1. A concentration monitor queries the substrate on a configurable interval
2. When total_strength exceeds alert_threshold AND distinct_sources >= min_sources, an AlertEscalation event is emitted
3. When total_strength exceeds incident_threshold AND distinct_sources >= min_sources, an IncidentEscalation event is emitted
4. Mode transitions are logged, metricsed, and persisted as durable state
5. Integration tests with two mock agents depositing to shared substrate prove: below threshold → no escalation, single source → no escalation, dual source above threshold → escalation fires
