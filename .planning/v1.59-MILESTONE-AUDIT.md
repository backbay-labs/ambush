## Cross-Phase Integration

The milestone contract is coherent end to end:

- Phase 204 introduced one repo-owned readiness verdict over telemetry,
  detector activation, and substrate health so onboarding can fail clearly
  before any synthetic walkthrough begins.
- Phase 205 reused that readiness gate to drive a bounded first-run flow that
  injects synthetic telemetry, captures the first approval, and exports signed
  proof artifacts without leaving the repo-owned operator path.
- Phase 206 turned signed Providence analyst feedback into durable
  per-detector and per-host false-positive measurements that can be queried
  through the same status surfaces as the rest of the runtime.
- Phase 207 consumed those measured rollups to emit bounded advisory tuning
  recommendations on the same CLI and API surfaces, closing the loop from
  onboarding to analyst-guided quality improvement.

## E2E Flows Verified

1. Operators can run `swarmctl readiness` and receive one bounded verdict over
   telemetry sources, detector activation, and substrate readiness before
   guided onboarding begins.
2. `swarmctl first-run` reuses that readiness state, injects synthetic
   telemetry, walks through first detection and approval, and returns durable
   proof identifiers in one operator-visible report.
3. Signed Providence analyst feedback persists durable reviewed-finding
   measurements with detector and host attribution, and both `swarmctl status`
   and `/v2/api/runtime/status` surface bounded false-positive rollups.
4. Those same operator read surfaces now derive concrete advisory tuning
   recommendations from the measured false-positive state without mutating
   runtime config automatically.
