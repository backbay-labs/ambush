## Cross-Phase Integration

The milestone contract is coherent end to end:

- Phase 220 turned `swarm-evolution`'s oversized `evolution.rs` into a focused
  extracted module tree without changing the crate contract consumed by the
  runtime.
- Phase 221 applied the same decomposition discipline to the oversized mutation
  path, keeping public crate consumers stable while tightening internal module
  responsibilities.
- Phase 222 added an explicit pheromone wire `schema_version` plus a bounded
  current-and-previous compatibility lane so substrate persistence no longer
  depends on implicit deposit shape.
- Phase 223 carried the same explicit-version discipline onto the shipped
  operator and platform response envelopes, with one bounded negotiation seam
  instead of silent JSON field drift.

## E2E Flows Verified

1. The extracted evolution and mutation module trees keep the
   `swarm-evolution` crate contract stable while eliminating the previous
   oversized single-file bottlenecks.
2. Pheromone deposits now emit explicit wire versions and still reopen through
   the bounded legacy compatibility lane when reading prior stored payloads.
3. Operator-facing control and platform envelopes now emit top-level
   `schema_version` metadata and reject unsupported requested schema versions
   through one shared negotiation seam.
4. Repo-owned `swarmctl` control outputs keep the same compatibility lane at
   schema version `1` and fail closed on unsupported requested output versions.
