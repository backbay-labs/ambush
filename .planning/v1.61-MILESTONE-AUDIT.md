## Cross-Phase Integration

The milestone contract is coherent end to end:

- Phase 212 expanded the shared response catalog so Swarm can express a
  materially broader set of containment, network, host, account, and deception
  actions without adding a second executor path.
- Phase 213 attached typed blast-radius scope and rollback metadata to that
  expanded catalog, establishing one previewable action contract shared by
  rehearsal and live execution.
- Phase 214 lifted those actions into repo-owned composed playbooks with
  deterministic branch selection and fallback behavior through the normal
  approval-aware runtime lane.
- Phase 215 exposed the composed result on repo-owned operator surfaces as a
  dry-run preview that reuses the same typed metadata and policy gate without
  producing live side effects.

## E2E Flows Verified

1. Expanded response actions now route through the shared guarded execution
   contract instead of adapter-specific side channels.
2. Every supported playbook action now carries typed blast-radius and rollback
   metadata that later seams can project without heuristic reconstruction.
3. Repo-owned YAML playbooks now select one deterministic ordered branch or
   fallback action set from runtime context.
4. Operators can now dry-run one matched playbook through `swarmctl
   playbook-preview` and receive projected approval requirements plus typed
   rollback and blast-radius output without live executor calls.
